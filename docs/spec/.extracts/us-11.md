# Extract: us-11

## Summary

US-11 enriches the position detail page's leg history table with a **running cost basis column** (per-share basis after each leg, derived from historical cost basis snapshots) and **special premium-cell rendering** for ASSIGN, CALLED_AWAY, CC_CLOSE, and CC_EXPIRED legs. The backend `getPosition` service gains an `allSnapshots` field (all snapshots ordered `snapshot_at ASC`); a new renderer pure function `deriveRunningBasis` matches snapshots to legs via a carry-forward pointer scan; and `LegHistoryTable` is extended from 5 columns to 8 with a conditional `<tfoot>` Final P&L row. As part of the green phase, the main process also began persisting explicit `CALLED_AWAY` and `CC_EXPIRED` leg roles (previously emitted as `CC_CLOSE` / `EXPIRE`) so the renderer can apply the story-specific row labels and annotations. No schema migration required. (Source: `plans/us-11/plan.md` Summary, `plans/us-11/green-phase-results.md`)

## Architecture Decisions

### ADR: Snapshot-to-leg matching uses a carry-forward pointer scan in the renderer

- **Decision:** Iterate legs in `fill_date ASC` order; maintain a snapshot pointer advancing through snapshots sorted `snapshot_at ASC`; for each leg advance the pointer while `snapshot.snapshotAt.slice(0,10) <= leg.fillDate`, then record the last seen `basisPerShare` as `runningCostBasis` for that leg.
- **Why:** Snapshots are created on the same day as their triggering leg (CSP_OPEN, ASSIGN, CC_OPEN, CC_EXPIRED, CALLED_AWAY). Date comparison via `slice(0,10)` is safe because snapshot timestamps use ISO-8601 and leg `fillDate` is already `YYYY-MM-DD`. CC_CLOSE has no snapshot, so its leg simply carries forward the last known basis. Algorithm is O(n+m), no look-ahead.
- **Alternatives considered:** Matching by leg role name (brittle — breaks if two CC_OPEN legs exist); SQL join on fill_date (not possible client-side); returning pre-computed running basis from the backend (adds DB logic that belongs in display layer).
- **Source:** `plans/us-11/research.md`

### ADR: Add `allSnapshots` to `getPosition` rather than a separate IPC channel

- **Decision:** Add a second SQLite query in `get-position.ts`: `SELECT * FROM cost_basis_snapshots WHERE position_id = ? ORDER BY snapshot_at ASC`. Return as `allSnapshots: CostBasisSnapshotRecord[]` on `GetPositionResult`. The `positions:get` IPC channel shape is the only change; no new channel needed.
- **Why:** The current service already issues a second query for all legs (`GET_LEGS_QUERY`). Adding a parallel snapshot query is consistent with that pattern and keeps the IPC response self-contained.
- **Alternatives considered:** Embedding snapshot data in the legs query via JOIN (overcomplicated); returning only the latest snapshot and re-deriving history (data loss — terminal P&L is on the last snapshot only).
- **Source:** `plans/us-11/research.md`, `plans/us-11/contracts/get-position.md`

### ADR: `deriveRunningBasis` lives in the renderer, not in `src/main/core/`

- **Decision:** Place as a pure function in `src/renderer/src/lib/deriveRunningBasis.ts`. Signature `deriveRunningBasis<T extends { fillDate: string }>(legs: T[], snapshots: SnapshotInput[]): Array<T & { runningCostBasis: string | null }>`.
- **Why:** This is display logic (enriching data for rendering), not business logic. The renderer already has a `lib/` folder for pure helpers (`format.ts`, `phase.ts`). Keeping it renderer-side avoids coupling the backend service to a display concern.
- **Alternatives considered:** Placing in `src/main/core/` (would work since it's pure, but violates separation of display vs business logic); placing inline in `PositionDetailPage` (testability concern).
- **Source:** `plans/us-11/research.md`

### ADR: Replace 5-column `LegHistoryTable` with the 8-column mockup layout

- **Decision:** Replace the existing 5-column table (Date, Action, Type, Strike, Premium) with the mockup's 8-column layout: Role (badge) | Action | Strike | Expiration | Contracts | Premium | Fill Date | Running Basis / Share. `LegHistoryEntry` adds `expiration: string | null`, `contracts: number`, and `runningCostBasis: string | null`; `premiumPerContract` becomes `string | null`. New optional `finalPnl?: string | null` prop on the table.
- **Why:** Mockup is authoritative. "Type" column is replaced by the Role badge per technical notes.
- **Alternatives considered:** Keep old columns and add to them (rejected — old column order doesn't match mockup).
- **Source:** `plans/us-11/research.md`, `plans/us-11/data-model.md`

### ADR: Centralize role color and label maps in `phase.ts`

- **Decision:** Add `ROLE_COLOR: Record<string, string>` to `src/renderer/src/lib/phase.ts` with hex values from the mockup. Update `LEG_ROLE_LABEL` to add `CALLED_AWAY: 'Called Away'`, `CC_EXPIRED: 'CC Expired'`, `CC_CLOSE: 'CC Close'` and replace existing labels (e.g. `CSP_OPEN: 'Sell Put'` → `'CSP Open'`) to match mockup labels.
- **Why:** Centralized alongside existing role/phase maps. Mockup explicitly defines colors per role.
- **Alternatives considered:** Inline constants in `LegHistoryTable.tsx` (duplication risk); separate `legRoles.ts` file (unnecessary fragmentation).
- **Source:** `plans/us-11/research.md`

### ADR: Persist `CALLED_AWAY` and `CC_EXPIRED` as distinct leg roles (green-phase decision)

- **Decision:** Add `CALLED_AWAY` and `CC_EXPIRED` to the `LegRole` enum in `src/main/core/types.ts`. `record-call-away-position.ts` now persists `CALLED_AWAY` (was emitting `CC_CLOSE`). `expire-cc-position.ts` now persists `CC_EXPIRED` (was emitting a generic `EXPIRE` role).
- **Why:** The renderer needs the distinct role values to render the story-specific row labels (`Called Away`, `CC Expired`) and annotations (`100 shares called away`, `expired worthless`) without special-casing older roles. The E2E spec exposed the gap.
- **Alternatives considered:** Special-case the renderer to interpret existing `CC_CLOSE`/`EXPIRE` rows differently (rejected — leg-role semantics should match the mockup contract at the persistence layer).
- **Source:** `plans/us-11/green-phase-results.md`

### ADR: Same-day basis sequencing happens in the renderer (green-phase decision)

- **Decision:** `deriveRunningBasis()` groups legs and snapshots by fill date and assigns same-day snapshots in sequence so earlier rows keep their own basis while later rows inherit the latest available snapshot.
- **Why:** Same-day multi-leg chains (e.g. assign and open CC on the same day) initially collapsed to the latest snapshot, causing the CSP_OPEN row to inherit the CC_OPEN basis. The fix preserves chronological progression per row.
- **Alternatives considered:** Move sequencing into the backend query (rejected — keep display-layer logic in the display layer).
- **Source:** `plans/us-11/green-phase-results.md`

### ADR: DTE math switches to UTC (green-phase decision)

- **Decision:** `computeDte()` in `src/renderer/src/lib/format.ts` now evaluates persisted `YYYY-MM-DD` strings in UTC.
- **Why:** Matches the main-process defaults that already use `toISOString().slice(0, 10)`. Removes the date-boundary mismatch that made the expired-CC action flaky around local/UTC midnight.
- **Alternatives considered:** None recorded.
- **Source:** `plans/us-11/green-phase-results.md`, `plans/us-11/refactor-phase-results.md` (Layer 4 follow-up)

### `deriveRunningBasis` pure function

- **Type:** other (renderer pure helper)
- **Shape:**

```typescript
type SnapshotInput = { snapshotAt: string; basisPerShare: string }

export function deriveRunningBasis<T extends { fillDate: string }>(
  legs: T[],
  snapshots: SnapshotInput[]
): Array<T & { runningCostBasis: string | null }>
```

Algorithm (per `data-model.md`):

```
currentBasis = null
si = 0
for each leg in legs:
  while si < snapshots.length AND snapshots[si].snapshotAt.slice(0,10) <= leg.fillDate:
    currentBasis = snapshots[si].basisPerShare
    si++
  leg.runningCostBasis = currentBasis
```

Green-phase enhancement: same-day sequencing groups legs and snapshots by fill date so earlier rows keep their own basis while later rows on the same day inherit the latest snapshot.

- **Source:** `plans/us-11/data-model.md`, `plans/us-11/research.md`, `plans/us-11/plan.md` area 3, `plans/us-11/green-phase-results.md`
- **Implementation:** `src/renderer/src/lib/deriveRunningBasis.ts`

## Acceptance Criteria

- Scenario: Leg chain displays all legs in chronological order
  - Given the position has legs CSP_OPEN, ASSIGN, CC_OPEN
  - Then the leg history table shows all three legs in `fill_date` order (oldest first)
  - And each row shows: leg role, action, instrument type, strike, expiration, contracts, premium, fill date
- Scenario: Running cost basis column shows basis after each leg, including CC_CLOSE carry-forward
  - Given the position has CSP_OPEN ($180 / +$3.50 / basis $176.50), ASSIGN ($180 / — / $176.50), CC_OPEN ($182 / +$2.30 / $174.20), CC_CLOSE ($182 / −$1.80 / $174.20)
  - Then each row shows the cost basis at that point in the chain
  - And the ASSIGN row shows "— (assigned)" for premium
  - And the CC_OPEN row shows $174.20 running basis
  - And the CC_CLOSE row shows $174.20 running basis (carried forward — no new snapshot at early close)
  - And the CC_CLOSE premium column shows "−$1.80" in amber (buyback debit, not a credit)
- Scenario: Completed wheel shows final P&L in the chain footer
  - Given `position.status === 'WHEEL_COMPLETE'` and the final snapshot's `final_pnl = "$780.00"`
  - Then a summary row at the bottom shows "Final P&L: +$780.00"
  - And the P&L is green for profit / red for loss
- Scenario: ASSIGN leg displays shares received, not premium
  - Given an ASSIGN leg with `contracts = 1`
  - Then the premium column shows "— (assigned)"
  - And a "100 shares received" annotation appears below it (contracts × 100)
  - And the strike column shows the assignment strike
- Scenario: CALLED_AWAY leg shows call-away strike and inherits running basis
  - Given a CALLED_AWAY leg at $182.00 with `contracts = 1`
  - Then the premium column shows "— (assigned)" and a "100 shares called away" annotation
  - And the strike column shows $182.00
  - And the running cost basis column carries forward from the prior snapshot (CC_OPEN basis)
- Scenario: CC_EXPIRED leg displays expired worthless in muted style
  - Given a CC_EXPIRED leg
  - Then the premium column shows "expired worthless" in muted text style
  - And running cost basis carries forward from the CC_OPEN snapshot
- Scenario: Single-leg position (CSP still open) shows partial chain
  - Given the position has only a CSP_OPEN leg
  - Then only the CSP_OPEN row is shown
  - And the running cost basis shows the initial basis from the opening cost basis snapshot

(Source: `docs/epics/02-stories/US-11-wheel-leg-chain-display.md`)

## Decisions & Tradeoffs

- Premium-cell rendering (verbatim per mockup + technical notes):
  - `ASSIGN`: flex column, muted italic "— (assigned)" + `{contracts × 100} shares received` annotation at `0.68rem`.
  - `CALLED_AWAY`: flex column, muted italic "— (assigned)" + `{contracts × 100} shares called away` annotation at `0.68rem`.
  - `CC_EXPIRED`: muted italic "expired worthless".
  - `CC_CLOSE`: amber `var(--wb-gold)` "−${premiumPerContract}" — **em-dash minus prefix, not hyphen**.
  - Else with value: green `var(--wb-green)` "+${premiumPerContract}".
  - Else null/zero: muted "—".
  - (Source: `plans/us-11/plan.md` area 5, `plans/us-11/research.md`)
- Basis cell rendering: `null` → muted "—"; value → sky `#79c0ff` bold "$X.XX" via `parseFloat(value).toFixed(2)`. Running-Basis column header has `background: rgba(121,192,255,0.05)`, `borderLeft: '1px solid rgba(121,192,255,0.12)'`, `color: '#79c0ff'`; tbody cells inherit the same sky-tinted accent. (Source: `plans/us-11/plan.md` area 5)
- Final P&L `<tfoot>`: rendered only when `finalPnl` is truthy; `<td colSpan={8}>` with green-dim border-top `rgba(63,185,80,0.25)` + `rgba(63,185,80,0.04)` background; uses `fmtMoney` and `pnlColor` from `src/renderer/src/lib/format.ts`. (Source: `plans/us-11/plan.md` area 5, `plans/us-11/research.md`)
- Instrument type intentionally **not** rendered as its own column — conveyed implicitly by the role badge (CSP Open = PUT, CC Open/Close/Expired = CALL, Called Away = CALL) to keep the table width manageable. (Source: `docs/epics/02-stories/US-11-wheel-leg-chain-display.md` Technical Notes)
- Roll legs (`ROLL_FROM`, `ROLL_TO`) may appear in leg history — render with their role badge, carry forward the previous running basis, do not crash. Full roll visualization is deferred to a future story. (Source: `docs/epics/02-stories/US-11-wheel-leg-chain-display.md`)
- The table is non-interactive in Phase 1 — no sorting, no pagination, no CSV export. (Source: story Out of Scope)
- CC_CLOSE net contribution = `open_premium − close_price` (can be negative if closed at a loss); the running basis for the CC_CLOSE row carries forward and net contribution is reflected in the terminal snapshot once the wheel completes. (Source: story Technical Notes)
- `LegHistoryTable` `whiteSpace: 'nowrap'` retained on all cells to prevent wrapping. (Source: `plans/us-11/plan.md` area 5 Refactor, `plans/us-11/tasks.md` Layer 2 Refactor)
- `allSnapshots ?? []` fallback used in `PositionDetailPage` to keep older test fixtures compiling without backfilling the field everywhere. (Source: `plans/us-11/plan.md` area 6 Refactor)
- The previous backend claim that "no new backend data is required" (in an earlier story draft) was incorrect — without historical snapshots the running basis per leg cannot be derived. The story explicitly calls this out. (Source: `docs/epics/02-stories/US-11-wheel-leg-chain-display.md` Technical Notes)

### Refactor-phase decisions (authoritative; `plans/us-11/refactor-phase-results.md`)

- **Extract row mapping helpers in `get-position.ts`** — `mapActiveLeg()` and `mapLatestSnapshot()` handle nullable joined-row mapping; existing `mapLegRow()` and `mapSnapshotRow()` helpers reused for list results.
- **Extract shared renderer detail types** — `LegDetail` and `SnapshotDetail` are now named exported types in `src/renderer/src/api/positions.ts`, reused by `PositionDetail` (was inline duplication for `activeLeg`/`legs` and `costBasisSnapshot`/`allSnapshots`).
- **Extract repeated notes markup in `PositionDetailContent`** — `NoteBlock` encapsulates the shared caption + mono-text structure (Thesis and Notes were near-identical blocks).
- **Consolidate premium and basis formatting in `LegHistoryTable`** — added local helpers/constants `formatDollarAmount()`, `renderAssignedPremiumCell()`, `assignmentAnnotationByRole`, plus shared muted/running-basis style objects. ASSIGN and CALLED_AWAY no longer duplicate the assigned-cell markup; amount formatting and accent styles are no longer repeated inline.
- **Layer 4 follow-up** — `src/renderer/src/lib/format.ts` `computeDte()` now uses UTC dates to match the main-process ISO date convention, removing the date-boundary mismatch that made the expired-CC action flaky around local/UTC midnight. Small readability cleanup retained in `e2e/leg-chain-display.spec.ts` `getLegHistoryTable()` helper.
- **Quality gates after refactor:** 49 test files, 499 tests passing; `pnpm test`, `pnpm lint`, `pnpm typecheck` all clean.
- **Tech debt acknowledged (not addressed in this story):**
  - `LegData.premium_per_contract` remains snake_case while surrounding renderer types are mostly camelCase; normalizing would require a wider consumer audit.
  - The IPC adapter still relies on `as unknown as ...` casts for responses; tightening would need shared schemas beyond the US-11 layer 1–3 surface.
  - `ROLE_COLOR` and `LEG_ROLE_LABEL` are still `Record<string, string>`; tightening to a renderer leg-role union is possible but would expand the surface.
  - `src/renderer/src/pages/PositionDetailPage.test.tsx` remains large and fixture-heavy; splitting into helper factories is a future refactor-only task.
