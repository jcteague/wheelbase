# Extract: us-102

## Summary

Delivered the shared PMCC expiration-safety prerequisite and regression coverage for
existing entry and roll consumers. The shared comparator now uses date-fns calendar
comparison, invalid parsed dates cannot establish coverage, and both PMCC roll
sheets use the New York calendar day for review and default fill dates. Existing
messages, services, live-leg lookup, atomic transactions and IPC envelopes remain
the contracts. Recorded verification includes 4,633 passing unit/integration tests
across 288 files, 100% lines and branches for all four changed production files,
479 passing Electron cases across 42 suites with one pre-existing TODO, and nine
fully named safety cases. Fresh-context review reported zero blocking and zero
advisory findings. US-115 still owns the three subsequent-short integration cases
S5/S6; completing this shared prerequisite does not establish full cross-story
acceptance. Sources: `plans/us-102/green-phase-results.md`,
`plans/us-102/refactor-phase-results.md`, `plans/us-102/review-phase-results.md`,
`plans/us-102/area-f-results.md`.

## Architecture Decisions

### ADR: Shared prerequisite precedes the subsequent-short consumer

- **Decision:** US-102 supplies the shared invariant that US-115 consumes. S5/S6 remain that consumer's integration obligations: three cases across two scenario families.
- **Why:** This follows Linear's dependency direction. Existing comparator and roll-path verification deliver the prerequisite without introducing an artificial dependency cycle.
- **Alternatives considered:** Absorbing US-115 duplicates its scope; waiting for it reverses the dependency. Comparator checks and test-only leg insertion cannot substitute for the future real workflow.
- **Source:** `plans/us-102/research.md`, `plans/us-102/tasks.md`, `plans/us-102/review-phase-results.md`.

### ADR: One pure calendar comparator and stable message identities

- **Decision:** Reuse `shortExpiresBeforeLeaps` with `isBefore(parseISO(shortExpiration), parseISO(longExpiration))`, preserving its signature, callers and both message exports.
- **Why:** Existing valid-date behavior was correct; parsed calendar dates also prevent invalid dates from establishing coverage. Entry and both roll directions continue to share one predicate independently of displayed DTE.
- **Alternatives considered:** Another comparator, duplicated predicates/messages, a new validation framework or configurable threshold.
- **Source:** `plans/us-102/research.md`, `plans/us-102/data-model.md`, `plans/us-102/area-a-results.md`.

### ADR: Existing service boundaries remain authoritative and atomic

- **Decision:** Read the live pair through `getPosition(...).pmccOpenLegs` / `loadPmccRollContext`; validate with pure engines before `recordPmccRoll` writes linked legs and a snapshot.
- **Why:** A preceding opposite-leg roll must change the coverage boundary. Regression tests establish unchanged complete persisted state on rejection and retain the established error envelope through real services.
- **Alternatives considered:** Rebuilding working services, trusting renderer-supplied opposite-leg dates or moving business logic into IPC.
- **Source:** `plans/us-102/data-model.md`, `plans/us-102/area-c-e-results.md`, `plans/us-102/refactor-phase-results.md`.

### ADR: New York clock selection stays at the two roll-sheet boundaries

- **Decision:** Add `newYorkToday(now = new Date())` using native Intl with `America/New_York` and numeric date parts; both roll sheets use it as default `today`, preserving explicit injection and existing date-fns DTE calculations.
- **Why:** This supplies the review's explicit valuation basis without changing the expiration invariant or adding a timezone dependency. The shared `today` also determines these forms' default fill dates.
- **Alternatives considered:** Changing all application clocks, a production clock-control IPC API, cached-DTE validation or another timezone library. Consolidating with core `etDateOf` would broaden imports or require another shared module.
- **Source:** `plans/us-102/research.md`, `plans/us-102/data-model.md`, `plans/us-102/area-d-results.md`, `plans/us-102/refactor-phase-results.md`.

### ADR: Extend shipped roll behavior only for demonstrated gaps

- **Decision:** Retain the existing roll sheets, forms, RHF/Zod rules, financial context, field mapping and visibly disabled `FormButton`. Production changes are limited to the comparator, date helper and two sheet defaults.
- **Why:** Existing service, IPC and most UI safety behavior already worked; the missing behavior was calendar parsing and timezone selection. Passing regressions were recorded honestly rather than manufacturing failures.
- **Alternatives considered:** Replacing shipped sheets with prototypes, adding preset controls, a Sell Short Call sheet, another form abstraction or a wider type redesign.
- **Source:** `plans/us-102/research.md`, `plans/us-102/red-phase-results.md`, `plans/us-102/area-d-results.md`, `plans/us-102/refactor-phase-results.md`.

## Contracts

### Shared expiration comparator

- **Type:** other
- **Shape:**

```typescript
shortExpiresBeforeLeaps(shortExpiration: string, longExpiration: string): boolean
```

  Canonical inputs are `YYYY-MM-DD`. The implementation uses date-fns `isBefore`
  with `parseISO`; invalid parsed dates cannot establish coverage. Equality rejects.
- **Source:** `plans/us-102/data-model.md`, `plans/us-102/area-a-results.md`.
- **Implementation:** `src/main/core/pmcc-rules.ts`.

### Stable PMCC coverage errors and field routing

- **Type:** other
- **Shape:**

```typescript
SHORT_NOT_BEFORE_LONG = {
  code: 'short_not_before_long',
  message: 'Short call must expire before the LEAPS call.'
}
LONG_NOT_AFTER_SHORT = {
  code: 'long_not_after_short',
  message: 'LEAPS call must expire after the short call.'
}
```

  Entry reports the short-side error at `short.expiration`; both rolls report
  their corresponding error at `newExpiration`. No coverage comparison applies
  when a LEAPS roll has no open short. Other validation continues to apply.
- **Source:** `plans/us-102/data-model.md`, `plans/us-102/area-a-results.md`.
- **Implementation:** `src/main/core/pmcc-rules.ts`.

### New York valuation day

- **Type:** other
- **Shape:**

```typescript
newYorkToday(now?: Date): string
```

  Returns the `YYYY-MM-DD` calendar date in `America/New_York`; omitted `now`
  defaults at the call boundary. Both roll sheets preserve injected `today`.
- **Source:** `plans/us-102/data-model.md`, `plans/us-102/green-phase-results.md`, `plans/us-102/area-d-results.md`.
- **Implementation:** `src/renderer/src/lib/dates.ts`, `src/renderer/src/components/RollPmccShortCallSheet.tsx`, `src/renderer/src/components/RollPmccLeapsSheet.tsx`.
