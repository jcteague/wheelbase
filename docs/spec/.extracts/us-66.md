# Extract: us-66

## Summary

US-66 is the payoff surface of the screener epic and a **pure renderer story** — every
backend piece it consumes shipped in US-65. It adds the `/screener` route rendering
US-65's scored candidates as a dense 12-column ranked table (one recommended put strike
per ticker, in the engine's yield-per-delta order — the renderer never re-sorts), a
collapsed `Excluded (n)` section carrying each non-ranking ticker's verbatim engine
reason, three mutually exclusive body states (ranked / no-candidates / market-data-
unavailable), and a `Stale snapshot` badge plus quote-time caption when the market status
pill reads CLOSED. Supporting pieces: seven pure display formatters
(`lib/screener-format.ts`), a status-preserving API adapter + TanStack Query hook, and a
two-tone `ScreenerStateCard`. No IPC surface, no service, no engine, no migration. The
Promote button (US-68), criteria editing (US-67), and the earnings badge treatment
(US-70) are deliberately out of scope with their seams left intact.

## Architecture Decisions

### ADR: Screener results consumed via a status-preserving API adapter

- **Decision:** `src/renderer/src/api/screener.ts` exports
  `getScreenerResults(): Promise<ScreenerResults>`, which throws mapped errors **only** on
  `!result.ok` (the unexpected `internal_error` row) and otherwise returns the full
  payload **including `status`**. `provider_unavailable` is data the page renders, not an
  error the query rejects with. `useScreenerResults()` wraps TanStack `useQuery` with a key
  from `hooks/screenerQueryKeys.ts`, fetches on mount, and has **no `refetchInterval`**;
  the outage card's "Retry refresh" button calls `refetch()`.
- **Why:** Matches the repo's adapter/hook/queryKeys pattern (watchlist, alerts,
  market-data). US-65 deliberately modelled every expected failure inside the success
  payload so the renderer can distinguish outage from empty; letting the query reject on
  outage would collapse that distinction into a generic error state. No polling because a
  screen run fans out provider requests per ticker — refresh is a deliberate trader
  action, and `MarketStatusPill` is the freshness signal.
- **Alternatives considered:** throwing an `ApiError` for `provider_unavailable` and
  branching on error code in the page (rejected — conflates the modelled outage with a
  genuine IPC failure and fights the US-65 contract); TanStack `refetchInterval` (rejected
  — unrequested, provider-expensive, and the story defines freshness via the pill + stale
  badge instead).
- **Source:** `plans/us-66/research.md`

### ADR: Table built on existing `TablePrimitives`, not a new shadcn Table import

- **Decision:** Render the ranked table as a plain `<table>` using the existing
  `TableHeader` / `TableCell` primitives, with `wb-*` token classes per cell (gold rank
  badge + ticker, `text-wb-green` yields, muted secondary columns).
- **Why:** The story's technical note says "dense shadcn `Table`", but the codebase's
  established dense-table convention (`WatchlistPage`, `LegHistoryTable`) is
  `TablePrimitives` — which _is_ this repo's shadcn-style table layer, already carrying the
  exact mono-uppercase header and border treatment the mockup shows. Adding the shadcn
  registry `table.tsx` would duplicate an existing primitive for one page.
- **Alternatives considered:** `npx shadcn add table` (rejected as duplication); CSS-grid
  rows like the mockup's MDX (rejected — the mockup's grid is a preview-rendering
  artifact; real pages use semantic tables and e2e selectors elsewhere assume `tr`/`td`).
- **Source:** `plans/us-66/research.md`

### ADR: Display formatting — trim-to-2dp percents, 2dp score, integer spread percent

- **Decision:** New pure helpers in `src/renderer/src/lib/screener-format.ts`:
  `fmtYieldPercent` (×100, up to 2dp, trailing zeros trimmed — `"0.0150"` → `1.5%`;
  annualized rendered as `` `${fmtYieldPercent(v)}/yr` ``), `fmtScore` (fixed 2dp —
  `"0.5286"` → `0.53`), `fmtSpread` (`` `${fmtMoney(abs)} (${fmtPct(Number(pct))})` `` →
  `$0.06 (2%)`), `fmtDelta` (fixed 2dp), `fmtIvr` (`n/a` when null; US-67 appends the `(MMM d)` observation date, else trailing zeros
  trimmed — `"44.0"` → `44`), `fmtOpenInterest` (`en-US` grouping, `—` when null), and
  `fmtQuoteTime` (local `HH:mm:ss` via `date-fns`).
- **Why:** These exact renderings are pinned by the ACs and by the mockup. Trailing-zero
  trimming on percents mirrors the US-65 engine's own reason-string convention (up to 2dp,
  zeros trimmed), so the table can never disagree stylistically with an exclusion reason
  beside it. Existing `fmtMoney` / `fmtPct` are reused rather than re-implemented.
- **Alternatives considered:** fixed 2dp everywhere (rejected — the AC pins `1.5%`, not
  `1.50%`); formatting in the main process and shipping display strings (rejected — US-65
  deliberately ships 4dp values and leaves display to the surface; two sources of rounding
  truth violates the round-once ADR).
- **Source:** `plans/us-66/research.md`

### ADR: Stale badge = market display CLOSED, driven by the existing pill wiring

- **Decision:** `ScreenerPage` calls `useMarketStatusDisplay()`; when `display === 'CLOSED'`
  **and** ranked results exist **and** the payload carries a `quoteTimestamp`, the header
  shows a gold `Stale snapshot` badge and the table is captioned
  `Quoted {fmtQuoteTime(quoteTimestamp)} · after-hours option marks are unreliable …`.
  `LIVE`/`EXT` render unbadged. The pill itself renders in the page header in all states.
  All three renderings (badge, caption, count-line variant) key off one derived value,
  `staleQuoteTime`, so they cannot disagree.
- **Why:** The AC pins exactly one trigger — "Given the market status pill reads CLOSED" —
  and the mockup's `stale` state is the CLOSED session. Reusing `useMarketStatusDisplay`
  keeps one session-derivation path: the pill plus this badge are the only freshness
  indicators, and no polling/timing copy was invented.
- **Alternatives considered:** badging on `EXT` too (rejected — not in the AC; US-67 can
  widen the predicate in one place); comparing `quoteTimestamp` age against wall-clock
  (rejected — invents a staleness heuristic the story doesn't define).
- **Source:** `plans/us-66/research.md`

### ADR: Three mutually exclusive body states + always-visible exclusions under `ok`

- **Decision:** The page body renders exactly one of: (1) **ranked table**
  (`status: 'ok'`, `ranked.length > 0`), (2) **empty card** "No candidates match your
  criteria" (`status: 'ok'`, `ranked.length === 0`), (3) **outage card** "Market data
  unavailable" with red-toned border/icon and a "Retry refresh" button
  (`status: 'provider_unavailable'`). The collapsed **Excluded (n)** section renders below
  states (1) _and_ (2) whenever `excluded.length > 0`; it never renders in state (3).
- **Why:** The ACs require outage and empty to be visually distinct (error-red vs
  neutral-muted per the mockup's `CenteredCard` tones). Showing exclusions under the empty
  state follows the story's trust requirement — an all-excluded screen _is_ the empty
  state, and hiding the reasons there would be exactly the silent trimming the story
  forbids. Never under outage, because US-65 guarantees `excluded` is empty on an outage
  (an outage says nothing about individual tickers).
- **Alternatives considered:** following the mockup literally, with no excluded section on
  the empty state (rejected — the mockup's `empty` toggle simply doesn't populate fixtures
  for it; the story text is the stronger signal); a single generic empty component
  parameterised by tone (**kept**, as one `ScreenerStateCard` with a `tone` prop, since the
  two cards differ only in tone / copy / action).
- **Source:** `plans/us-66/research.md`

### ADR: Score is exposed as a row data-attribute, not a column

- **Decision:** The ranked table has no score column; each row carries
  `data-yield-per-delta={fmtScore(candidate.yieldPerDelta)}` and
  `data-testid={'screener-row-' + ticker}`, and a `ScoreLegend` caption under the table
  explains the ranking ("Ranked by yield-per-delta — annualized return-if-flat ÷ delta").
  The rank badge additionally gets the score as a `title`.
- **Why:** AC scenario 2 asserts "its yield-per-delta score is 0.53" — the number must be
  machine-verifiable — but the mockup deliberately keeps it out of the dense column set and
  explains it in the legend instead. A data attribute satisfies the AC in e2e without
  adding a 13th column the design rejected.
- **Alternatives considered:** a visible score column (rejected — contradicts the mockup
  and widens an already 12-column dense table); tooltip-only via `title` (weaker — `title`
  is a UX affordance, the data attribute is the stable test contract, so the badge gets
  `title` as a bonus rather than as the contract).
- **Source:** `plans/us-66/research.md`

### ADR: Out-of-scope mockup elements are omitted, with their seams left intact

- **Decision:** Do **not** render the Promote button/column (US-68), the earnings warning
  badges or earnings row-demotion (US-70 — `earningsFlagged` is read into the renderer type
  but unused), or any criteria-editing affordance (US-67 — the empty card's "Open Screener
  settings" action from the mockup is omitted; the card is copy-only).
- **Why:** The story's Out of Scope section names all three explicitly, and Simplicity
  First forbids speculative rendering. Keeping `earningsFlagged` on the renderer type (it
  is already in `IpcScoredCandidate`) means US-70 adds a badge without touching the adapter.
- **Alternatives considered:** a disabled Promote button as a placeholder (rejected — dead
  UI for a story that may reshape it).
- **Source:** `plans/us-66/research.md`

### ADR: New `/screener` route + nav item after Watchlist

- **Decision:** Add `<Route path="/screener" component={ScreenerPage} />` and a `NavItem`
  (icon `⌕`, label from the exported `SCREENER_PAGE_TITLE`) in the Trading group directly
  after Watchlist in `App.tsx`, plus a `/screener` entry in the shell's `PAGE_TITLES` map.
- **Why:** The mockup's sidebar shows Screener adjacent to Watchlist (the feed it screens);
  hash routing and `NavItem`/`Route` are the established mechanism. Watchlist-then-Screener
  matches the trader's flow (curate list → screen it). Sourcing the label from the exported
  constant means the sidebar, shell header, and page heading cannot drift apart.
- **Alternatives considered:** the mockup's exact order (Watchlist, Screener, Calendar —
  i.e. moving Calendar) (rejected — reordering existing nav is unrelated churn).
- **Source:** `plans/us-66/research.md`, `plans/us-66/refactor-phase-results.md`

### ADR: Route paths stay stated in three places

- **Decision:** The refactor phase replaced the shell header's five-deep nested ternary with
  a `PAGE_TITLES` lookup, but left route paths stated in three places — nav item, title map,
  and the `Switch`.
- **Why:** Collapsing them needs a config-driven `PAGES` array, and the sidebar's
  interleaved section headers, the `/` route's two-value active check (`'/' || ''`), and the
  nav-less `/positions/:id` route each become an exception encoded into that config. The
  duplication is cheaper than the abstraction.
- **Source:** `plans/us-66/refactor-phase-results.md`

### ADR: E2E fixtures reproduce AC numbers through the real engine

- **Decision:** `e2e/screener-helpers.ts` builds OCC-keyed `WHEELBASE_MOCK_OPTION_SNAPSHOTS`
  fixtures with expirations computed from `localDate(offset)` so DTE lands in the default
  30–45 window on any run date. Canonical fixtures (all puts, signed negative deltas as the
  provider ships them): **KO** 60 @ 0.92/0.98 mid 0.95, δ −0.22, OI 1800, +37d ⇒ score 0.71
  (rank 1); **AAPL** 180 @ 2.67/2.73 mid 2.70, δ −0.28, OI 4200, +37d ⇒ period 1.5%, ann
  14.8%/yr, score 0.53, spread `$0.06 (2%)`; **MSFT** 410 @ 6.05/6.35 mid 6.20, δ −0.25, OI
  2600, +44d ⇒ score 0.50 with **no IVR outcome programmed** ⇒ `n/a`; **TSLA** 240 @
  2.67/3.33 mid 3.00, δ −0.25, OI 1000, +37d ⇒ excluded `spread 22% exceeds 10%` (spread
  0.66 is exactly 22% of mark, chosen so the engine's round-up-2dp formatter emits the AC's
  literal string). Watchlist seeded via `window.api.watchlist.add`; IVR (KO 38, AAPL 44) via
  the US-44 offline path (`WHEELBASE_FAKE_IVR` + `_test:ivr-set-outcomes` + collect-now);
  outage via `FAKE_MARKET_DATA_ERROR: 'network_error'`; CLOSED session via
  `FAKE_MARKET_STATUS`.
- **Why:** The ACs pin exact rendered strings. Deriving them from real engine math over
  crafted fixtures (rather than stubbing the IPC) keeps the test end-to-end and proves the
  renderer formats what US-65 actually emits. AC scenario 2's "expiring 2026-08-21 (37 DTE)"
  is fixture narrative — DTE, not the calendar date, is the invariant; hardcoded dates would
  rot.
- **Alternatives considered:** freezing the app clock (no such seam exists in the packaged
  main process; relative expirations are the established pattern — `e2e/dates.ts`, the
  expiring-soon specs).
- **Source:** `plans/us-66/research.md`, `plans/us-66/red-phase-results.md`

## Acceptance Criteria

- **Background** — the watchlist has been screened, and the market status pill reads LIVE.
- **Results are ranked by yield-per-delta** — given KO scores 0.71, AAPL 0.53 and MSFT
  0.50, KO is listed first, AAPL second, MSFT third; and each row shows strike, expiration,
  DTE, mark, period yield, annualized yield, delta, IV rank, open interest, and spread.
- **A row shows the metrics for its recommended strike** — AAPL's top strike (the $180 put,
  37 DTE, mark $2.70, delta 0.28, OI 4,200, spread $0.06 (2%)) renders `1.5% period`,
  `14.8%/yr`, delta `0.28`, IV rank `44`, `4,200 OI` and `$0.06 (2%)`; its yield-per-delta
  score is 0.53 (0.148 / 0.28).
- **IV rank unavailable is shown, not blank** — with no IVR for MSFT, the IV rank cell reads
  `n/a` and MSFT is still ranked by yield-per-delta.
- **Excluded candidates are listed with a reason** — expanding the excluded section shows
  TSLA with the verbatim reason `spread 22% exceeds 10%`, and no yield-per-delta rank is
  shown for it.
- **Provider outage is distinguished from no results** — when Massive was unreachable, a
  "market data unavailable" state is shown, visually distinct from an empty "no candidates
  match your criteria" state.
- **Stale marks are flagged** — when the market status pill reads CLOSED, the results are
  badged as a stale snapshot with the quote time.

## Decisions & Tradeoffs

- **The renderer never re-sorts.** Rank is `index + 1` over the array US-65 emits, so the
  displayed order can never contradict the engine's.
- **Exclusion reasons render verbatim.** The engine's formatter conventions (2dp deltas, en
  dash in band strings, round-up-trimmed percents, `$`-prefixed money) are load-bearing on
  this page — the table's own formatters trim trailing zeros the same way so a cell and an
  exclusion chip beside it cannot disagree stylistically.
- **Formatters take narrow primitive inputs,** never whole candidate objects, and all
  money-adjacent math goes through `decimal.js`. `fmtQuoteTime` uses `date-fns`
  `format(parseISO(...))` — never string-slicing a timestamp.
- **`ScreenerStateCard` tones are machine-checkable** via a `data-tone` attribute, so "the
  two states are visually distinct" is asserted rather than eyeballed.
- **The count line doubles as the stale indicator** — `3 candidates · 4 excluded` becomes
  `3 candidates · quoted 16:00:02` when the snapshot is stale.
- **`WatchlistPage`'s `EmptyGuidance` was deliberately not merged** with
  `ScreenerStateCard`: two call sites with different chrome is not duplication worth an
  abstraction.
- **Layer 5's e2e tests were green on arrival** — Layer 5 verifies Layers 1–4 end-to-end and
  the plan budgets no production code for its Green step — so their assertions were proved
  live by running a throwaway copy of the spec with every expected value flipped: all six
  failed against the real rendered value, each of which is exactly the string its AC pins.
  (Same falsification technique US-65's Layer 4 used.)
- **One Electron launch site for the whole e2e suite.** The refactor extracted
  `launchElectron(env)` into `e2e/assignment-helpers.ts`; `launchApp`, `launchIvrApp`, and
  `launchScreener` all delegate to it.
- **The IVR e2e seeding path goes through open positions.** The real collector reads its
  targets from `positions WHERE status != 'CLOSED'`, so the screener spec seeds a throwaway
  active CSP per ticker before collecting — inert here, since the screener reads only the
  watchlist.
- **`pnpm typecheck` does not cover `e2e/`** (pre-existing gap); e2e type errors surface
  only at run time under Vitest. `vitest.e2e.config.ts` sets `bail: 1`, so use `--bail=0`
  when diagnosing a failing run.

## Open Questions

- **Criteria are not editable** — the page always screens against
  `DEFAULT_SCREENING_CRITERIA`; the settings UI is US-67, and the empty card's "Open
  Screener settings" action from the mockup is omitted until it exists.
- **`earningsFlagged` is read but never rendered** — US-70 supplies both the earnings
  calendar and the badge treatment.
- **No Promote action** — moving a candidate into the trade form is US-68.
- **Refresh is manual only** — there is no polling and no auto-refresh; the trader
  re-triggers a screen via the outage card's retry or by re-entering the page.
- **The stale predicate is CLOSED-only** — whether `EXT` should also badge is left for a
  later story to decide in one place.
