# Extract: us-12

## Summary
US-12 delivers the ability to roll an open CSP out to a new expiration (same strike) with a live net credit/debit preview. The backend records an atomic ROLL_FROM/ROLL_TO leg pair linked by a shared `roll_chain_id`, recalculates cost basis, and keeps the position in `CSP_OPEN`. The frontend adds a right-side sheet (420px) with form validation, real-time client-side preview, and a post-success summary state. (Source: `plans/us-12/plan.md` Summary)

## Architecture Decisions

### ADR: Reuse existing `roll_chain_id` column
- **Decision:** Use the existing `roll_chain_id TEXT` column in the `legs` table (migration 001)
- **Why:** Already present in schema; no new migration needed
- **Alternatives considered:** Adding a separate `rolls` join table — not needed given the linked-leg-pair design already baked in
- **Source:** `plans/us-12/research.md`

### ADR: Reuse existing ROLL_FROM / ROLL_TO leg roles
- **Decision:** Use existing `ROLL_FROM` and `ROLL_TO` values in the `LegRole` enum (`src/main/core/types.ts`)
- **Why:** Already defined; `costbasis.ts` already references `ROLL_TO` in `LEG_ROLE_LABEL`
- **Alternatives considered:** None — these are already in the type system
- **Source:** `plans/us-12/research.md`

### ADR: Standalone service file per operation
- **Decision:** Create a standalone service file `src/main/services/roll-csp-position.ts` (not adding to `positions.ts`)
- **Why:** All other operations follow the one-file-per-operation pattern (close-csp-position.ts, assign-csp-position.ts, etc.)
- **Alternatives considered:** Adding to positions.ts — inconsistent with existing pattern
- **Source:** `plans/us-12/research.md`

### ADR: Cost basis after roll computed in pure engine
- **Decision:** Add `calculateRollBasis` to `src/main/core/costbasis.ts`. Formula: `prevBasisPerShare - netCreditPerShare` (credit case) or `prevBasisPerShare + netDebitPerShare` (debit case), where `netCredit = newPremium - costToClose`. Net per-share = net/contract value (option contracts are per-share already, 1 contract = 100 shares, so `netTotal = net * contracts * 100`, and `netPerShare = netTotal / (contracts * 100) = net`).
- **Why:** Consistent with `calculateCcOpenBasis` pattern; credit reduces basis, debit increases it
- **Alternatives considered:** Inline math in service — violates pure-engine boundary rule
- **Source:** `plans/us-12/research.md`

### ADR: Phase stays CSP_OPEN after roll
- **Decision:** Phase stays `CSP_OPEN` after a roll
- **Why:** Explicitly stated in the user story; the trader is extending the trade, not closing it
- **Alternatives considered:** N/A — requirement is clear
- **Source:** `plans/us-12/research.md`

### ADR: IPC handler uses `registerParsedPositionHandler` helper
- **Decision:** Use `registerParsedPositionHandler` helper for `positions:roll-csp`
- **Why:** Identical to all other position mutation handlers; eliminates boilerplate
- **Alternatives considered:** Inline `ipcMain.handle` — inconsistent with existing pattern
- **Source:** `plans/us-12/research.md`

### ADR: RollCspSheet uses portal pattern (420px)
- **Decision:** `RollCspSheet` uses `createPortal` to `document.body`, width 420px (matches mockup), slide-in animation class, success state rendered inside same portal
- **Why:** Matches `ExpirationSheet`, `AssignmentSheet`, `OpenCoveredCallSheet` patterns exactly; mockup specifies 420px
- **Alternatives considered:** Separate success page — inconsistent with existing UX patterns
- **Source:** `plans/us-12/research.md`

### ADR: Net credit/debit preview computed client-side
- **Decision:** Compute client-side in real time as the user types (no IPC call needed)
- **Why:** Pure arithmetic (`newPremium - costToClose`); no server-side state required. Matches mockup's `NetCreditDebitPreview` component logic
- **Alternatives considered:** Debounced IPC call — unnecessary round-trip for simple math
- **Source:** `plans/us-12/research.md`

### ADR: React Hook Form + Zod resolver for the sheet form
- **Decision:** React Hook Form + Zod resolver (`zodResolver`) — already used in `NewWheelForm.tsx` and other forms
- **Why:** Consistent with existing codebase; Zod schemas already defined on the main-process side; renderer-side schemas are defined inline in components
- **Alternatives considered:** Uncontrolled inputs — inconsistent with existing pattern
- **Source:** `plans/us-12/research.md`

### ADR: `newStrike` optional in payload schema
- **Decision:** Include `newStrike` as optional in `RollCspPayloadSchema` (defaults to current strike on the service side for roll-out). The form pre-fills it with the current strike (editable, not read-only at the data layer — the sheet renders it as editable per mockup, which supports both US-12 roll-out and US-13 roll-down-out)
- **Why:** Story notes say "newStrike is optional; defaults to current strike for roll-out"
- **Alternatives considered:** Separate schemas for roll-out vs roll-down — unnecessary complexity
- **Source:** `plans/us-12/research.md`

### ADR: Active-leg query must include ROLL_TO (post-review fix)
- **Decision:** Changed the `LEFT JOIN legs` subquery in `get-position.ts` from `leg_role = 'CSP_OPEN'` to `leg_role IN ('CSP_OPEN', 'ROLL_TO')`. Same for `CC_OPEN`. The `ORDER BY fill_date DESC, created_at DESC LIMIT 1` ensures the most recent leg wins.
- **Why:** After a roll the new effective open leg is a ROLL_TO; a query restricted to `leg_role = 'CSP_OPEN'` returned a stale leg and broke second-roll behavior
- **Alternatives considered:** None recorded
- **Source:** `plans/us-12/green-phase-results.md`

z.object({

| `newPremiumPerContract`  | `must_be_positive`      | `New premium must be greater than zero`               |

### rollCsp lifecycle function
- **Type:** other (pure lifecycle engine function)
- **Shape:**
```typescript
interface RollCspInput {
  currentPhase: WheelPhase
  currentExpiration: string
  newExpiration: string
  costToClosePerContract: number
  newPremiumPerContract: number
}
interface RollCspResult {
  phase: 'CSP_OPEN'
}
function rollCsp(input: RollCspInput): RollCspResult
```
Validations (throws `ValidationError`):
- `currentPhase === 'CSP_OPEN'` else field `__phase__` / code `invalid_phase`
- `newExpiration > currentExpiration` else field `newExpiration` / code `must_be_after_current`
- `costToClosePerContract > 0` else field `costToClosePerContract` / code `must_be_positive`
- `newPremiumPerContract > 0` else field `newPremiumPerContract` / code `must_be_positive`
- **Source:** `plans/us-12/plan.md` area 1, `plans/us-12/data-model.md`
- **Implementation:** `src/main/core/lifecycle.ts`

### calculateRollBasis cost-basis function
- **Type:** other (pure cost-basis engine function)
- **Shape:**
```typescript
interface RollBasisInput {
  prevBasisPerShare: string
  prevTotalPremiumCollected: string
  costToClosePerContract: string
  newPremiumPerContract: string
  contracts: number
}
interface RollBasisResult {
  basisPerShare: string
  totalPremiumCollected: string
}
function calculateRollBasis(input: RollBasisInput): RollBasisResult
```
Formula:
- `net = new Decimal(newPremiumPerContract).minus(costToClosePerContract)` (positive = credit)
- `basisPerShare = round4(new Decimal(prevBasisPerShare).minus(net)).toFixed(4)`
- `netTotal = net.times(sharesFromContracts(contracts))`
- `totalPremiumCollected = round4(new Decimal(prevTotalPremiumCollected).plus(netTotal)).toFixed(4)`
- **Source:** `plans/us-12/plan.md` area 2, `plans/us-12/data-model.md`
- **Implementation:** `src/main/core/costbasis.ts`

### rollCspPosition service
- **Type:** other (service function)
- **Shape:**
Service steps:
1. `getPosition(db, positionId)` — throws if null or no active leg
2. `rollCsp(...)` lifecycle call — throws on validation failure
3. `calculateRollBasis(...)` — compute new basis
4. `db.transaction(() => { ... })()` containing:
   - `INSERT INTO legs` for ROLL_FROM (BUY, strike=currentStrike, expiration=currentExpiration, roll_chain_id=shared UUID)
   - `INSERT INTO legs` for ROLL_TO (SELL, strike=newStrike??currentStrike, expiration=newExpiration, roll_chain_id=same UUID)
   - `INSERT INTO cost_basis_snapshots` with new basis values, `final_pnl=NULL`
   - Position row NOT updated (phase stays CSP_OPEN, no closed_date)
5. Returns `{ position, rollFromLeg, rollToLeg, rollChainId, costBasisSnapshot }`
- **Source:** `plans/us-12/plan.md` area 4
- **Implementation:** `src/main/services/roll-csp-position.ts`

## Schema Changes

### `legs` table — no schema change
- **Change:** none (reuse of existing `roll_chain_id TEXT` column and existing `ROLL_FROM` / `ROLL_TO` LegRole enum values)
- **Columns / fields:**
  - ROLL_FROM leg row (buy-to-close): `leg_role=ROLL_FROM`, `action=BUY`, `instrument_type=PUT`, `strike` = current CSP strike (unchanged), `expiration` = current CSP expiration (unchanged), `contracts` = same as current CSP, `premium_per_contract` = `costToClosePerContract` (what it costs to close), `fill_date` = payload fillDate (or today), `roll_chain_id` = shared UUID generated for this roll
  - ROLL_TO leg row (sell-to-open): `leg_role=ROLL_TO`, `action=SELL`, `instrument_type=PUT`, `strike` = `newStrike` (or current strike for roll-out), `expiration` = `newExpiration`, `contracts` = same as current CSP, `premium_per_contract` = `newPremiumPerContract`, `fill_date` = payload fillDate (or today), `roll_chain_id` = same UUID as ROLL_FROM
- **Source:** `plans/us-12/data-model.md`, `plans/us-12/quickstart.md` ("No migrations are needed")
- **Migration file:** none — `roll_chain_id` already exists in `migrations/001_initial_schema.sql`

### `positions` table — no update
- **Change:** none (position row is not updated)
- **Columns / fields:** phase stays `CSP_OPEN`, status stays `ACTIVE`. The new ROLL_TO leg becomes the effective open leg (most recent SELL leg in leg history).
- **Source:** `plans/us-12/data-model.md`
- **Migration file:** n/a

### `cost_basis_snapshots` — new snapshot row per roll
- **Change:** new row inserted (no schema change)
- **Columns / fields:**
  - `basis_per_share` = `prevBasisPerShare - netCreditPerContract` (credit) or `prevBasisPerShare + netDebitPerContract` (debit)
  - `total_premium_collected` = `prevTotalPremiumCollected + (newPremium - costToClose) * contracts * 100` (net, can be negative on a debit roll)
  - `final_pnl` = `null` (position not closed)
- **Source:** `plans/us-12/data-model.md`
- **Migration file:** n/a

## Acceptance Criteria

- Roll form shows current leg summary and new leg inputs — the form displays current leg: strike $180.00, expiration 2026-04-18, DTE remaining, premium collected $350.00; the form has inputs for new expiration date, cost to close (per contract), new premium (per contract); the strike field is pre-filled with $180.00 and read-only (roll out keeps the same strike).
- Net credit/debit preview updates as trader enters values — entering cost to close $1.20/contract and new premium $2.80/contract shows "Net Credit: $1.60/contract ($160.00 total)" displayed in green.
- Net debit preview shown with warning — entering cost to close $3.00/contract and new premium $2.50/contract shows "Net Debit: $0.50/contract ($50.00 total)" in amber/yellow with a warning icon and note "This roll will cost more to close than the new premium provides".
- Successful CSP roll out creates linked leg pair — confirming with cost to close $1.20, new premium $2.80, new expiration 2026-05-16 closes the old CSP leg with a ROLL_FROM leg (action: BUY, premium: $1.20), opens a new CSP leg with a ROLL_TO leg (action: SELL, strike: $180.00, expiration: 2026-05-16, premium: $2.80), both legs share the same roll_chain_id, the position remains in phase CSP_OPEN, a new cost basis snapshot is created reflecting the roll's net credit, and the trader is returned to the position detail page.
- Roll form validates new expiration is later than current — entering a new expiration of 2026-04-11 (before the current 2026-04-18) and attempting to confirm shows validation error "New expiration must be after the current expiration" and the roll is not executed.
- Roll form validates positive cost to close — entering cost to close $0.00 and attempting to confirm shows validation error "Cost to close must be greater than zero".
- Roll form validates positive new premium — entering new premium $0.00 and attempting to confirm shows validation error "New premium must be greater than zero".

(Source: `docs/epics/03-stories/US-12-roll-open-csp-out.md` — Gherkin Acceptance Criteria; AC text replicated in `plans/us-12/plan.md` and `plans/us-12/tasks.md` Layer 6.)

## Decisions & Tradeoffs

- Background blur: `rollCspOpen` must be included in `overlayOpen` prop passed to `PositionDetailContent` so the background blurs when the sheet is open. (Source: `plans/us-12/plan.md` area 9, `plans/us-12/tasks.md` Layer 5 Green)
- IPC log label convention: handler error label follows `positions_{verb}_{noun}_unhandled_error` pattern → `positions_roll_csp_unhandled_error`. (Source: `plans/us-12/plan.md` area 5, `plans/us-12/tasks.md` Layer 3)
- Snake_case at renderer adapter boundary: `RollCspPayload` is snake_case on the renderer side; adapter maps to camelCase for IPC. (Source: `plans/us-12/contracts/roll-csp.md`)
- Roll-after-roll: second roll must read strike/expiration from the previous ROLL_TO leg, not the original CSP_OPEN leg — required updating `get-position.ts` active-leg query to include ROLL_TO. (Source: `plans/us-12/red-phase-results.md` #1, #5; `plans/us-12/green-phase-results.md` #1+#5)
- Debit hero color: in `RollCspSuccess` the hero card uses gold/amber tokens (not green) when `isCredit === false` — applied to hero card, header border, and "Roll Complete" label. (Source: `plans/us-12/green-phase-results.md` #2)
- NaN strike protection: `RollCspSheet` tracks `strikeError` state and validates strike for NaN/empty/non-positive values in its `validate()` function, passing the error through to `RollCspForm` for display. (Source: `plans/us-12/green-phase-results.md` #6)
- `NetCreditDebitPreview` extraction: extract as a separate component if over ~30 lines. (Source: `plans/us-12/plan.md` area 8 Refactor)
- Date format strictness: `newExpiration` rejects non-`YYYY-MM-DD` formats including "May 16, 2026", `2026/05/16`, and empty string. (Source: `plans/us-12/red-phase-results.md` #3, `plans/us-12/green-phase-results.md` #3)
- Roll type badge: dynamic label from `getRollTypeLabel(currentStrike, newStrike)` → "Roll Out" (same strike) / "Roll Down & Out" (lower) / "Roll Up & Out" (higher). (Source: `plans/us-12/plan.md` area 8)
- Irrevocable warning text (verbatim): "This cannot be undone. A ROLL_FROM leg (buy-to-close) and ROLL_TO leg (sell-to-open) will be recorded as a linked pair. The position remains in CSP_OPEN phase." (Source: `plans/us-12/plan.md` area 8)
