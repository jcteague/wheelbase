## Summary
Adds a settings workflow for broker credentials and runtime broker-environment switching without tying broker state to shared market-data configuration. Massive credentials remain shared app-level configuration and are never stored in user settings. Alpaca paper and live credentials are stored in SQLite via a new generic `credential_settings` table with `safeStorage.encryptString` encryption, while non-secret state such as the active broker environment is persisted in a new `app_settings` table. A dedicated `save-verified-alpaca-credentials.ts` service (added post-plan during code-review) extracts the test-then-save orchestration out of the IPC handler. The renderer gets a dedicated `#/settings` route, per-environment Alpaca credential cards, a shared Massive status/test section, an always-visible `EnvironmentBadge`, a separate `MarketDataStatusDot`, and broker-only query invalidation keyed off `queryKey[0] === 'broker'`. Runtime broker changes recreate only the broker provider; market data continues uninterrupted. End-to-end coverage landed in `e2e/settings-environment.spec.ts`, covering vendor separation, test-connection flows, LIVE confirmation, secure persistence, stale-market-data fallback, and remembered broker environment. (Sources: `plans/us-37/plan.md`, `plans/us-37/quickstart.md`, `plans/us-37/refactor-phase-results.md`, `e2e/settings-environment.spec.ts`)

## Architecture Decisions

### ADR: Massive stays shared app configuration; user settings store Alpaca only
- **Decision:** Keep Massive credentials out of user settings entirely. The settings page can display Massive status and run a fixed reference probe, but there are no save/remove Massive settings channels and no Massive rows in `credential_settings`.
- **Why:** Product clarification changed the original story shape: Massive credentials are shared for all users and come from app configuration/env/packaging, while Alpaca paper/live credentials are user-specific.
- **Alternatives considered:** Per-user Massive credential storage in settings. Rejected because it conflicts with the clarified deployment model and would blur broker state with market-data state.
- **Source:** `plans/us-37/research.md`, `plans/us-37/data-model.md`, `plans/us-37/contracts/settings-ipc.md`

### ADR: Broker provider refresh is runtime-scoped; market-data provider is not recreated from settings
- **Decision:** `src/main/index.ts` registers broker handlers against a current-provider accessor so broker settings changes recreate only the broker provider cache. Market data keeps loading its shared Massive key from app configuration and is not recreated by settings page actions.
- **Why:** The story requires immediate broker-environment switching without interrupting ongoing quote/option data flows.
- **Alternatives considered:** Restart the app after credential changes; invalidate and recreate both provider stacks together. Both were rejected because they violate the scoped-refresh acceptance criteria.
- **Source:** `plans/us-37/research.md`, `plans/us-37/plan.md`, `plans/us-37/refactor-phase-results.md`

### ADR: Query invalidation is vendor-scoped by first key segment
- **Decision:** Normalize renderer query keys so broker reads start with `['broker', ...]` and market-data reads start with `['market', ...]`. Settings mutations invalidate broker queries via a predicate on `queryKey[0] === 'broker'` and separately refresh `settingsQueryKeys.status`.
- **Why:** The broker environment switch should refresh buying power, activities, and market-status surfaces without causing stock quote or option snapshot churn.
- **Alternatives considered:** Blanket invalidation after every settings mutation. Rejected because the story explicitly preserves uninterrupted market-data polling/streaming.
- **Source:** `plans/us-37/research.md`, `plans/us-37/plan.md`

### ADR: LIVE activation is a confirmed renderer action; switching back to paper is immediate
- **Decision:** The renderer shows a dedicated `LiveBrokerConfirmDialog` before invoking `settings:set-active-broker-environment` with `environment: 'live'`. The dialog includes copy about live-account reads, unsynced Wheelbase positions, unaffected Massive market data, and an open-position warning derived from existing position-list data. Switching from live back to paper has no dialog.
- **Why:** The story wants a visible risk boundary around live broker reads while keeping the paper path lightweight.
- **Source:** `plans/us-37/research.md`, `plans/us-37/quickstart.md`, `e2e/settings-environment.spec.ts`

### ADR: Save-then-verify orchestration extracted into its own service
- **Decision:** `save-verified-alpaca-credentials.ts` owns the test-connection → validate → save → compute-refresh-flag flow. `settings.ts` delegates to it via `saveVerifiedAlpacaCredentials`. The IPC handler calls `settings.saveVerifiedAlpacaCredentials` directly and receives back `{ status, test, refreshBroker }`.
- **Why:** Code-review feedback after the plan was written identified that the IPC handler was doing orchestration that belongs in the service layer. Extracting it keeps the handler thin and makes the flow independently testable.
- **Source:** `src/main/services/save-verified-alpaca-credentials.ts`, `src/main/ipc/settings.ts`

## Contracts

### New persisted shapes
- **`credential_settings`** — generic credential table keyed by `(vendor, environment)` with encrypted `key_id_encrypted`, encrypted `secret_encrypted`, optional `last_verified_at`, masked account number, and timestamps. US-37 writes Alpaca rows only.
- **`app_settings`** — key/value settings table used here for `active_broker_environment = 'paper' | 'live' | 'none'`.
- **Source:** `plans/us-37/data-model.md`

### Settings IPC channels
- **`settings:get-credential-status`** — returns `CredentialStatus` with shared Massive status, per-environment Alpaca status, active broker environment, and masked account numbers.
- **`settings:save-alpaca-credentials`** — validates trimmed non-empty credentials, tests them via `saveVerifiedAlpacaCredentials`, encrypts them, upserts the requested Alpaca environment, returns `{ status, test }`, and refreshes the broker provider only when the active environment changed or was updated.
- **`settings:remove-alpaca-credentials`** — deletes paper or live credentials, resets active broker environment to `none` when removing the active row, and refreshes broker state only when needed.
- **`settings:set-active-broker-environment`** — requires that the target environment has saved credentials, persists the active environment, and recreates only the broker provider.
- **`settings:test-connection`** — discriminated union payload: Massive runs a fixed `GET /v3/reference/tickers/AAPL` probe with the shared configured key; Alpaca runs `GET /v2/account` against paper or live using candidate credentials and returns the masked account number.
- **`settings:test-stored-alpaca-connection`** — added post-plan; uses already-saved encrypted credentials for a paper/live re-verification probe without exposing secrets back to the renderer.
- **Source:** `plans/us-37/contracts/settings-ipc.md`, `src/main/ipc/settings.ts`

### Connection probe mismatch detection
The original plan specified only the paper-card direction (live keys in paper card → `environment_mismatch`). The actual implementation in `settings-connections.ts` detects **both** directions:
- Paper card + key starting with `AK` → `Environment mismatch — these are LIVE keys, not paper keys`
- Live card + key starting with `PK` → `Environment mismatch — these are PAPER keys, not live keys`

Both helpers are exported: `isLikelyLiveKey` and `isLikelyPaperKey`.

### Renderer-facing state
- **`CredentialStatus`** — `{ massive, alpacaPaper, alpacaLive, activeBrokerEnv, massiveLastCheckedAt, alpacaPaperAccountNumberMasked, alpacaLiveAccountNumberMasked }`
- **`TestConnectionResult`** — success for Massive (`connected`) or Alpaca (`environment`, `accountNumberMasked`), or typed failure with `errorCode` and `message`
- **Source:** `plans/us-37/data-model.md`, `src/renderer/src/api/settings.ts`

## Decisions & tradeoffs

- **Secrets never round-trip to the renderer.** Saved cards render masked placeholders plus a `Replace` flow; the renderer never receives decrypted key material.
- **`CredentialStatus.massiveLastCheckedAt` remains `null`.** The status shape reserves the field, but the current implementation does not persist a Massive probe timestamp.
- **`settings:test-stored-alpaca-connection` was added post-plan.** The original plan focused on candidate-key tests. This extra channel supports re-verification/re-entry flows without re-entering credentials or exposing saved key material.
- **Bidirectional mismatch detection is broader than the plan spec.** The plan only specified the paper←live direction. The implementation also catches live←paper (`PK`-prefixed keys in live card) for symmetry.
- **Market-data unavailability is vendor-specific.** Massive auth failures affect live quote surfaces and stale-data messaging; broker auth failures affect account/activity surfaces and the broker setup prompt.
- **`save-verified-alpaca-credentials.ts` was extracted to keep the IPC handler thin.** This was a code-review-driven refactor, not part of the original plan.
