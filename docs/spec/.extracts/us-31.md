## Summary

Builds a provider-agnostic `MarketDataProvider` interface with an `AlpacaMarketDataProvider` implementation supporting both REST request/response (stock quotes, option snapshots, activities, account info, market status) and WebSocket streaming (stock quotes via JSON, option quotes/trades via MessagePack). A factory function abstracts provider construction so downstream services never import the concrete class. This is the foundational integration layer for all Epic 06 live market data stories. Streaming uses RxJS Observables so downstream consumers get first-class unsubscription, error/completion channels, and operators like `retry`, `share`, and `debounceTime`. (Source: `plans/us-31/plan.md`)

## Architecture Decisions

### ADR: Alpaca SDK — use for REST, bypass for streaming

- **Decision:** Use `@alpacahq/typescript-sdk` (v0.0.32-preview) for REST calls where it works correctly; bypass it with raw `ws` WebSocket clients for streaming. Keep working endpoints on the SDK rather than rewriting them.
- **Why:** The SDK is a Deno-to-Node transpile (via `dnt`), marked as no longer maintained. Several methods have bugs or incomplete types (`getStocksSnapshots` hits wrong path; `getOptionsSnapshots` type omits `greeks`/`impliedVolatility`; `getActivity` ignores query params; WebSocket streaming is "todo"). The core REST client (`getAccount`, `getClock`, `getStocksQuotesLatest`, `getActivity`) works. Building a full replacement HTTP client would be wasted effort.
- **Alternatives considered:** Replace SDK entirely with raw `fetch` (too much work for endpoints that already work); `alpaca-trade-api-js` (older, callback-based, worse TypeScript support).
- **Source:** `plans/us-31/research.md`

### ADR: Streaming via raw `ws` package with two dedicated sockets

- **Decision:** Use the `ws` npm package with two independent WebSocket connections — one for stock data at `wss://stream.data.alpaca.markets/v2/{dataFeed}` (JSON frames), one for option data at `wss://stream.data.alpaca.markets/v1beta1/{optionFeed}` (MessagePack binary frames). Multiplex all symbol subscriptions over each connection.
- **Why:** Alpaca SDK has zero WebSocket support. Node's built-in `WebSocket` (Node 21+) may differ in Electron's bundled Node version. `ws` is battle-tested, works identically in Electron main process and Vitest, and is trivially mockable. Alpaca allows only 1 concurrent connection per endpoint, so multiplexing is required.
- **Alternatives considered:** Node built-in WebSocket (Electron's bundled Node may not match; less mockable); `socket.io` (wrong protocol, Alpaca uses raw WebSocket).
- **Source:** `plans/us-31/research.md`

### ADR: RxJS Observables for the streaming interface

- **Decision:** Use RxJS `Observable` for `stream(feed, symbols)` — REST methods remain plain `Promise`-returning functions. Errors flow through the Observable error channel as `StreamError`; unsubscribe via `subscription.unsubscribe()` which sends the WebSocket unsubscribe message via Observable teardown.
- **Why:** Hand-rolled callback + manual subscription registry is a less capable Observable. RxJS provides (1) first-class unsubscription via `Subscription`, (2) built-in error/completion channels — no separate `onStreamError` callback, (3) operators downstream stories need: `retry`/`retryWhen` for US-38 reconnection, `share`/`shareReplay` for multicasting in US-32–34, `distinctUntilChanged` and `debounceTime` for throttling. Native `Observable` (WICG, Chromium 135+) only exists in the renderer — the main process is Node.js, which has no native Observable.
- **Alternatives considered:** Native Observable (not available in Node.js/Electron main process, missing critical operators); callbacks with manual registry (reimplements Observable badly; downstream stories would hand-roll retry/multicast); AsyncIterables (pull-based, wrong model for push-based WebSocket streams).
- **Dependency impact:** RxJS is ~30KB tree-shakeable; only `Observable`, `Subject`, and a few utility functions needed here.
- **Source:** `plans/us-31/research.md`

### ADR: MessagePack decoding via `@msgpack/msgpack`

- **Decision:** Use `@msgpack/msgpack` for decoding option stream binary frames. Use `decodeMulti()` (not `decode()`) because Alpaca batches messages as arrays per frame.
- **Why:** Standard MessagePack implementation for JavaScript, works with Node `Buffer` directly (extends `Uint8Array`), and is the library Alpaca documentation references. `decode()` throws `RangeError` if a buffer contains multiple packed objects — `decodeMulti()` handles Alpaca's batching.
- **Alternatives considered:** `msgpack-lite` — older, less maintained, same API surface.
- **Source:** `plans/us-31/research.md`

### ADR: Greeks/IV available via REST snapshot only; OI not available at all

- **Decision:** `OptionSnapshot.greeks` and `OptionSnapshot.iv` come from REST `/v1beta1/options/snapshots` only — stream events never carry them. `openInterest` and `volume` are typed `number | null` and Alpaca always returns `null` for both (not available in any Alpaca option endpoint).
- **Why:** Alpaca's option streaming only provides quote (bid/ask) and trade (price/size) data. Greeks/IV come from the REST snapshot. Open interest is absent from all Alpaca option endpoints.
- **Alternatives considered:** Derive volume from `getOptionsBars()` (possible but adds complexity); OI would need a different data source entirely.
- **Source:** `plans/us-31/research.md`

### ADR: Derive market session client-side from clock + calendar

- **Decision:** Derive session type (`regular`, `pre`, `post`, `closed`) by comparing the clock timestamp against calendar open/close times plus known extended-hours windows. Pre-market is 4:00–9:30 AM ET, post-market is 4:00–8:00 PM ET.
- **Why:** Alpaca's `/v2/clock` only returns `is_open` (boolean), `next_open`, and `next_close`. There is no `session` field. The AC requires session as one of `regular | pre | post | closed`.
- **Alternatives considered:** Only returning `is_open` boolean — insufficient for the AC.
- **Source:** `plans/us-31/research.md`

### ADR: Structured `MarketDataError` class with discriminating `code`

- **Decision:** Define `MarketDataError` extending `Error` with a typed `code` field. Codes: `auth_failed`, `network_error`, `rate_limited`, `stream_disconnected`, `streaming_unsupported`, `subscription_failed`, `unknown`. Throw (don't return) errors, consistent with the rest of the codebase.
- **Why:** Consistent with the story's AC requiring structured errors with specific codes. Services can pattern-match on `error.code` without parsing message strings.
- **Alternatives considered:** Returning `Result<T, E>` tuples — cleaner functionally but inconsistent with the rest of the codebase which uses thrown errors.
- **Source:** `plans/us-31/research.md`, `plans/us-31/data-model.md`

### ADR: Keep existing `alpaca.ts` but mark `@deprecated`

- **Decision:** Keep `src/main/integrations/alpaca.ts` as-is during this story. The new `AlpacaMarketDataProvider` creates its own SDK client internally. Add `@deprecated` JSDoc to `client` and `resetClient` exports. Removal happens when downstream stories migrate callers.
- **Why:** Deleting immediately risks breaking the build if any downstream branch depends on it. Deprecation signals intent without disruption.
- **Alternatives considered:** Delete immediately — safe today (no active imports) but unnecessarily risky.
- **Source:** `plans/us-31/research.md`

### ADR: Provider constructor owns SDK client lifecycle

- **Decision:** `AlpacaMarketDataProvider` constructor accepts `{ keyId, secretKey, paper, dataFeed?, optionFeed? }` and creates the Alpaca SDK client internally via `createClient({ key, secret, paper })`. `environment: 'paper' | 'live'` is derived from the constructor's `paper` flag, not from any API response.
- **Why:** Alpaca's `getAccount()` has no paper/live indicator. The constructor is the only place this fact is known reliably.
- **Source:** `plans/us-31/research.md`, `plans/us-31/data-model.md`

### WebSocket subscribe/unsubscribe protocol

- **Type:** Wire protocol (Alpaca WebSocket)
- **Shape:**

  ```
  // Auth flow (both stock and option sockets)
  1. Client connects to WebSocket
  2. Server: [{"T":"success","msg":"connected"}]
  3. Client: {"action":"auth","key":"...","secret":"..."}
  4. Server: [{"T":"success","msg":"authenticated"}]

  // Subscribe (stock — JSON; option — MessagePack-encoded)
  Client: {"action":"subscribe","quotes":["AAPL","MSFT"]}

  // Server pushes stock quote frame
  [{"T":"q","S":"AAPL","bp":172.60,"ap":172.70,...}]

  // Unsubscribe — sent on Observable teardown
  Client: {"action":"unsubscribe","quotes":["AAPL","MSFT"]}
  ```

- **WebSocket URLs:**
  - Stock: `wss://stream.data.alpaca.markets/v2/{dataFeed}` (default `sip`) — JSON text frames
  - Option: `wss://stream.data.alpaca.markets/v1beta1/{optionFeed}` (default `opra`) — MessagePack binary frames
- **Connection limits:** 1 concurrent connection per endpoint — adapter multiplexes all symbol subscriptions.
- **Paper/live note:** Paper and live accounts share the same data stream URLs; the paper/live distinction only affects the trading API base URL.
- **Source:** `plans/us-31/research.md`, `plans/us-31/plan.md` Area 4

## Acceptance Criteria

(16 ACs — one e2e test per AC; all 16 pass in `src/main/integrations/alpaca-market-data.e2e.test.ts`. Source: `plans/us-31/plan.md` Area 7, `plans/us-31/red-phase-results.md`.)

- **AC-1:** Interface exposes stock quote retrieval — `getStockQuotes(["AAPL","MSFT","TSLA"])` returns a `Map` with 3 entries, each `price` as a 2dp string.
- **AC-2:** Interface exposes option snapshot retrieval — `getOptionSnapshots(["AAPL260516P00180000"])` returns a `Map` entry with `bid`, `ask`, `mid` (= `(bid+ask)/2`), `greeks.delta`, `greeks.iv`, `timestamp`.
- **AC-3:** Interface exposes broker activity polling — `getActivities({ type: "OPASN", since: "2026-04-20" })` returns an array sorted by `transactionTime` descending with fields `activityId`, `activityType`, `symbol`, `qty`, `price`, `transactionTime`.
- **AC-4:** Interface exposes account info retrieval — `getAccountInfo()` returns `buyingPower`, `portfolioValue`, `cash`, `environment` (paper).
- **AC-5:** Interface exposes market status check — `getMarketStatus()` returns `isOpen`, `nextOpen`, `nextClose`, `session` (one of `regular | pre | post | closed`).
- **AC-6:** Provider declares streaming capabilities per feed — `supportsStreaming("stockQuotes" | "optionQuotes" | "optionTrades")` returns `true`.
- **AC-7:** Provider connects and streams stock quotes — after `connect()`, `stream("stockQuotes", ["AAPL","MSFT"]).subscribe(observer)` emits `StreamEvent<StockQuote>` for each tick.
- **AC-8:** Provider streams option quotes via MessagePack — `stream("optionQuotes", ["AAPL260516P00180000"]).subscribe(observer)` decodes MessagePack frames and emits `StreamEvent`.
- **AC-9:** Unsubscribe stops receiving events for those symbols — calling `subscription.unsubscribe()` causes the WebSocket to receive `unsubscribe` and observer receives no further emissions; WebSocket stays open for other subscriptions.
- **AC-10:** Disconnect closes all streams — `disconnect()` closes both sockets and all active subscribers receive `complete`.
- **AC-11:** Alpaca implementation connects using configured credentials — provider built with `paper: true` authenticates against paper endpoints; `getAccountInfo()` returns `environment: "paper"`.
- **AC-12:** Provider returns structured error when credentials are invalid — 401 from SDK becomes `MarketDataError` with `code: "auth_failed"`, message includes `"authentication"`.
- **AC-13:** Provider returns structured error when API is unreachable — network error becomes `MarketDataError` with `code: "network_error"`, message includes endpoint context.
- **AC-14:** Provider emits error event when stream disconnects unexpectedly — unexpected WebSocket close pushes `StreamError` through the Observable error channel with `code: "stream_disconnected"`, includes feed name and `reconnectable: true`.
- **AC-15:** Provider handles unknown ticker gracefully — `getStockQuotes(["AAPL","ZZZZZ"])` returns a `Map` with AAPL only, no error thrown.
- **AC-16:** Subscribe rejects unsupported feed — calling `stream(feed, ...)` where `supportsStreaming(feed)` is `false` throws `MarketDataError` with `code: "streaming_unsupported"`.

## Decisions & Tradeoffs

- **One factory entry per provider, services never import the concrete class.** Downstream code imports `createMarketDataProvider` and the `MarketDataProvider` interface only; the factory hides which provider is in use, enabling future non-Alpaca providers without churn. (Source: `plans/us-31/data-model.md`)
- **REST methods are `Promise`-returning; only streaming uses Observables.** Mixed paradigms intentionally — REST is request/response, streaming is push, and they should be modeled accordingly. (Source: `plans/us-31/research.md`)
- **`StockQuote.change` and `changePercent` are hardcoded to `'0.00'` in both REST and streaming paths** because previous-close data isn't available from `getStocksQuotesLatest` or from stream frames. US-32 later addresses this by adding a `prevClose` field and computing `change` client-side, but US-31 ships with the limitation in place. (Source: `plans/us-31/refactor-phase-layer3-results.md`, `plans/us-31/green-phase-streaming-results.md`)
- **No reconnection logic in the provider.** `StreamError.reconnectable: true` signals intent, but the caller is responsible for retry/reconnect. Downstream stories will compose `retry`/`retryWhen` operators on the Observable. (Source: `plans/us-31/refactor-phase-layer3-results.md`, `plans/us-31/green-phase-streaming-results.md`)
- **One Subject per socket bridges WebSocket events to Observable subscribers.** Each `stream()` call returns a new Observable that filters from the per-socket `Subject<StreamEvent>` by symbol; teardown sends `unsubscribe` and removes the symbol filter. (Source: `plans/us-31/plan.md` Area 4, `plans/us-31/green-phase-streaming-results.md`)
- **`disconnect()` nulls out internal socket and Subject references after cleanup** to prevent accidental use of closed/completed resources. (Source: `plans/us-31/refactor-phase-layer3-results.md`)
- **Shared `mapQuoteToStockQuote(bp, ap, timestamp)` helper** keeps REST and streaming codepaths consistent for `StockQuote` shape construction. (Source: `plans/us-31/refactor-phase-layer3-results.md`)
- **Test utilities (`emitSocketEvent`, `simulateAuth`, `MockSocket`) extracted to `alpaca-stream-test-utils.ts`** to avoid drift between unit and e2e tests; `connectAndAuth` kept per-file because factory vs direct-constructor versions differ. (Source: `plans/us-31/refactor-phase-results.md`)
- **All money values converted via `new Decimal(value).toFixed(2)` (or `.toFixed(4)` for greeks)** — never floats in the public type surface. (Source: `plans/us-31/plan.md` Area 3)
- **Backend-only story — no UI, no IPC handlers, no Zod schemas.** All types are integration-layer TypeScript only; downstream UI stories (US-32–34) wire IPC and Zod on top. (Source: `plans/us-31/quickstart.md`, `plans/us-31/plan.md`)
- **Test file naming:** unit + integration tests live alongside the implementation (`*.test.ts`); end-to-end factory-driven tests live in `*.e2e.test.ts` colocated in the same dir. (Source: `plans/us-31/plan.md` Area 7)
