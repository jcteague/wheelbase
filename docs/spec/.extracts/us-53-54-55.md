# Extract: us-53-54-55

## Summary
This plan adds three Classic Wheel management rules to the Epic 07 alert engine: `MANAGEMENT_WINDOW` (US-53, already implemented at the engine level — this plan adds AC-driven verification only), `PROFIT_TARGET` (US-54), and `STRIKE_PROXIMITY` (US-55). Because US-54 and US-55 require live market data, `evaluateAlerts` becomes async and pre-fetches live option mids and underlying prices at the service boundary, passing plain values into the pure `RULES` registry in `core/alerts.ts`. On the existing scheduler cadence, positions crossing profit-target or strike-proximity thresholds surface deduplicated, restart-safe alerts in the US-51 queue alongside DTE alerts, and clear when conditions reverse. No new tables or migrations are required. A subsequent high-effort code review produced a post-review hardening pass that fixed three failure-isolation defects so that one bad leg, one bad position, or a provider outage can never suppress healthy positions' (especially DTE) alerts. (`plans/us-53-54-55/plan.md`, `research.md`, `refactor-phase-results.md`)

## Architecture Decisions

### ADR: Pre-fetch live marks in the service; keep the rule engine pure
- **Decision:** Live option mids and underlying prices are fetched in `src/main/services/evaluate-alerts.ts` (the service boundary) — one batched `fetchStockQuotes` for the distinct evaluable tickers and one batched `fetchOptionSnapshots` for the distinct evaluable OCC symbols per run — then passed into `AlertEvaluationInput` as plain strings (`currentUnderlyingPrice`, `currentOptionMid`). The `RULES` predicates in `src/main/core/alerts.ts` stay pure and read only the input record; they never call a provider.
- **Why:** Preserves the `src/main/core/` no-I/O rule and the alert-rule-registry ADR. Batching mirrors `fetchOptionSnapshots`/`fetchStockQuotes` usage elsewhere and keeps one provider round-trip per data type per run. Pure predicates stay unit-testable with literal inputs, exactly like the existing DTE rules.
- **Alternatives considered:** (a) Fetch inside each rule predicate — rejected, violates the pure-core rule and would issue N provider calls. (b) Persist a price cache table read synchronously — rejected; no such table exists, and it adds a staleness/write path the stories don't need.
- **Source:** `plans/us-53-54-55/research.md`

### ADR: `evaluateAlerts` becomes async
- **Decision:** Change `evaluateAlerts` to `async` returning `Promise<EvaluateAlertsResult>` and accept an injected `provider: MarketDataProvider` (defaulted from the factory) alongside `db`. The compute phase awaits the two batched fetches first, builds a `ticker → price` map and an `occSymbol → mid` map, then runs the existing synchronous per-position loop. The persist phase (`db.transaction`) is unchanged. The scheduler handler in `src/main/index.ts` already `await`s the handler body, so it passes the provider and awaits `evaluateAlerts`.
- **Why:** The provider API is async-only (`getStockQuotes`/`getOptionSnapshot` return Promises). The compute/persist split from US-50 is retained — all awaits happen in the compute phase, so no write occurs until every fetch and pure evaluation has completed (the US-50 atomicity ADR still holds).
- **Alternatives considered:** Keeping `evaluateAlerts` sync and fetching in the handler — rejected; it would push orchestration into the thin handler and split the compute phase across two files.
- **Source:** `plans/us-53-54-55/research.md`

### ADR: Generalize the engine's missing-data skip from `requiresDte` to a per-rule reason
- **Decision:** Replace the boolean `requiresDte` on `RuleDefinition` with an optional `missingData?: (input) => string | null` that returns a skip reason or `null`. Existing DTE rules return `'missing_dte'` when `dte === null`; `PROFIT_TARGET` returns `'missing_option_mark'` when the live mid (or entry premium/contracts) is absent. `evaluatePosition` calls `missingData` per rule: a non-null reason → `SkippedRule`, else the rule's `test` runs.
- **Why:** US-54 AC requires a DEBUG skip log when the option mark is missing — the skip mechanism must express reasons beyond DTE. A per-rule function keeps each rule self-contained (registry ADR) and lets the service keep logging skips uniformly.
- **Alternatives considered:** Adding more booleans (`requiresOptionMark`, `requiresUnderlyingPrice`) — rejected; a single reason function is less bookkeeping and directly supplies the log reason string.
- **Source:** `plans/us-53-54-55/research.md`

### ADR: STRIKE_PROXIMITY is CSP-only and states direction; below-strike flags in-the-money
- **Decision:** `STRIKE_PROXIMITY` (medium) matches only when `phase === 'CSP_OPEN'` and `|price − strike| / strike × 100 ≤ 1`. Summary states direction relative to the strike: above → `"Stock is {pct}% above the ${strike} put strike"`; below → the same with `" — now in the money"` appended. Percent and strike are formatted to the story's precision (1 dp for percent, 2 dp for strike). When `phase === 'CC_OPEN'` the rule does not apply (no match, no skip). When CSP and the underlying price is missing, the rule skips with `'missing_underlying_price'`.
- **Why:** Matches US-55 ACs exactly (CC positions excluded; direction-aware copy; below-strike is the genuine assignment-risk case). Covered-call breach is US-62; PMCC is Epic 09.
- **Alternatives considered:** Denominator = current price instead of strike — rejected; the summary is phrased relative to the strike and the AC values round identically, so strike is the clearer basis.
- **Source:** `plans/us-53-54-55/research.md`

### ADR: PROFIT_TARGET and STRIKE_PROXIMITY co-fire with DTE rules (no cross-rule precedence)
- **Decision:** The new rules are independent of the DTE rules — a position may hold an open `PROFIT_TARGET` and an open `EXPIRATION_IMMINENT` alert simultaneously (distinct `rule_code`s, distinct rows under the partial unique index). Only `EXPIRATION_IMMINENT`↔`MANAGEMENT_WINDOW` remain mutually exclusive via their DTE windows.
- **Why:** The stories describe orthogonal conditions (opportunity vs. time vs. assignment risk); the queue is expected to show them as separate items. No AC asks to suppress one for another across these dimensions.
- **Alternatives considered:** Suppressing lower-urgency rules when a higher one fires — rejected; not in any AC and would hide actionable profit-taking/assignment signals.
- **Source:** `plans/us-53-54-55/research.md`

### Failure & missing-data behavior (contract table)
- **Type:** service-behavior contract
- **Shape:** Post-review hardening invariant — no single failure (provider outage, one malformed leg, one bad position) may prevent healthy positions' alerts (especially DTE rules) from being evaluated and persisted. Documented situations:
  - Single option symbol unavailable (`not_found`) → symbol absent (or `unavailable: true`); affected legs get `currentOptionMid = null`.
  - Whole market-data feed throws / outage → each feed wrapped in `fetchOrDegrade` (run concurrently via `Promise.all`); logs WARN (`alert_evaluation_stock_quotes_unavailable` / `..._option_snapshots_unavailable`) and degrades to empty; DTE rules still fire.
  - Leg data can't form a valid OCC symbol → `occSymbolForRow` catches, logs `alert_evaluation_occ_symbol_invalid`, returns `null`; leg gets `currentOptionMid = null` (PROFIT_TARGET skips) but its DTE rules still fire.
  - Option mid missing for a leg → PROFIT_TARGET skips with `missing_option_mark`; DEBUG log `alert_rule_skipped`.
  - Invalid stored premium/contracts → PROFIT_TARGET skips with `invalid_profit_target_input` (guard rejects non-positive premium / non-positive-integer contracts before compute can throw).
  - Underlying price missing for a CSP → STRIKE_PROXIMITY skips with `missing_underlying_price` (DEBUG log).
  - One position throws mid-compute → caught per-position (`alert_evaluation_failed` error log); persist phase still runs for the rest (unchanged US-50 behavior).
- **Source:** `plans/us-53-54-55/contracts/evaluate-alerts-market-data.md`, `plans/us-53-54-55/data-model.md`
- **Implementation:** `src/main/services/evaluate-alerts.ts`

## Acceptance Criteria
AC list (13 ACs across the three stories, each mapped to exactly one named e2e test in `src/main/services/evaluate-alerts.e2e.test.ts`; from `plans/us-53-54-55/plan.md` Area 4 and `tasks.md` Area 4):

US-53 — MANAGEMENT_WINDOW:
- Alert fires when a position enters the 21-DTE window — MSFT `CC_OPEN` @ 21 DTE → medium `MANAGEMENT_WINDOW`, summary `"21 DTE remaining — review for roll or close"`.
- Alert remains open while the position stays between 6 and 21 DTE — existing open alert re-eval @ 12 DTE keeps it open and updates summary to `"12 DTE remaining — review for roll or close"` (same `triggered_at`).
- Alert does not fire outside the threshold — 22 DTE → no `MANAGEMENT_WINDOW`.
- Expiration-imminent takes precedence inside 5 DTE — 4 DTE → no `MANAGEMENT_WINDOW`; only `EXPIRATION_IMMINENT`.

US-54 — PROFIT_TARGET:
- Alert fires when unrealized profit reaches the default target — AAPL `CSP_OPEN` entry `3.50`, mid `1.70`, target 50% → low `PROFIT_TARGET`, summary `"51.4% of max profit captured — consider closing"`.
- Alert fires for an open covered call that reaches the target — MSFT `CC_OPEN` entry `4.00`, mid `1.90` → low `PROFIT_TARGET`, summary `"52.5% of max profit captured — consider closing"`.
- Alert does not fire before the target is reached — AAPL entry `3.50`, mid `2.40` → no `PROFIT_TARGET`.
- Position without a live option mark is skipped — no mid available → no `PROFIT_TARGET` row + DEBUG skip log for missing mark data.
- Holding-shares positions do not receive profit-target alerts — TSLA `HOLDING_SHARES`, no open option leg → no `PROFIT_TARGET` (dropped by `activeLegSubquery` inner join).

US-55 — STRIKE_PROXIMITY:
- Alert fires when price is within 1% above the CSP strike — AAPL `CSP_OPEN` $180 strike, price `181.20` → medium `STRIKE_PROXIMITY`, summary `"Stock is 0.7% above the $180.00 put strike"`.
- Alert fires when price is within 1% below the CSP strike — price `179.10` → medium, summary `"Stock is 0.5% below the $180.00 put strike — now in the money"`.
- Alert does not fire when the stock is safely away from the strike — price `183.80` → no `STRIKE_PROXIMITY`.
- Covered-call positions do not use this CSP strike-proximity rule — MSFT `CC_OPEN` $420 strike, price `419.60` → no `STRIKE_PROXIMITY`.

## Decisions & Tradeoffs

### Rule specifications (from data-model.md §4)
- **MANAGEMENT_WINDOW (US-53, already implemented):** urgency `medium`; `missingData`: `dte === null → MISSING_DTE`; `test`: `dte > EXPIRATION_IMMINENT_MAX_DTE (5) && dte <= managementWindowDte (default 21)`; summary `"{dte} DTE remaining — review for roll or close"`; mutually exclusive with EXPIRATION_IMMINENT via DTE windows (inside 5 DTE only EXPIRATION_IMMINENT fires).
- **PROFIT_TARGET (US-54, new):** urgency `low`; `missingData`: any of `entryPremiumPerContract`, `contracts`, `currentOptionMid` absent → `MISSING_OPTION_MARK`; else non-positive premium or non-positive-integer contracts → `INVALID_PROFIT_TARGET_INPUT` (post-review hardening); `test`: `capturedPct >= resolveProfitTarget(profitTargetPercentOverride)` where `capturedPct = parseFloat(computeUnrealizedPnl({ entryPremium, currentMid, contracts }).pnlPercent)`; summary `"{capturedPct, 1dp}% of max profit captured — consider closing"`; applies to any open short option leg (both `CSP_OPEN` and `CC_OPEN`; `HOLDING_SHARES` never reaches the engine). Worked examples: 3.50/1.70/1 → 51.4286% fires at target 50; 4.00/1.90/1 → 52.5% fires; 3.50/2.40/1 → 31.4286% no fire; 3.50/(none)/1 → skip `missing_option_mark`.
- **STRIKE_PROXIMITY (US-55, new):** urgency `medium`; let `proximityPct = |price − strike| / strike × 100`; `missingData`: `phase === 'CSP_OPEN' && currentUnderlyingPrice === null → MISSING_UNDERLYING_PRICE`, otherwise `null`; `test`: `phase === 'CSP_OPEN' && strike != null && price != null && proximityPct <= 1`; summary above `"Stock is {proximityPct, 1dp}% above the ${strike, 2dp} put strike"`, below `"...below... — now in the money"`; direction by `price >= strike` → "above" else "below"; applies to `CSP_OPEN` only (`CC_OPEN` → no match, no skip). Worked examples (strike $180.00): 181.20 → 0.6667→0.7 fires "above"; 179.10 → 0.5 fires "below … in the money"; 183.80 → 2.1111 no fire; CC_OPEN @ 420 price 419.60 → not applicable.
- **Source:** `plans/us-53-54-55/data-model.md`

- `MISSING_UNDERLYING_PRICE = 'missing_underlying_price'` — STRIKE_PROXIMITY (new, CSP only)

### Post-review hardening — failure isolation (data-model.md §7, refactor-phase-results.md)
A high-effort code review of the async `evaluateAlerts` refactor found three ways a single failure could abort the whole run and suppress unrelated (market-data-independent) DTE alerts. Guiding invariant: one bad leg, one bad position, or a provider outage must never prevent healthy positions' alerts — especially the high-urgency `EXPIRATION_IMMINENT` / `MANAGEMENT_WINDOW` DTE rules — from being evaluated and persisted. Three fixes, all TDD-first (Red → Green):
1. **Market-data outage no longer aborts the run** (`src/main/services/evaluate-alerts.ts`): fetches were awaited outside the per-row `try/catch`; a provider rejection rejected the whole run. Fix — a `fetchOrDegrade` helper wraps each fetch, logs a WARN (`alert_evaluation_stock_quotes_unavailable` / `alert_evaluation_option_snapshots_unavailable`) and returns empty on failure; both feeds run concurrently under `Promise.all` (also resolves sequential-fetch latency). Test: "still evaluates DTE rules when the market-data provider fails".
2. **One malformed leg no longer aborts the batch** (`src/main/services/evaluate-alerts.ts`): `rows.map(occSymbolForRow)` ran `buildOccSymbol` unguarded; a leg with empty ticker, strike ≤ 0, or bad expiration threw and aborted the batch. Fix — `occSymbolForRow` now takes a logger, catches the throw, logs `alert_evaluation_occ_symbol_invalid`, and returns `null`; symbols are built once into an `occByPositionId` map and threaded into `toEvaluationInput` (removing the prior double-computation). Test: "does not abort the batch when one leg yields an invalid OCC symbol".
3. **Invalid premium no longer drops a position's alerts** (`src/main/core/alerts.ts`): `PROFIT_TARGET.missingData` only null-checked; a non-null but invalid premium (`0`/negative) or `contracts` (`0`) made `computeUnrealizedPnl` throw and cost the position all its alerts. Fix — new `hasComputableProfit` guard + `INVALID_PROFIT_TARGET_INPUT` skip reason; non-positive premium or non-positive-integer contracts skip cleanly. Tests: "PROFIT_TARGET skips (never throws) on a non-positive entry premium, preserving other rules" and "… when contracts is not a positive integer".
- **Source:** `plans/us-53-54-55/data-model.md`, `plans/us-53-54-55/refactor-phase-results.md`

### Deliberately not changed (post-review)
- **`profit_target_percent = 0`:** the review flagged that a `0` override fires PROFIT_TARGET at breakeven, but `resolveProfitTarget(0) === 0` is locked in by an explicit test (`profit-target.test.ts` → "treats 0 as a real override"), so honoring `0` is intentional. Left as-is pending a product decision on whether `0` should mean "unset → 50% default".
- **`capturedPercent` / `proximityPercent` recomputed in both `test` and `summary`:** inherent to the alert-rule-registry pattern (uniform `summary: (input) => string`); the Decimal work is cheap and only runs for matched rules, so the pattern was kept over threading a precomputed value.
- **Source:** `plans/us-53-54-55/data-model.md`, `plans/us-53-54-55/refactor-phase-results.md`

### Compute-phase pre-fetch (data-model.md §6)
- OCC symbols built once per row into `occByPositionId: Map<positionId, string | null>` before fetching, reused for both the symbol set and `toEvaluationInput`.
- Distinct tickers → `fetchStockQuotes(provider, tickers)` → `Record<ticker, IpcStockQuote>`.
- Distinct OCC symbols of evaluable option legs → `fetchOptionSnapshots(provider, symbols)` → `{ snapshots, unavailable }`; a missing symbol yields `currentOptionMid = null` → PROFIT_TARGET skips `missing_option_mark`.
- Both fetches run concurrently via `Promise.all`, each degrading to empty on failure, so a provider outage never aborts the run.
- **Source:** `plans/us-53-54-55/data-model.md`

### Test-utility consolidation (refactor)
Layer 4 refactor extracted `seedAaplCsp(db)` for the shared AAPL $180 CSP fixture and created a shared `src/main/services/evaluate-alerts-test-utils.ts` module (named to match the `alpaca-stream-test-utils.ts` convention so the `*.test.ts` glob doesn't collect it), resolving ~150 lines of cross-file fixture duplication between `evaluate-alerts.test.ts` and `evaluate-alerts.e2e.test.ts`. Final results: `pnpm test` → 1482 passed across 137 files (after hardening); lint/typecheck/format clean.
- **Source:** `plans/us-53-54-55/refactor-phase-results.md`
