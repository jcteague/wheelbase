# Extract: us-17

## Summary

US-17 ensures comprehensive test coverage for roll rejection when a position is not in a rollable phase. The lifecycle engine, service layer, and renderer action bar already implement the correct behavior (from US-12/US-14). This story adds parameterized tests at the core, service, and component layers covering all 10 phases, plus AC-driven e2e tests. No new production code is expected — this is a test-coverage story.

## Architecture Decisions

### ADR: No new implementation required for phase validation

- **Decision:** No new production code; rely on existing `rollCsp` and `rollCc` phase guards in `src/main/core/lifecycle.ts`, plus existing IPC handlers, service layer, and renderer action bar.
- **Why:** US-12 (CSP roll) and US-14 (CC roll) already implemented the validation logic. US-17 is about ensuring comprehensive test coverage for all non-rollable phases at every layer (core, service, IPC, renderer component, e2e).
- **Alternatives considered:** N/A — no design decisions needed.
- **Source:** `plans/us-17/research.md`

### ADR: Parameterized/table-driven tests for all non-rollable phases

- **Decision:** Add parameterized/table-driven tests (`it.each`) for all non-rollable phases at the lifecycle engine and service layers. Expand renderer component tests and add AC-driven e2e tests.
- **Why:** Current tests only verify 1–2 non-rollable phases per function. US-17 ACs require all 9 (CSP) / 9 (CC) non-rollable phases to be explicitly tested.
- **Alternatives considered:** Continue with single-phase tests (rejected — insufficient coverage of AC).
- **Source:** `plans/us-17/research.md`

### ADR: Existing phase-to-action mapping retained

- **Decision:** Keep the existing `PositionDetailActions` component's phase-to-action mapping as-is.
- **Why:** Component already renders "Roll CSP →" only for `CSP_OPEN`, "Roll CC →" only for `CC_OPEN`, hides roll buttons for all other phases. Verified by reading `src/renderer/src/components/PositionDetailActions.tsx`.
- **Alternatives considered:** N/A — existing UI behaviour already matches AC.
- **Source:** `plans/us-17/research.md`

## Contracts

### ValidationError shape (lifecycle engine → IPC)

- **Type:** Error shape (returned through IPC services as `{ ok: false, errors: [...] }`)
- **Shape:**

```typescript
{
  field: '__phase__',
  code: 'invalid_phase',
  message: string  // varies by function
}
```

  Error messages:
  - `rollCsp` → `"Position is not in CSP_OPEN phase"`
  - `rollCc` → `"No open covered call on this position"`
- **Source:** `plans/us-17/data-model.md`
- **Implementation:** `src/main/core/lifecycle.ts` (existing `rollCsp` / `rollCc` guards; service wrappers `src/main/services/roll-csp-position.ts`, `src/main/services/roll-cc-position.ts`)

### `positions:roll-csp` IPC handler (existing)

- **Type:** IPC handler
- **Shape:** Not respecified in US-17; relies on US-12 contract. Service returns `{ ok: true, ...result } | { ok: false, errors: [{ field: '__phase__', code: 'invalid_phase', message: 'Position is not in CSP_OPEN phase' }] }` when phase invalid.
- **Source:** `plans/us-17/plan.md` (Prerequisites)
- **Implementation:** existing handler wired in `src/main/ipc/` (US-12)

### `positions:roll-cc` IPC handler (existing)

- **Type:** IPC handler
- **Shape:** Not respecified in US-17; relies on US-14 contract. Service returns `{ ok: false, errors: [{ field: '__phase__', code: 'invalid_phase', message: 'No open covered call on this position' }] }` when phase invalid.
- **Source:** `plans/us-17/plan.md` (Prerequisites)
- **Implementation:** existing handler wired in `src/main/ipc/` (US-14)

## Acceptance Criteria

- CSP roll rejected for non-CSP_OPEN phases (all 9 phases): `HOLDING_SHARES`, `CC_OPEN`, `CSP_EXPIRED`, `CSP_CLOSED_PROFIT`, `CSP_CLOSED_LOSS`, `CC_EXPIRED`, `CC_CLOSED_PROFIT`, `CC_CLOSED_LOSS`, `WHEEL_COMPLETE`
- CC roll rejected for non-CC_OPEN phases (all 9 phases): `CSP_OPEN`, `HOLDING_SHARES`, `CSP_EXPIRED`, `CSP_CLOSED_PROFIT`, `CSP_CLOSED_LOSS`, `CC_EXPIRED`, `CC_CLOSED_PROFIT`, `CC_CLOSED_LOSS`, `WHEEL_COMPLETE`
- Roll button hidden on position card for non-rollable phases
- Roll CSP button visible and enabled for `CSP_OPEN`
- Roll CC button visible and enabled for `CC_OPEN`
- Roll rejected after CSP has already been closed (phase remains `CSP_CLOSED_PROFIT` / `CSP_EXPIRED`; no Roll CSP button shown)

## Decisions & Tradeoffs

- **Test-coverage-only story:** No new production code expected; Green phases verify existing code already passes. If any test fails, the validation logic is fixed in place (`src/main/core/lifecycle.ts` or the relevant service).
- **Service-layer test coverage:** Plan suggests minimum representative phases (`HOLDING_SHARES`, `CC_OPEN`, `WHEEL_COMPLETE`) but ideally all 9 — explicit tradeoff between repetitive DB setup and exhaustive coverage.
- **Renderer tests prefer `it.each` over many `it()` blocks:** Refactor step considers removing now-redundant individual visibility tests once parameterized coverage is in place.
- **E2E tests assert button absence as the user-visible proof of rejection** rather than always exercising IPC rejection directly (UI prevention is the AC).
- **Optional helper extraction:** Consider `createPositionInPhase(db, phase)` for service tests and `reachPhase(page, targetPhase)` for e2e if setup is repetitive.
