# Extract: us-96

## Summary

US-96 folds the Screener page into the Watchlist page. One route at `/watchlist` shows
every watchlist entry as a card carrying its live price and an age-assessed IV rank, split
into **Meets criteria** (every saved condition passes on a usable IV reading _and_ the
screener ranked a qualifying put) and **Stocks of interest** (everything else, each
carrying the single most decisive reason it is held back). Selecting a card opens a sticky
detail panel with the thesis, each condition's verdict, the earnings date, and — for a
name that meets criteria — the matching put's metrics with a **Review trade** handoff into
the pre-filled new-wheel form.

The join is computed in two halves. A new read-only `watchlist:snapshot` IPC returns one
row per entry — quote, freshness-assessed IV reading, earnings display, and a per-gate
verdict from a new pure engine — all stamped at a single request clock. A pure renderer
helper then merges those rows with `screener:results`.

US-98's rule governs throughout: **an unusable reading is an unknown, and an unknown never
decides anything.** A stale, expired, or earnings-predating reading cannot satisfy an
`IVR ≥ N` condition, so a stale-rich reading can never promote a name into Meets criteria.

`ScreenerPage`, `ScreenerResultsTable`, and `ScreenerExcludedSection` are deleted, along
with the `/screener` route and nav item.

**Implementation status: complete.** All 32 tasks across 10 areas are done. 33 of 33
acceptance criteria are covered by passing, verbatim-named tests in
`e2e/watchlist-bench.spec.ts`. Two review cycles returned no outstanding blocking findings.

## Architecture Decisions

### ADR: `expired` becomes an assessed reading, not an absence

- **Decision:** `IvRankState` gains a fifth member, `expired`, carried on an ordinary
  assessed reading with its value, `observedAt` and `ageTradingDays`. `IvRankAssessment`
  drops from three variants to two (`assessed | unreadable`); `unreadable` — a corrupt
  value, or a calendar that cannot reach the observation — is now the only path that
  yields no reading.
- **Why:** Ageing out is not a failure to read. Collapsing it to `null` made a reading
  that had simply gone past use indistinguishable from a ticker never collected at all.
  The trader now sees `exp` rather than the same `n/a`, and the operator still hears about
  genuine degradation through the `unreadable` warn log.
- **Consequence:** `isUsableState` is unchanged, so `services/screener.ts::usableIvRanks`
  still passes only `fresh`/`aging` readings to the engine. US-98's ACs "the IV-rank floor
  is not applied to an expired reading" and "a stale IV rank never blocks a candidate from
  ranking" continue to hold.
- **Supersedes:** the us-98 ADR "Assessment returns a three-state result, not `null`".
- **Source:** `plans/us-96/data-model.md`, `src/main/core/ivr-freshness.ts`

### ADR: The verdict engine is pure so alerting can reuse it

- **Decision:** `src/main/core/watchlist-signal.ts` takes an entry's conditions plus the
  day's snapshot values and returns per-gate verdicts — price, IV, earnings — each
  `met | unmet | unknown | none` with a display label. No DB, broker, IPC, or logger
  imports; only `decimal.js`, `date-fns`, and sibling core modules.
- **Why:** A future alert must answer the same question without a page being open. Purity
  is what makes that possible, and it is a hard CLAUDE.md rule for `src/main/core/`.
- **Source:** `plans/us-96/data-model.md`, `src/main/core/watchlist-signal.ts`

### ADR: An unknown never decides anything, including by falling through

- **Decision:** Every gate treats absent or unusable evidence as `unknown`, never as a
  quiet pass. `earningsDisplay` explicitly guards `Number.isNaN(daysUntil)` alongside the
  past-date check.
- **Why:** Found in review. Every comparison against `NaN` is false, so an unparseable
  earnings date (or an invalid clock, which `etDateOf` answers with `''`) skipped both the
  past-date check and the window check and fell through to `met` — inverting the module's
  governing rule and able to promote a stock into Meets criteria on an unpriced print.
- **Source:** `src/main/core/watchlist-signal.ts`

### ADR: `isUsableState` is the gate, with labels layered on top

- **Decision:** The IV gate asks `isUsableState` rather than enumerating the unusable
  states, and a small partial record supplies the more specific copy for `stale` and
  `predates_earnings`, defaulting to `IV unavailable`.
- **Why:** Implementing `data-model.md`'s table literally would have left `isUsableState`
  as dead code, since the explicit branches already exhausted the unusable states. This
  way there is one authority on usability, and a future `IvRankState` degrades to
  `IV unavailable` rather than silently satisfying an `IVR ≥ N`.
- **Source:** `src/main/core/watchlist-signal.ts` (implementation; refines
  `plans/us-96/data-model.md` § Gate rules)

### ADR: Reason precedence is earnings, then price, then IV

- **Decision:** `reasonsFor` returns the labels of blocking gates in that fixed order. A
  waiting card shows them joined with `·`.
- **Why:** An imminent print keeps a trader out whatever the price, and a price miss
  outranks an IV reading.
- **Source:** `plans/us-96/data-model.md`

### ADR: The join is a pure renderer helper, mirroring two engine rules

- **Decision:** `src/renderer/src/lib/bench.ts` merges the snapshot rows with
  `screener:results` into `{ meets, waiting }`. It reimplements `isBlocking`,
  `reasonsFor` and `allGatesPass` over the IPC mirror of `EntryVerdict`, because the
  renderer cannot import from `src/main/`. The duplication is documented on both sides.
- **Why:** `src/main/` is a genuine process boundary with no shared leaf between them.
- **Known tradeoff:** Correctness rests on three details staying identical across the
  boundary — the blocking-verdict set, the gate ordering, and the null-label filter. Both
  code reviews flagged that putting `reasons` and `gatesPass` on the wire would delete the
  mirror outright and be strictly less code. Not applied; recorded as an advisory.
- **Source:** `plans/us-96/data-model.md`, `src/renderer/src/lib/bench.ts`

### ADR: Meets criteria requires both halves and a screen that actually ran

- **Decision:** A stock meets criteria only when every gate is `met` or `none`, **and**
  `results.status === 'ok'`, **and** a ranked candidate exists for its ticker. `meets` is
  ordered by the candidate's index in `results.ranked` — the renderer never re-sorts.
- **Why:** A ranked put alone must never promote a stock past an unmet or unknown
  condition, and the engine owns rank order.
- **Source:** `plans/us-96/data-model.md`

### ADR: An outage does not blame the criteria

- **Decision:** The empty Meets section shows "No candidates match your criteria — loosen
  your delta band" only when a screen actually ran. After a provider outage it says it is
  waiting for market data instead.
- **Why:** Found while re-pointing the inherited e2e suites. Nothing had been screened, so
  the card invented a verdict and sent the trader to fix criteria that had rejected
  nothing — the exact confusion US-66's "an outage is distinguished from no results" AC
  exists to prevent.
- **Source:** `src/renderer/src/components/BenchGrid.tsx`

### ADR: Copy must not assert a cause it has not checked

- **Decision:** Two pieces of copy were rewritten to stop naming a specific cause. The
  held-back paragraph now reads "held back by the entry conditions above" rather than
  naming the IV reading, and the no-reading note reads "There is no usable IV rank"
  rather than "No IV rank has been collected".
- **Why:** Both were reachable while false. The held-back line rendered for any waiting
  stock with a candidate — including one blocked on price with a perfectly usable reading
  — and the note claimed the collector never ran when the row may in fact exist but be
  unreadable, a distinction the engine takes care to preserve and the IPC payload then
  collapses.
- **Source:** `src/renderer/src/components/BenchDetail.tsx`, `ReadingNote.tsx`

### ADR: A `none` gate is impossible by construction, not guarded at runtime

- **Decision:** `GateBadge` takes a `DecidedGate` — a gate whose verdict excludes `none` —
  and `BenchDetail.gateEntries` filters on both the null condition and the `none` verdict
  before rendering.
- **Why:** The runtime guard was unreachable dead code, since its only caller already
  filtered. Encoding the invariant in the type removes the branch rather than testing it.
- **Source:** `src/renderer/src/components/GateBadge.tsx`

### ADR: The horizon wrapper lives in its own module so the mock boundary survives

- **Decision:** `readEarningsOrEmpty` and the `LOOKAHEAD_BUFFER_DAYS` constant move to a
  new `services/earnings-horizon.ts` rather than into `earnings-dates.ts` beside
  `getEarningsCalendar`.
- **Why:** Both callers' tests mock `getEarningsCalendar` through
  `vi.mock('./earnings-dates')`. Placing the wrapper in that same module made its call
  intra-module, bypassing the mock and breaking nine screener tests. A separate module
  keeps the call crossing the mocked boundary. The extraction itself is justified by the
  constant's fourteen-line rationale, which had been duplicated in two files where anyone
  tuning it would fix one and miss the other.
- **Source:** `src/main/services/earnings-horizon.ts`

### ADR: The degraded-read log label stays the caller's

- **Decision:** `readEarningsOrEmpty` takes the log label as a parameter, so the screener
  and the bench snapshot keep their own distinct event names.
- **Why:** Which surface degraded is the first thing an operator needs, and renaming an
  existing log event during a refactor is a behaviour change.
- **Source:** `src/main/services/earnings-horizon.ts`

### ADR: Per-condition parts, not parsed chip strings

- **Decision:** `watchlistConditionTags.ts` exports `conditionTagParts(entry)`, one
  nullable field per condition, and `bench-conditions.ts` reads those fields.
- **Why:** `benchConditions` had been routing each condition to its gate by prefix-matching
  the rendered chip text, so renaming a chip's wording would have silently dropped or
  misrouted a trader's entry condition with no test failing at the point of the change.
- **Consequence:** `buildConditionTags` lost its last caller and was removed.
- **Source:** `src/renderer/src/lib/watchlistConditionTags.ts`, `bench-conditions.ts`

### ADR: The thesis occupies the card slot the mockup reserved for a company name

- **Decision:** A waiting card renders `entry.notes` in its third-row left slot.
- **Why:** The outage AC requires every card to keep showing its thesis, and the app has
  no company-name source for the slot the mockup drew there. During an outage every card
  is a waiting card (an outage always yields `ranked: []`), so "waiting cards only"
  satisfies "every card".
- **Source:** `src/renderer/src/components/BenchCard.tsx`

## Contracts

### `watchlist:snapshot` (new)

- **Type:** IPC handler, read-only, no request payload
- **Shape:** `{ ok: true, rows: IpcWatchlistSnapshotRow[], asOf: string }` where a row is
  `{ entry, quote: IpcSnapshotQuote | null, ivRank: IpcIvRank | null, earnings:
IpcEarningsDisplay, verdict: IpcEntryVerdict }`. Rows come back in watchlist order
  (`added_at DESC`); `asOf` is the ISO request clock every verdict was computed at. No
  chain pull — `screener:results` stays a separate, heavier query.
- **Degradation guarantees (each asserted at the service boundary):** the provider factory
  throwing yields `quote: null` on every row with price gates `unknown` and `ok: true`; one
  ticker's quote rejecting nulls only that row; an earnings-read rejection yields
  `{ kind: 'unknown' }` everywhere with `lastEarnings` undefined; an IVR-read failure
  yields `ivRank: null` everywhere with IV gates `unknown`; an empty watchlist returns
  `{ rows: [], asOf }` without constructing the provider at all.
- **Errors:** only the standard `__root__` / `internal_error` envelope. Every expected
  failure is modelled inside the success payload.
- **Source:** `plans/us-96/contracts/watchlist-snapshot.md`
- **Implementation:** `src/main/ipc/watchlist.ts`, `src/main/services/watchlist-snapshot.ts`

### `screener:results` (amended response)

- **Type:** IPC handler, unchanged shape
- **Shape:** `IpcIvRank.state` widens to include `'expired'`. An expired reading now
  arrives as a reading rather than collapsing to `null`. Engine behaviour is unchanged.
- **Source:** `plans/us-96/contracts/screener-results.md`

### `watchlist:list` (retired)

- **Type:** IPC handler, removed
- **Notes:** Its only renderer consumer was the pre-rewrite watchlist table. The handler,
  its preload binding, `IpcWatchlistListResult`, and the renderer's `listWatchlist` adapter
  are all deleted. A main-process caller wanting the entries calls
  `services/watchlist.ts::listWatchlist(db)` directly, as the snapshot service does.
- **Source:** implementation

### `fetchIsolatedStockQuotes` (new shared service)

- **Type:** service function
- **Shape:** `fetchIsolatedStockQuotes(provider, tickers): Promise<Map<string,
IpcStockQuote>>`. Concurrency 4, per-ticker `try/catch` with an
  `underlying_quote_fetch_failed` warn; a failing ticker is simply absent from the map. An
  empty ticker list never touches the provider.
- **Notes:** Extracted from `screener.ts::readUnderlyingPrices`, which keeps its
  price-ceiling early return. The warn label moved from `screener_quote_fetch_failed`.
- **Source:** `plans/us-96/plan.md` (Area 4)
- **Implementation:** `src/main/services/underlying-quotes.ts`

### `readEarningsOrEmpty` (new shared service)

- **Type:** service function
- **Shape:** `readEarningsOrEmpty(db, tickers, criteria, currentDate, logLabel)`. Converts
  the caller's DTE window into a horizon date (`dteMax + 45`) and degrades a read failure
  to an empty map under the caller's own log label.
- **Source:** implementation — the plan scheduled the extraction for the refactor phase
- **Implementation:** `src/main/services/earnings-horizon.ts`

### Renderer bench shapes

- **Type:** pure renderer types
- **Shape:** `BenchStock = { ticker, row, candidate, rank, reason, verdictCopy }` and
  `Bench = { meets, waiting }`. `buildBench(snapshot, results)` partitions;
  `defaultSelection(bench)` prefers `meets[0]`, then `waiting[0]`, then null.
- **Reason precedence:** `provider_unavailable` → `Data unavailable · not evaluated`; else
  the gate reasons joined; else the screener's verbatim exclusion; else `Not screened yet`.
- **Source:** `plans/us-96/data-model.md`
- **Implementation:** `src/renderer/src/lib/bench.ts`

## Schema Changes

**None.** Every entity read is an existing persisted record; every computed shape is
transient. No migration.

## Decisions & Tradeoffs

- **Fixture numbers come from the engine.** XLF's 1.3% period yield, its 0.53 score below
  KO's 0.71, and AMD's `spread 14% exceeds 10%` are pinned through `scoreCandidate` in
  `src/main/core/screener.test.ts` before any e2e assertion uses them (US-66 ADR).
- **Three plan fixture errors were corrected.** AMD could not satisfy the earnings-caution
  and the spread-reason ACs on one bench, because `earnings_in_window` sits above `spread`
  in the filter registry; ORCL's requested one-session-old reading with a print the day
  after was unsatisfiable on four weekdays in five; and ORCL's earnings were specified on a
  fixture type with no field for them.
- **An empty watchlist renders no bench sections**, only the guidance and the add form —
  otherwise the meets-section empty card would libel a watchlist that is simply new.
- **The old `screener-count` line has no successor.** Per-section counts replace it.
- **The stale caption is now a bare `quoted HH:mm:ss`**; the "after-hours option marks are
  unreliable" sentence is retired.
- **Two mutation hooks invalidate both `['watchlist']` and `['watchlist','snapshot']`.**
  The second is redundant under TanStack's prefix matching, kept deliberately so the
  bench dependency is visible at the call site.
- **`asOf` and `SnapshotQuote.timestamp` have no consumer yet.** The contract specifies
  `asOf`; the header's stale caption uses the screener's `quoteTimestamp`.

## Open Questions

- **The mirrored derivation in `bench.ts`** — both reviews recommend putting `reasons` and
  `gatesPass` on the IPC payload to delete it. Not applied.
- **The quote fetch is per ticker**, one request each at concurrency 4, and now runs on
  every page load and window focus rather than only under a price ceiling. Batching with a
  per-ticker fallback would preserve isolation at a fraction of the request volume.
- **Five parallel per-tier tables** span four files; one exported tier descriptor would
  collapse them to a single edit site.
- **`EarningsBadge` and `BenchDetail` disagree on toning an unknown earnings date** — the
  badge treats it neutrally by design, the detail line cautions it per this story's AC.
- **`--wb-sky-dim`**, used by `AlertBox`'s `info` variant, is not a defined token
  (pre-existing).
- **US-98's AC5 and AC13 are closed by this story.** Both assert on a bench verdict that
  had no surface before it; they were added to `e2e/ivr-staleness.spec.ts` under their own
  names once it shipped, taking that suite to 13 of 13.
