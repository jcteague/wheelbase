# Extract: us-32

## Summary

Adds a live `Price` column to the Positions list (between `Phase` and `Strike`) showing real-time underlying price and signed daily change, plus a session-aware market status pill in the page header. The renderer's TanStack Query cache is seeded once via REST (`market-data:stock-quotes`) and continuously updated by WebSocket ticks bridged through `market-data:stock-quote` push events from the existing US-31 `MarketDataProvider`. Done state: every active position row shows price + change during market hours, the pill reflects `LIVE`/`EXT`/`CLOSED`/`DELAYED`, missing tickers render `—` with a tooltip, and a stale-data banner appears when no quotes have arrived for >5 min. (Source: `plans/us-32/plan.md`)

## Architecture Decisions

### ADR: Transport — Stream-First with REST Seed

- **Decision:** Use `provider.stream('stockQuotes', tickers)` for live updates. On every ticker-list change, also fire a one-shot `provider.getStockQuotes(tickers)` to seed the renderer with current price + `change` (which depends on `prev_daily_bar.c` and isn't carried by stream events). After the seed, all updates flow through the WebSocket Observable.
- **Why:** The stock stream pushes only `bp`/`ap`/`bs`/`as`/`t` per quote frame — no previous-close field. Without a REST seed, the price column would be empty until the first tick arrives (which during low-liquidity hours could be a long wait), and `change` could never be computed at all. Combining streaming for live updates with a single REST call for the per-day baseline gives us both real-time movement and accurate daily change with one initial round-trip.

> Reconciliation note (2026-06-27): Market data is now provided by `MassiveMarketDataProvider`, not Alpaca. The REST seed reads Massive's stock snapshot endpoint (`/v2/snapshot/locale/us/markets/stocks/tickers/{ticker}`), and `prevClose` comes from that snapshot's previous-day bar — not Alpaca `getStocksSnapshots`/`prev_daily_bar`.
- **Alternatives considered:**
  - Pure REST polling (story's original suggestion) — works but wastes the streaming infrastructure US-31 already built; updates lag by up to 60 s.
  - Pure streaming with no seed — rows blank until first tick, no `change` value possible from stream alone.
  - Stream-only and compute change client-side from a remembered "first price seen today" — drifts when the app is opened mid-session (the first observed tick isn't the open price).
- **Source:** `plans/us-32/research.md`

### ADR: Provider Lifecycle in the Main Process

- **Decision:** Instantiate the provider once at app startup in `src/main/index.ts`. Call `provider.connect()` on first subscription request from the renderer, not at startup, so the WebSocket only opens when needed. Hold the provider instance and current Observable subscription at module level inside `src/main/ipc/market-data.ts`. On `app.before-quit`, call `provider.disconnect()`.
- **Why:** Connecting on startup wastes a WebSocket while the user is on, e.g., the New Wheel page with no active positions. Connecting on first subscribe matches user intent: the renderer has decided it wants live data. Single `connect()` per app session matches the provider's contract — multiple connect calls would be ambiguous.

> Reconciliation note (2026-06-27): The provider is no longer built via `createMarketDataProvider(...)`. `src/main/index.ts` calls `marketDataFactory.configure({ loadMassiveApiKey })` then `marketDataFactory.create()` (which returns a `MassiveMarketDataProvider`), and cleanup calls `marketDataFactory.disconnect()`.
- **Alternatives considered:**
  - `connect()` at startup unconditionally — opens a socket the user may never use.
  - `connect()` per ticker change — recreates the WebSocket on every position add/remove; the provider's design uses one persistent socket and multiplexes subscriptions over it.
- **Source:** `plans/us-32/research.md`

### ADR: Renderer-Initiated Subscription Updates

- **Decision:** Renderer calls `window.api.setStockQuoteTickers(tickers)` whenever the active-ticker list changes (positions added, closed, or initial mount). Main-process handler tears down the previous Observable subscription, optionally connects the provider, subscribes to `provider.stream('stockQuotes', tickers)`, and pushes each `StreamEvent<StockQuote>` via `webContents.send('market-data:stock-quote', ...)`. Returns `{ ok: true, subscribedTickers: tickers }`.
- **Why:** The renderer is the source of truth for "which tickers do we care about?" — it derives that list from `usePositions()`. Keeping subscription mutation as an explicit IPC invoke (request/response) makes intent clear, lets the renderer await success before assuming the stream is live, and gives a clean error channel for `auth_failed` / `network_error`.
- **Alternatives considered:**
  - Main process queries the DB itself — couples market-data to DB; harder to test; doesn't compose with future "watch this ticker even though no position exists" UX.
  - Renderer subscribes per-ticker — multiplies IPC traffic and forces server-side bookkeeping of N subscriptions.
- **Source:** `plans/us-32/research.md`

### ADR: Push Event Channels (main → renderer)

- **Decision:** Two push event channels (one-way, fire-and-forget from main): `market-data:stock-quote` per stream tick, and `market-data:stream-error` for WebSocket failures. The initial snapshot is delivered via the request/response `market-data:stock-quotes` call (consumed by TanStack Query's `queryFn`), not via a push event.
- **Why:** Snapshot vs delta is a meaningful distinction: snapshot replaces the renderer's whole map; delta merges one ticker. Sending both as the same channel would force the renderer to disambiguate by shape, which is fragile.
- **Alternatives considered:** One unified `market-data:stock-quote-event` with a discriminated `kind: 'snapshot' | 'tick'` union — works but adds a level of indirection in every receiver; two channels are simpler.
- **Source:** `plans/us-32/research.md`, `plans/us-32/contracts/market-data-events.md`

### ADR: Daily Change Calculation Split (Adapter vs Renderer)

- **Decision:** Compute `change` and `changePercent` inside the adapter on the REST snapshot path (using `latest_quote` mid + `prev_daily_bar.c`). On stream ticks, the adapter cannot compute change (no prev_close in the frame), so it emits `change: null, changePercent: null` on stream events. Add a `prevClose` field to `IpcStockQuote`; on a snapshot, `prevClose` is set; on a stream tick, `prevClose` is `null` and the renderer carries it forward from the cached snapshot value. The renderer computes `change` and `changePercent` itself per render from `(price, prevClose)`.
- **Why:** Stream frames are intentionally minimal. Forcing the adapter to round-trip a REST call on every tick to refresh `change` would defeat the purpose of streaming. Best to compute prev_close once per ticker (during seed) and keep applying it client-side.
- **Alternatives considered:**
  - Stream events that carry `prevClose` on every tick — Alpaca's frame doesn't include it; we'd have to inject it server-side from cache, which adds bookkeeping.
  - Compute change in main process and emit as part of the stream event — same problem (main has to remember prev_close per ticker).
  - Skip `change` entirely on stream events — change number would freeze on the seed value while price ticks; worse UX.
- **Source:** `plans/us-32/research.md`

### ADR: Market Status — REST + TanStack Query polling

- **Decision:** Keep market status as a request/response IPC channel called by `useMarketStatus()` with `refetchInterval: 60_000`. The provider has no streaming option for clock/session.
- **Why:** Market status changes ~6 times per day at predictable boundaries (4 AM, 9:30 AM, 4 PM, 8 PM ET, plus weekends/holidays). A 60 s poll catches transitions within a minute.

> Reconciliation note (2026-06-27): There is no `market-data:market-status` IPC channel. Market status is served by the broker handler `broker:market-status` (`src/main/ipc/broker.ts`); `useMarketStatus()` polls it via `window.api.broker.marketStatus()`.
- **Alternatives considered:**
  - Compute session client-side from `Date.now()` + a hardcoded ET schedule — fragile (holidays, half-days).
  - Skip market status polling entirely — without it, the indicator dot is stuck.
- **Source:** `plans/us-32/research.md`

### ADR: Stale Data Detection (>5 min)

- **Decision:** Track freshness through TanStack Query's `dataUpdatedAt`, which is bumped automatically by both `queryFn` resolution and `setQueryData` calls (stream ticks). Render the `StaleDataBanner` and override the market-status pill to `DELAYED` when `Date.now() - dataUpdatedAt > 300_000`, or when `streamError != null` (immediately, without waiting for the threshold).
- **Why:** With streaming, the natural staleness signal is "no events arrived recently" rather than "the last poll was X seconds ago." `dataUpdatedAt` captures both REST seeds and stream ticks in one freshness clock.
- **Alternatives considered:**
  - Listen for the provider's `StreamError` → relay to renderer and trigger the banner directly. Better signal but requires plumbing the error channel; a timestamp-based check covers both "explicit error" and "silent stall" with one mechanism.
  - Single global `lastUpdateAt` (any ticker) — masks the case where one ticker stops updating while others still tick.
- **Source:** `plans/us-32/research.md`, `plans/us-32/data-model.md`

### ADR: Renderer State — Single TanStack Query Cache + Stream Bridge

- **Decision:** Use TanStack Query as the single cache for live stock quotes. The hook `useStockQuotes(tickers)` defines a query with `queryKey: ['market-data', 'stock-quotes', sortedTickers]` and `queryFn` that calls the IPC REST endpoint `market-data:stock-quotes`. In a side effect it calls `window.api.setStockQuoteTickers(tickers)`, then subscribes to `onStockQuote` / `onStreamError` and merges each tick into the cached data via `queryClient.setQueryData(queryKey, prev => mergeTick(prev, event))`. `staleTime: Infinity` so stream ticks are the only live signal; `refetchOnWindowFocus: true` to refresh `prevClose`.
- **Why:** Keeps one cache and one freshness clock — `dataUpdatedAt` covers both REST seeds and stream ticks. Cache-level deduping means multiple components on the same ticker list share data. `setQueryData` is TanStack Query's intended escape hatch for push-based mutations.
- **Alternatives considered:**
  - Custom `useSyncExternalStore` store separate from TanStack Query — duplicates state machinery, requires bespoke tests for caching/stale logic.
  - Mix: TanStack Query for REST, `useSyncExternalStore` for stream updates merged in a custom hook — two stores fight each other; React 19 may render with a stale view in the brief gap before the merged hook re-syncs.
- **Source:** `plans/us-32/research.md`

### ADR: Two TanStack Query-Backed Hooks

- **Decision:** Two hooks in `src/renderer/src/hooks/`: `useStockQuotes(tickers)` (REST seed + stream bridge, `staleTime: Infinity`) and `useMarketStatus()` (poll with `refetchInterval: 60_000`, `staleTime: 30_000`).
- **Why:** Two concerns, two hooks. Both live inside the TanStack Query mental model so consumers learn one pattern.
- **Alternatives considered:** One combined hook — couples ticker-driven and time-driven concerns; harder to test.
- **Source:** `plans/us-32/research.md`

### ADR: IPC Error Mapping — Two Pathways

- **Decision:** Catch `MarketDataError` inside each IPC handler and return `{ ok: false, errors: [{ field: '__root__', code, message }] }`. For stream subscription errors, the provider's Observable emits a `StreamError` — the main process logs and forwards via a separate `market-data:stream-error` event so the renderer can surface a banner.
- **Why:** Two error pathways (request/response error from the snapshot/setTickers calls, async stream error from broken socket) need two delivery mechanisms. The main process is the seam that owns the conversion.
- **Source:** `plans/us-32/research.md`

### ADR: Component Decomposition

- **Decision:** Three new presentational components plus a row mod: `MarketStatusPill` (pill with colored dot + label, four states: `LIVE` green pulse, `EXT` amber, `CLOSED` gray, `DELAYED` amber, no pulse), `PriceCell` (table cell with price + signed change, or dash + tooltip), `StaleDataBanner` (amber banner above the table when most-recent update is >5 min ago). Modify `PositionRow` and `PositionsListPage` to add the `Price` column header and pass quote data into rows.
- **Why:** Mirrors the mockup's component structure. Each unit is testable in isolation.
- **Source:** `plans/us-32/research.md`

### ADR: Type Sharing Across the Bridge

- **Decision:** Add IPC-flat types to `src/preload/index.d.ts` (`IpcStockQuote`, `IpcMarketStatus`, `IpcSetStockQuoteTickersPayload`, `IpcSetStockQuoteTickersResult`, `IpcGetMarketStatusResult`, `IpcStockQuoteEvent`, `IpcStreamErrorEvent`). Renderer consumes these and re-exports renderer-side aliases from `src/renderer/src/api/market-data.ts` so renderer code never imports from `src/main/`.
- **Why:** Matches the existing `IpcPositionListItem` pattern. The provider's `StockQuote` type can be shared structurally, but the IPC types add `prevClose: string | null` (a US-32-only concept needed by the renderer change calculation).
- **Source:** `plans/us-32/research.md`

## Acceptance Criteria

```gherkin
Background:
  Given the trader has 3 active positions:
    | ticker | phase          | strike |
    | AAPL   | CSP_OPEN       | 180.00 |
    | MSFT   | CC_OPEN        | 420.00 |
    | TSLA   | HOLDING_SHARES | —      |
  And the MarketDataProvider is configured and returning data
```

- **Position rows show live underlying price during market hours** — Given the market is open (regular session) and AAPL is trading at $182.45, MSFT at $418.30, TSLA at $248.10, when the trader views the position list, then each row displays the current stock price in a "Price" column, the AAPL row shows "$182.45", and a green "LIVE" dot indicator appears next to the price.
- **Price updates on polling interval without full page reload** — Given AAPL was showing $182.45, when the next 60-second poll completes and AAPL is now $183.10, then the AAPL row updates to show "$183.10" and no loading spinner or page flash occurs.
- **Price shows daily change amount and direction** — Given AAPL opened at $181.00 and is now trading at $182.45, when the trader views the position list, then the AAPL row shows "+$1.45" in green text next to the price, and when a stock is down (MSFT at $418.30, opened at $420.00) then the MSFT row shows "-$1.70" in red text.
- **Market closed — show last closing price with indicator** — Given the market is closed (weekend or after 8:00 PM ET) and AAPL last closed at $182.00, when the trader views the position list, then the AAPL row shows "$182.00" and a gray "CLOSED" indicator appears instead of the green dot.
- **Extended hours — show pre/post market price** — Given the market is in extended hours (pre-market or after-hours) and AAPL closed at $182.00 but is trading at $183.50 in after-hours, when the trader views the position list, then the AAPL row shows "$183.50" and an amber "EXT" indicator appears.
- **Price data unavailable — show dash with tooltip** — Given the MarketDataProvider returns no quote for TSLA (API error or timeout), when the trader views the position list, then the TSLA price column shows "—", a tooltip or subtle message indicates "Price unavailable", and all other position data (strike, DTE, premium) still displays normally.
- **Stale data warning when last update exceeds 5 minutes** — Given the last successful price poll was more than 5 minutes ago, when the trader views the position list, then a subtle banner appears: "Prices may be delayed — last updated 6m ago" and the market status dot changes to amber.

(Source: `docs/epics/06-stories/US-32-live-underlying-price.md` via `plans/us-32/plan.md`)

## Decisions & Tradeoffs

- **`prevClose: null` on stream ticks, populated on REST snapshot.** IPC type `IpcStockQuote.prevClose` is `string | null` — set on seed, null on tick. Renderer merges by carrying forward the cached `prevClose` (`prevClose: event.quote.prevClose ?? prev?.[event.ticker]?.prevClose ?? null`). (Source: `plans/us-32/data-model.md`, `plans/us-32/contracts/market-data-events.md`)
- **`change` and `changePercent` omitted from `IpcStockQuote`.** The renderer computes them client-side from `(price, prevClose)`. Avoids two divergent values when prevClose drifts and keeps the math in one place. (Source: `plans/us-32/data-model.md`)
- **Stream `mapQuoteToStockQuote` sets `prevClose: ''`** — the IPC layer translates this to `null` when forwarding to the renderer. (Source: `plans/us-32/plan.md`)
- **`MarketStatusDisplay` derivation table (precedence order):** `streamError != null` → `DELAYED`; `Date.now() - dataUpdatedAt > 300_000` → `DELAYED`; `session === 'regular'` → `LIVE`; `session === 'pre' | 'post'` → `EXT`; `session === 'closed'` (or session unknown) → `CLOSED`. Stale check takes precedence so a stuck stream always surfaces visually. (Source: `plans/us-32/data-model.md`)
- **Stale threshold constant** `STALE_THRESHOLD_MS = 5 * 60 * 1000` (300_000 ms). (Source: `plans/us-32/data-model.md`)
- **Pill colors and animation** — green `#3fb950` (LIVE), amber `#e6a817` (EXT/DELAYED), gray `#6e7681` (CLOSED). Dot is 6×6 round span with `boxShadow` + `animation: wb-pulse 1.8s ease-in-out infinite` only when `state === 'LIVE'`. `@keyframes wb-pulse` added to `src/renderer/src/index.css`. (Source: `plans/us-32/plan.md`)
- **Banner styling** — amber background `#e6a81712`, amber border `#e6a81730`, amber text `#e6a817`, mono font, copy `⚠ Prices may be delayed — last updated {minutesAgo}m ago`. (Source: `plans/us-32/plan.md`)
