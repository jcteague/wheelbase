# Extract: us-65

## Summary

US-65 turns US-64's raw put chains into a ranked, explainable candidate list. A new pure
engine `src/main/core/screener.ts` disqualifies strikes against seven ordered hard
filters — each carrying a machine-readable code and a rendered reason — scores the
survivors on premium yield, and picks one representative strike per ticker ranked by
**yield-per-delta** (annualized return-if-flat ÷ |delta|). A thin
`src/main/services/screener.ts` orchestrates the chain pull, a new `ivr_snapshot` read
path, and an optional underlying-quote fetch, isolating every boundary; a new
`screener:results` IPC channel plus preload exposure delivers the whole payload to the
renderer. Exclusions travel alongside survivors so US-66 can show *why excluded*
separately from *why ranked #3*. Nothing is persisted and no migration was added — US-65
only reads the existing `ivr_snapshot` and `watchlist` tables. No renderer work: US-66
consumes the channel. A post-implementation code-review hardening pass
(`code-review-fixes-results.md`) fixed ten verified findings — most notably the
one-row-per-non-ranking-ticker guarantee, per-ticker quote-fetch isolation, pre-engine
strike validation, and the `provider_unavailable` state for an unconfigured provider.

## Architecture Decisions

### ADR: Hard filters as an ordered pure-predicate registry, first failure wins

- **Decision:** Model the hard filters as an ordered `FILTERS` array of
  `{ code, applies, test, reason }` pure objects in `src/main/core/screener.ts`,
  evaluated by a single `findIndex` that stops at the **first** failing filter and
  attaches that filter's `code` + rendered `reason` to the candidate. Order is
  `price_ceiling → earnings_in_window → dte_window → delta_unavailable → delta_band →
  open_interest → spread`.
- **Why:** It is the established shape for rule evaluation in this codebase
  (`core/alerts.ts` `RULES`, the `alert-rule-registry` ADR), it keeps every exclusion
  message next to the predicate that produces it, and new filters (the IV-rank floor in
  US-67) append without touching the loop. First-failure-wins gives each candidate
  exactly one reason, which is what US-66 renders.
- **Alternatives considered:** an if/return chain (rejected — the registry ADR bans it);
  collecting **all** failing reasons per candidate (rejected — US-66 shows one reason per
  row and a candidate failing four gates is not four times as interesting).
- **Source:** `plans/us-65/research.md`

### ADR: Ticker-level filters run first so the representative exclusion reason is the right one

- **Decision:** Order the registry so ticker-wide gates (price ceiling, earnings) run
  before structural selection (DTE, delta) and structural selection before per-strike
  liquidity (OI, spread). Sort a ticker's exclusions by **filter index descending**
  (latest stage reached first), tie-broken by chain order, so `excluded[0]` is the
  candidate that got furthest through the funnel and becomes the ticker's representative
  reason downstream.
- **Why:** US-66's excluded section shows **one row per ticker**. With this order the
  representative reason matches the mockup exactly: TSLA (in-band strikes failing the
  spread gate) reads the spread reason rather than `delta 0.42 outside 0.20–0.30`
  from some far-OTM strike; AMD, whose whole chain misses the band, reads the delta
  reason; F reads the OI reason. Putting delta after liquidity would invert all three.
- **Alternatives considered:** returning an unsorted list and letting the renderer pick
  (rejected — the renderer would show a meaningless first-in-chain reason, and the choice
  belongs to the engine, which knows the funnel); computing a separate "closest miss"
  score (rejected — the filter index already encodes it for free).
- **Source:** `plans/us-65/research.md`

### ADR: No non-ranking ticker ever vanishes from the results

- **Decision:** The `ScreenerResults` contract — every watchlist ticker appears in
  `ranked` or `excluded` — is enforced at two layers. The chain pull classifies a chain
  whose quotes are all untradeable as `no_options_listed` (an `ok` chain always carries
  ≥ 1 tradeable strike), and the service's `representativeExclusion` falls back to a
  `data_unavailable` row for a screened ticker with no survivor and no exclusions (every
  strike dropped as malformed).
- **Why:** Before the review-fix pass, an all-untradeable ticker (illiquid names near the
  close, halted underlyings) produced `{ best: null, excluded: [] }` and silently
  disappeared from both lists — the only failure mode without an explained row.
- **Source:** `plans/us-65/code-review-fixes-results.md`

### ADR: Validate strikes before the pure engine — a catch is a backstop, not a filter

- **Decision:** The service screens each chain through the pure guard
  `isWellFormedStrike` (`src/main/core/candidate-chain.ts` — bid/ask/mark/strike parse to
  finite Decimals; delta null or finite) before calling `screenTicker`. A malformed
  strike drops only itself, logged `warn` (`screener_malformed_strike_dropped`). The
  per-ticker try/catch remains as a last-resort backstop only. `isTradeableStrike`
  likewise returns false on malformed input rather than throwing.
- **Why:** The `alert-evaluation-failure-isolation` ADR forbids relying on a downstream
  catch that drops an item's other results: previously one bad quote string threw inside
  the engine's Decimal math and the ticker-level catch discarded the whole ticker as
  `data_unavailable`, costing the trader its valid candidates.
- **Source:** `plans/us-65/code-review-fixes-results.md`

### ADR: Delta is absolutized at the engine boundary

- **Decision:** The engine compares and scores on `|delta|`, and the `ScoredCandidate` it
  emits carries the **absolute** 4dp delta. The adapter keeps returning the raw signed
  value.
- **Why:** Puts carry a negative delta from Massive, but every trader-facing artifact —
  the criteria band `0.20–0.30`, the exclusion message `delta 0.42 outside 0.20–0.30`,
  the mockup's `Δ 0.28` column, and yield-per-delta itself — is stated in absolute terms.
  A `-0.42` compared against a `0.20–0.30` band would silently exclude the entire chain,
  and a negative divisor would rank candidates upside-down.
- **Alternatives considered:** absolutizing in the adapter (rejected — it would corrupt
  the signed value the cockpit Greeks panel displays); requiring criteria to be signed
  (rejected — nonsense for a trader, and calls would then need the opposite sign).
- **Source:** `plans/us-65/research.md`

### ADR: Round once, at the output boundary

- **Decision:** Compute `periodYield`, `annualizedYield`, and `yieldPerDelta` from a
  single unrounded `Decimal` chain and round each to 4dp only when writing the output
  field. Rank on the emitted 4dp `yieldPerDelta` string, tie-broken by ticker ascending
  (and, within a ticker, by lower strike).
- **Why:** Rounding intermediates compounds — AAPL's score is `0.5285` computed once
  versus `0.5286` computed from a pre-rounded `0.1480` annualized. Ranking on the same
  rounded value the trader sees means the displayed order can never contradict the
  displayed numbers, and the alphabetical tie-break keeps runs deterministic.
- **Alternatives considered:** ranking on full precision (rejected — two rows showing
  `0.53` could then sort in an order the trader cannot explain); rounding to 2dp
  (rejected — 2dp collides too often across a real watchlist).
- **Source:** `plans/us-65/research.md`

### ADR: A hard filter never excludes on a missing input — except a missing delta

- **Decision:** Each filter declares an `applies` guard; when its input is `null` (no
  earnings date, no underlying price, ceiling disabled, no open interest) the filter does
  not fire and the candidate passes it. The single exception is a **missing delta**, which
  excludes with code `delta_unavailable` because the rank is undefined without it.
- **Why:** Mirrors the alert engine's `missingData` guards, and prevents an unowned
  upstream (the earnings calendar, US-70) or a degraded quote fetch from silently emptying
  the screener. A missing delta is different in kind: the candidate cannot be ranked at
  all, so keeping it would put an unscoreable row in a ranked table.
- **Alternatives considered:** excluding on unknown earnings (rejected — US-70's AC
  requires a *caution*, not an exclusion, and US-65 has no earnings source yet, so every
  candidate would vanish); excluding on unknown price when the ceiling is enabled
  (rejected — a degraded quote fetch would empty the results; the service logs a warn
  instead).
- **Source:** `plans/us-65/research.md`

### ADR: The earnings gate is bounded to the holding window, and 'flag' mode really flags

- **Decision:** `earnings_in_window` fires only for a print **on or after the trader's
  current calendar day and on or before expiry** (`earningsWithinHolding`, anchored on
  `startOfDay(currentDate)`; `FilterInput` carries `currentDate`). In `'exclude'` mode
  the strike is excluded with reason `earnings <date> falls on or before expiry`; in
  `'flag'` mode the strike ranks normally and the survivor carries
  `ScoredCandidate.earningsFlagged: true` for US-66 to render as a warning.
- **Why:** Without the lower bound, a feed reporting the *most recent* (past) earnings
  date would permanently exclude every strike — precisely the post-earnings entry the
  wheel trader wants. And `'flag'` was previously declared in `ScreeningCriteria` with no
  implementation, so a trader selecting it would silently get no earnings handling at all.
  Both remain latent in production until US-70 supplies earnings dates.
- **Source:** `plans/us-65/code-review-fixes-results.md`

### ADR: The spread gate needs both thresholds breached

- **Decision:** Exclude for spread only when `spreadAbsolute > maxSpreadAbsolute` **and**
  `spreadPercent > maxSpreadPercent`. Defaults `10%` / `$0.10`. The rendered reason quotes
  the percent (`spread 22.23% exceeds 10%`) per the AC.
- **Why:** AC "Narrow absolute spread on a cheap option is not excluded" — a `0.08 / 0.15`
  quote is 58% of mark but only 7¢ wide, which is a real, fillable market. A percent-only
  gate would delete every low-priced underlying from the screener.
- **Alternatives considered:** percent-only with a lower bound on mark (rejected — an
  extra magic price threshold that says the same thing less directly).
- **Source:** `plans/us-65/research.md`

### ADR: New `ivr_snapshot` read module, not a widened collector

- **Decision:** Add `src/main/services/ivr-snapshots.ts` exporting
  `getLatestIvrByUnderlying(db, underlyings)` — one prepared
  `ORDER BY observed_at DESC LIMIT 1` per upper-cased underlying, misses skipped. It
  returns the engine's `IvRank` shape (`{ value, observedAt }`) directly — the
  structurally-identical `IvrSnapshot` type and its field-renaming layer were deleted in
  the review-fix pass. `services/ivr-collector.ts` stays write-only.
- **Why:** The collector is a scheduled-job module (throttling, market-status guard, clock
  injection); a synchronous read path for the screener shares none of that. Watchlists are
  small (tens of tickers) and the `(underlying, observed_at DESC)` index makes each lookup
  a single index seek, so the loop is simpler and faster to read than a row-value `IN`
  subquery. One domain concept (an IVR reading plus its scrape time) gets one type.
- **Alternatives considered:** one `GROUP BY`/window-function query (rejected — more SQL
  for no measurable gain at this cardinality); exporting from `ivr-collector.ts` (rejected
  — mixes read and write responsibilities on a job module).
- **Source:** `plans/us-65/research.md`, `plans/us-65/code-review-fixes-results.md`

### ADR: A provider outage — or a never-configured provider — short-circuits the screen

- **Decision:** `screenWatchlistCandidates` takes a **thunk**
  (`getProvider: () => MarketDataProvider`) and resolves it inside the service; a
  construction throw (no `MASSIVE_API_KEY` / `FAKE_MARKET_DATA`) returns
  `{ status: 'provider_unavailable', ranked: [], excluded: [], quoteTimestamp: null }`,
  the same state returned when `pullWatchlistChains` reports an outage — in both cases
  without joining IVR or fetching quotes. Per-ticker `no_options_listed` and
  `data_unavailable` are folded into the same `excluded` list the engine's exclusions use,
  with codes of the same name.
- **Why:** US-66's AC requires "market data unavailable" to be visually distinct from "no
  candidates match your criteria" — and a user who has not yet entered an API key is in
  exactly that state, not in an "unexpected error" state. Resolving the provider inside
  the service keeps the IPC handler thin while turning the factory's throw into the
  modelled status instead of the generic `internal_error` envelope.
- **Alternatives considered:** scoring whatever partial data arrived during an outage
  (rejected — by US-64's definition an outage means no ticker answered); catching the
  factory error in the handler (rejected — branching in handler files is banned).
- **Source:** `plans/us-65/research.md`, `plans/us-65/code-review-fixes-results.md`

### ADR: IV rank travels with its observation time

- **Decision:** The engine carries `IvRank = { value: string; observedAt: string }` rather
  than a bare number, and `ScoredCandidate.ivRank` is `IvRank | null`. Deciding what counts
  as too stale is left to the display surface.
- **Why:** IV can re-rate hard overnight — an earnings print alone can move rank by tens of
  points — so a bare number gives a caller no way to judge whether it is still worth acting
  on. `observedAt` is when *we* scraped the value, so it is an upper bound on freshness
  rather than a guarantee.
- **Source:** `plans/us-65/green-phase-results.md`, `src/main/core/screener.ts` (the plan
  originally specified a bare `Map<string, string>`; the shipped code is authoritative)

### ADR: AC coverage is a headless service-level integration test, not Playwright

- **Decision:** US-65's acceptance criteria are proven by
  `src/main/services/screener.integration.test.ts` — the real `screenWatchlistCandidates`
  (real chain pull, real IVR read, real engine) against an in-memory SQLite DB with
  migrations applied and a scripted `MarketDataProvider`. One `it()` per AC bullet, named
  to mirror the Gherkin. Only the provider and the logger are faked.
- **Why:** US-65 has no renderer surface — the ranked table is US-66 — so Playwright
  `_electron` has nothing to drive. Same rationale as US-64's Area 4.
- **Source:** `plans/us-65/quickstart.md`, `plans/us-65/refactor-phase-results.md`

## Contracts

### `screener:results`

- **Type:** IPC handler
- **Shape:**

```typescript
// request — no payload, and therefore no Zod request schema
invoke('screener:results')

// response (success)
{
  ok: true
  status: 'ok' | 'provider_unavailable'
  ranked: ScoredCandidate[]     // rank order (yieldPerDelta desc); [] = nothing survived
  excluded: ScreenerExclusion[] // one row per non-ranking ticker, watchlist order
  quoteTimestamp: string | null // newest ranked strike's ISO quote time; null when ranked is empty
}

type IvRank = {
  value: string // as stored, 1dp
  observedAt: string // ISO timestamp of the scrape that produced it
}

type ScoredCandidate = {
  ticker: string
  contractId: string
  strike: string // 4dp
  expiration: string // 'YYYY-MM-DD'
  dte: number
  bid: string // 2dp
  ask: string // 2dp
  mark: string // 2dp
  spreadAbsolute: string // 2dp
  spreadPercent: string // 2dp
  delta: string // 4dp, absolute
  openInterest: number | null
  volume: number | null
  ivRank: IvRank | null // null → US-66 renders "n/a"
  capitalSecured: string // 2dp
  periodYield: string // 4dp fraction
  annualizedYield: string // 4dp fraction
  yieldPerDelta: string // 4dp — the rank score
  earningsFlagged: boolean // 'flag' mode only: earnings land inside the holding window
  timestamp: string // ISO
}

type ScreenerExclusion = {
  ticker: string
  code:
    | 'price_ceiling'
    | 'earnings_in_window'
    | 'dte_window'
    | 'delta_unavailable'
    | 'delta_band'
    | 'open_interest'
    | 'spread'
    | 'no_options_listed'
    | 'data_unavailable'
  reason: string // e.g. 'spread 22.23% exceeds 10%', 'no puts quoted in the 30–45 DTE window'
}
```

  `status: 'provider_unavailable'` always comes with `ranked: []`, `excluded: []`, and
  `quoteTimestamp: null` — the market-data-unavailable state US-66 renders distinctly from
  an empty-but-successful screen (`status: 'ok'`, `ranked: []`). It covers both a
  mid-flight outage and a never-configured provider (no API key yet). Every watchlist
  ticker in an `ok` screen appears in exactly one of `ranked` / `excluded`.
- **Error codes:** only the standard envelope row — `__root__` / `internal_error` /
  `An unexpected error occurred`. There is no request payload to validate, and every
  expected failure mode is modelled **inside** the success payload rather than thrown:
  a provider outage or unconfigured provider becomes `status: 'provider_unavailable'`,
  per-ticker provider failures become `data_unavailable` exclusions, and an IVR or
  quote-fetch failure degrades to missing soft data. `handleIpcCall` catches anything
  genuinely unexpected (e.g. a SQLite failure) into that row.
- **Source:** `plans/us-65/contracts/screener-results.md`,
  `plans/us-65/code-review-fixes-results.md`
- **Implementation:** `src/main/ipc/screener.ts` (`registerScreenerIpc({ db, getProvider })`),
  `src/preload/index.ts`, `src/preload/index.d.ts`

### `screenWatchlistCandidates` (service entry point)

- **Type:** in-process service function
- **Shape:**

```typescript
type ScreenerExclusionCode = ExclusionCode | 'no_options_listed' | 'data_unavailable'

type ScreenerResults = {
  status: 'ok' | 'provider_unavailable'
  ranked: ScoredCandidate[]
  excluded: ScreenerExclusion[]
  quoteTimestamp: string | null
}

function screenWatchlistCandidates(
  getProvider: () => MarketDataProvider, // thunk — resolved inside; a throw ⇒ provider_unavailable
  db: Database.Database,
  opts?: { criteria?: ScreeningCriteria; currentDate?: Date }
): Promise<ScreenerResults>
```

  Orchestration: resolve the provider (throw ⇒ `provider_unavailable`) → pull chains
  (DTE window derived from the criteria) → short-circuit on outage → IVR join in
  `try/catch` → per-ticker quote fetch **only** when `maxUnderlyingPrice !== null`
  (each ticker isolated in its own `try/catch`, concurrency-capped at 4) →
  `earningsDate: null` (the US-70 seam) → drop malformed strikes via
  `isWellFormedStrike` (warn per strike) → per-ticker `screenTicker` in its **own**
  `try/catch` backstop → `rankCandidates` → newest `quoteTimestamp`.
- **Source:** `plans/us-65/data-model.md`, `plans/us-65/code-review-fixes-results.md`
- **Implementation:** `src/main/services/screener.ts`

### `screenTicker` / `rankCandidates` / `scoreCandidate` (pure engine)

- **Type:** pure core functions
- **Shape:**

```typescript
type ScreeningCriteria = {
  deltaMin: string // absolute delta, e.g. '0.20'
  deltaMax: string // absolute delta, e.g. '0.30'
  dteMin: number // calendar days, inclusive
  dteMax: number // calendar days, inclusive
  minOpenInterest: number // inclusive floor
  maxSpreadPercent: string // percent of mark, e.g. '10'
  maxSpreadAbsolute: string // dollars, e.g. '0.10'
  maxUnderlyingPrice: string | null // null = ceiling disabled
  earningsHandling: 'exclude' | 'flag'
}

const DEFAULT_SCREENING_CRITERIA: ScreeningCriteria = {
  deltaMin: '0.20',
  deltaMax: '0.30',
  dteMin: 30,
  dteMax: 45,
  minOpenInterest: 500,
  maxSpreadPercent: '10',
  maxSpreadAbsolute: '0.10',
  maxUnderlyingPrice: null,
  earningsHandling: 'exclude'
}

function screenTicker(
  input: TickerScreeningInput, // { ticker, strikes, ivRank, underlyingPrice, earningsDate }
  criteria: ScreeningCriteria,
  currentDate: Date
): TickerScreeningResult // { ticker, best: ScoredCandidate | null, excluded: ExcludedCandidate[] }

function rankCandidates(results: TickerScreeningResult[]): ScoredCandidate[]

function scoreCandidate(
  strike: CandidateStrike,
  ticker: string,
  dte: number,
  ivRank: IvRank | null,
  earningsFlagged = false
): ScoredCandidate

function evaluateFilters(
  input: FilterInput, // { strike, dte, underlyingPrice, earningsDate, currentDate }
  criteria: ScreeningCriteria
): { code: ExclusionCode; reason: string; index: number } | null
```

  Yield math: `spreadAbsolute = ask − bid` (2dp),
  `spreadPercent = (ask − bid) / mark × 100` (2dp), `capitalSecured = strike × 100` (2dp),
  `periodYield = mark / strike` (4dp), `annualizedYield = periodYield × 365 / dte` (4dp,
  calendar 365 — never 252), `yieldPerDelta = annualizedYield / |delta|` (4dp).
- **Source:** `plans/us-65/data-model.md`, `plans/us-65/code-review-fixes-results.md`
- **Implementation:** `src/main/core/screener.ts`

### `getLatestIvrByUnderlying` (IVR read path)

- **Type:** in-process service function (read-only)
- **Shape:**

```typescript
function getLatestIvrByUnderlying(
  db: Database.Database,
  underlyings: string[]
): Map<string, IvRank> // IvRank = { value: string; observedAt: string }, from core/screener
```

  Keyed by upper-cased ticker; underlyings with no snapshot are **absent** from the map —
  never `null` and never `'0'`, so callers surface "unknown" rather than a fabricated zero.
  An empty `underlyings` array returns an empty map without preparing a statement. The
  former `IvrSnapshot` type was deleted in the review-fix pass — the read path returns the
  engine's `IvRank` shape directly.
- **Source:** `plans/us-65/plan.md` (Area 4), `plans/us-65/code-review-fixes-results.md`
- **Implementation:** `src/main/services/ivr-snapshots.ts`

## Acceptance Criteria

- **Premium yield is computed on capital secured** — an AAPL 37-DTE put at the $180 strike
  with a $2.70 mark yields a period yield of 1.5% (2.70 / 180), an annualized
  return-if-flat of 14.8% (1.5% × 365 / 37), and capital secured of $18,000 per contract
  (180 × 100).
- **Rank is annualized yield per unit of delta** — candidate A at 0.30 delta yielding 30.0%
  annualized ranks *below* candidate B at 0.20 delta yielding 24.0% annualized, because B
  shows the higher yield-per-delta score (1.20 vs 1.00).
- **Exclude a strike outside the delta band** — a 0.42-delta strike against a 0.20–0.30
  band is excluded with reason `delta 0.42 outside 0.20–0.30`, and a high yield does not
  rescue it into the ranked results.
- **Exclude an illiquid strike** — open interest of 120 against a 500 minimum is excluded
  with reason `open interest 120 below 500`.
- **Exclude a wide-spread strike** — bid 2.40 / ask 3.00 on a 2.70 mark against a 10%
  maximum is excluded with reason `spread 22.23% exceeds 10%` (percent rendered at up to
  2dp, rounded up, since the review-fix pass).
- **Narrow absolute spread on a cheap option is not excluded** — bid 0.08 / ask 0.15 is not
  excluded for spread, because the $0.07 absolute spread is within tolerance.
- **Missing IV rank does not exclude a candidate** — with no IVR for a ticker, IV rank shows
  "n/a" and candidates are still ranked by yield-per-delta without an IVR contribution.
- **Best strike per ticker is selected** — given three AAPL strikes surviving the filters,
  the highest-scoring survivor represents AAPL in the results.

## Decisions & Tradeoffs

- **`mark` is copied, never recomputed.** `scoreCandidate` yields on the `mark` the strike
  supplies (US-64's `computeMid`), even when it disagrees with `(bid + ask) / 2`, so money
  rounding lives in exactly one place.
- **Exclusion reason strings are load-bearing.** US-66 renders them verbatim, so the
  formatters are fixed: 2dp deltas, **en dash** `–` (U+2013) in band strings, percents at
  up to 2dp **rounded up** with trailing zeros trimmed, `$`-prefixed 2dp money. The en
  dash is not cosmetic. Percents round *up* so an exclusion can never read as
  self-contradictory ("spread 10% exceeds 10%" is now "spread 10.05% exceeds 10%").
- **The `no_options_listed` reason names the window.** The chain query is
  expiration-bounded, so the reason reads
  `no puts quoted in the ${dteMin}–${dteMax} DTE window` — a monthly-only underlying
  frequently has zero expirations inside the default 30–45 window while plainly listing
  options.
- **DTE `0` and an unparseable expiration fail `dte_window`,** guarding a divide-by-zero in
  the annualized yield before the scorer is ever reached.
- **`openInterest: null` does not exclude; `openInterest: 0` does.** Absent liquidity data
  is unknown, not zero.
- **Six hard filters were specified, seven codes ship** — `delta_unavailable` is split out
  from `delta_band` so a missing delta reads as an unscoreable candidate rather than a
  band miss.
- **The IV-rank floor and the premium-yield floor are deliberately not implemented.** US-65
  classes IVR as a soft, rank-only input ("never a default hard exclude"); both optional
  floors are US-67's ACs.
- **Criteria are a parameter, not a settings read.** The service takes an optional
  `criteria` override defaulting to `DEFAULT_SCREENING_CRITERIA` — the seam US-67 fills —
  so US-65 never reaches into a settings store that may not exist yet.
- **Failure isolation throughout** (`alert-evaluation-failure-isolation` ADR): the IVR read
  degrades to an empty map plus a `warn`; the quote fetch is **per-ticker** — one failed
  quote skips only that ticker's ceiling (warn), never the watchlist's; malformed strikes
  are dropped individually by `isWellFormedStrike` before the engine; and the per-ticker
  `try/catch` around `screenTicker` remains as a backstop that drops a ticker to
  `data_unavailable` only on a genuinely unexpected throw.
- **Provider fan-outs are concurrency-capped at 4.** The shared `mapWithConcurrency`
  helper lives in `src/main/concurrency.ts` (extracted from `candidate-chains.ts`) and
  bounds the chain pull, the screener's quote fetch, and
  `MassiveMarketDataProvider.getStockQuotes` — an unbounded burst earns a 429 from a
  healthy provider.
- **Logging shape mirrors `candidate-chains.ts`:** `debug` for the request and per-ticker
  outcomes, exactly one `info` on completion with `{ status, rankedCount, excludedCount }`.
- **Layer 4's AC tests were green on arrival** — they add no production code — so each was
  falsified against deliberate engine mutations instead (365→360 annualization; en dash →
  hyphen, OI floor → `< 0`, spread filter disabled; spread `&&` → `||`). All eight fail
  under a mutation of exactly the behaviour they assert.
- **Shared test seeders extracted** — `seedWatchlist` (three identical copies) and `seedIvr`
  (two) moved into `src/main/test-utils.ts`. The four `Partial<OptionChainQuote>` builders
  were deliberately **not** merged: they share a type but not a concept (US-64's defaults
  are a representative quote whose exact values its tests assert; US-65's are tuned to clear
  every screening filter).
- **Known, deliberately-unfixed efficiency findings** from the review (documented in
  `code-review-fixes-results.md`): ticker-level filters re-evaluate per strike;
  `computeStrikeMetrics` runs twice per surviving strike; the IVR read is one query per
  underlying (by design); `yieldPerDelta` would render `'Infinity'` if a zero-delta strike
  ever survived (the delta filters currently prevent it).

## Open Questions

- **IVR staleness.** The screener uses the latest `ivr_snapshot` row regardless of age; the
  collector runs daily so this is fresh in practice. `IvRank.observedAt` now carries the
  scrape time so a display surface can judge it, but no cutoff is enforced — that decision
  belongs with the IVR surface, not the scorer.
- **Where criteria are persisted** is US-67's; US-65 only exports the defaults and the
  override seam.
- **Earnings dates are always `null`** until US-70 wires the calendar, so
  `earnings_in_window` and `earningsFlagged` cannot currently fire in production even
  though both modes (`exclude` and `flag`) are implemented and tested.
- Display (US-66), the criteria settings UI (US-67), multiplicative liquidity/IVR score
  factors, and PMCC criteria (Epic 09) remain out of scope and unbuilt.
