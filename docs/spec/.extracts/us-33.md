## Summary
Adds two new columns (`Opt Mid` and `P&L`) to the positions list and three new stats (`Current Mid`, `Unrealized P&L`, `% of Max Profit`) to the position-detail Open Leg section, plus a gold `TARGET` badge that fires when unrealized P&L reaches the position's profit target (default 50%, optionally overridden per position). A new IPC channel `market-data:option-snapshots` polls the existing `MarketDataProvider` (`getOptionSnapshots(symbols)` shipped in US-31) every 60 s for OCC symbols built from each active option leg. Done state: every active option leg shows live mid-price, signed P&L colored green/red, and the TARGET badge when threshold is crossed; HOLDING_SHARES rows show `—`; spread > 10% of mid shows an amber warning; missing snapshots show `—` without breaking the row. The story also landed (via `handoff/`) the "Triage Cockpit" position-detail redesign — a verdict-driven layout with delta gauge, distance thermometer, context strip, and collapsible drawers — built on top of the new P&L data. (Source: `plans/us-33/plan.md`)

## Architecture Decisions

### ADR: OCC option symbol built in a pure leaf module
- **Decision:** Build OCC symbols in the form `{TICKER}{YYMMDD}{P|C}{STRIKE_8}` (strike × 1000, zero-padded to 8) in a new pure module `src/main/core/option-symbol.ts`. Example: AAPL `2026-05-16` `$180.00` PUT → `AAPL260516P00180000`. Used by the renderer via direct import (allowed — `src/main/core/` is a leaf with no DB/Electron imports).
- **Why:** Matches the format already accepted by `provider.getOptionSnapshots()` and used in `alpaca-market-data.test.ts`. Industry standard. Pure derivation avoids storing a `contract_id` column on `legs` and keeps the rule in one location (no main/renderer drift).
- **Alternatives considered:**
  - Persist a `contract_id` on each `legs` row to skip recomputation — rejected for this story (no caching benefit at our scale).
  - Duplicate in `src/renderer/src/lib/` — rejected; symbol format is a domain rule, not a UI concern.
- **Source:** `plans/us-33/research.md`

### ADR: Profit-target storage — nullable column + hard-coded default constant
- **Decision:** Add nullable `profit_target_percent INTEGER` column to `positions` via migration `005_add_profit_target_percent.sql`. The "global default" is a hard-coded `DEFAULT_PROFIT_TARGET_PERCENT = 50` in a new `src/main/core/profit-target.ts`. No `app_settings` table is introduced. A pure helper `resolveProfitTarget(override: number | null): number` returns the override when non-null (including `0`), else the default.
- **Why:** No AC describes the _act_ of setting the override — only the result of having one. A constant satisfies every AC, and per-position override satisfies the "AAPL has a per-position profit target of 25%" scenario. Centralizing in a resolver means the future settings UI replaces the constant in one place.
- **Alternatives considered:**
  - `app_settings` key/value table — rejected; adds storage and IPC surface for a feature without a story.
  - Env var — rejected; no end-user control without a setting.
- **Source:** `plans/us-33/research.md`, `plans/us-33/data-model.md`

### ADR: Profit-target check runs in the renderer
- **Decision:** Compute `targetReached = pnlPercent >= resolveProfitTarget(positionOverride)` in the renderer after `computeUnrealizedPnl` returns. The IPC layer does not ship a `targetReached` boolean.
- **Why:** The renderer already has the entry premium and current mid (from the snapshot poll), so it can compute P&L without an extra IPC round-trip. Pushing this server-side would require IPC on every price update, defeating the point of polling on the renderer.
- **Source:** `plans/us-33/research.md`

### ADR: P&L math lives in `src/main/core/costbasis.ts`
- **Decision:** Add `computeUnrealizedPnl({ entryPremium, currentMid, contracts })` to `src/main/core/costbasis.ts`. Returns `{ pnl, pnlPercent, maxProfit }` — all strings, all `Decimal.toFixed(4)`. Reuses existing `costbasis.ts` helpers (`sharesFromContracts`, `round4` where applicable) and the `Decimal.ROUND_HALF_UP` convention.
- **Why:** Keeps the engine convention of decimal-string returns (`basisPerShare`, `totalPremiumCollected`, `finalPnl` all return strings). Matches the sign convention in the AC (positive when option decayed). Keeping `pnlPercent` on the 0–100 scale (not 0–1) matches the story's `50` and `25` thresholds directly.
- **Alternatives considered:** Returning numbers — rejected for consistency with rest of the engine.
- **Source:** `plans/us-33/research.md`, `plans/us-33/data-model.md`

### ADR: REST-only polling at 60 s, disabled when market closed
- **Decision:** `useOptionSnapshots(legs, { session })` uses TanStack Query with `refetchInterval: session === 'closed' ? false : 60_000`, `staleTime: 30_000`, `refetchOnWindowFocus: true`, `enabled: symbols.length > 0`. No streaming bridge.
- **Why:** Matches the story's "polls on the same interval as stock quotes" note and aligns with US-32 cadence. Alpaca's snapshot endpoint returns Greeks; the streaming option-quote feed does not. US-34 (Greeks display) is the next story; once it lands, option-quote streaming is more compelling. For now REST is simpler and sufficient at 60 s.
- **Alternatives considered:**
  - Stream option quotes via existing WebSocket bridge — rejected because the stream lacks Greeks.
  - Match US-32's `staleTime: Infinity` + stream merge — rejected; REST polling is simpler and ample at 60 s.
- **Source:** `plans/us-33/research.md`, `plans/us-33/plan.md`

### ADR: Renderer builds OCC symbols (no server symbol building)
- **Decision:** A new `useOptionSnapshots(legs: ActiveLegSummary[])` hook builds OCC symbols from active legs via `buildOccSymbol`, then calls `getOptionSnapshots(symbols)` via REST. Per-leg `try/catch` around `buildOccSymbol` skips legs with invalid inputs (e.g. `strike: 0`).
- **Why:** Mirrors `useStockQuotes(tickers)`. Symbol building is pure and the renderer already has every input it needs (ticker + strike + expiration + instrumentType, surfaced via `PositionListItem` extension).
- **Alternatives considered:** Send legs to IPC, build symbols server-side — rejected; the renderer already has the inputs.
- **Source:** `plans/us-33/research.md`, `plans/us-33/plan.md`

### ADR: Active-leg metadata flows through `positions:list`, not a second query

## Decisions & Tradeoffs

- **P&L formula** — `maxProfit = entryPremium × contracts × 100`; `pnl = (entryPremium − currentMid) × contracts × 100`; `pnlPercent = (pnl / maxProfit) × 100`. All returned as `Decimal.toFixed(4)` strings. Sign convention: positive when option decayed below entry premium. (Source: `plans/us-33/research.md`, `plans/us-33/data-model.md`)
- **Mid-price formula** — `mid = (bid + ask) / 2` (set by the provider in `OptionSnapshot.mid`; the renderer reads it directly — no client-side recomputation). (Source: `plans/us-33/data-model.md`)
- **Wide-spread predicate** — `mid > 0 && (ask − bid) / mid > 0.10`. `WIDE_SPREAD_THRESHOLD = 0.1`. When `mid === 0` the predicate returns `false` (the "no bid" indicator handles that case). (Source: `plans/us-33/research.md`, `plans/us-33/data-model.md`)
- **"No bid" predicate** — `Decimal(bid).isZero()`. Inputs `'0'`, `'0.00'`, `'0.0000'` all return `true`. (Source: `plans/us-33/research.md`, `plans/us-33/plan.md`)
