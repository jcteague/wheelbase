# Extract: us-13

## Summary

US-13 extends the US-12 roll form to support strike changes (roll down/up), adds a 5-way roll-type label, a roll-count badge with a 3+ warning, updated net-debit copy, and ensures the position card and detail page reflect the new strike after rolling. The lifecycle engine relaxes its US-12 rule that `newExpiration > currentExpiration` so a strike-only "Roll Down" / "Roll Up" at the same expiration becomes valid, while rejecting rolls where neither strike nor expiration changes and rejecting earlier expirations. Position queries (`list-positions.ts`, `get-position.ts`) are updated to include `ROLL_TO` in their active-leg filters so the most recent rolled leg drives display, and `getPosition` returns a new `rollCount` field. The IPC contract for `positions:roll-csp` is unchanged — only its validation behaviour and response payload (`rollCount` on `positions:get`) widen. (Source: `plans/us-13/plan.md` Summary)

**Note:** This plan dir contains only `plan.md`, `research.md`, `data-model.md`, `contracts/positions-roll-csp.md`, and `quickstart.md`. There is **no `tasks.md` and no refactor-phase-results.md** in `plans/us-13/`, so this extract reflects design intent only — not verified implementation state. `/update-spec us-13` should re-run once those artifacts land.

## Architecture Decisions

### ADR: Strike-change validation lives in the lifecycle engine

- **Decision:** Extend `RollCspInput` with `currentStrike: string` and `newStrike: string`, and move the "no change" / "earlier expiration" / "positive strike" checks into `rollCsp()` in `src/main/core/lifecycle.ts`.
- **Why:** `lifecycle.ts` owns all phase-transition and roll-validity rules per the architecture standards. Strike-change rules are part of the roll's domain validity, not a service concern.
- **Alternatives considered:** Validating only in the service layer — rejected because it would split roll-validity rules across layers.
- **Source:** `plans/us-13/research.md` ("Lifecycle Validation Change"), `plans/us-13/plan.md` §1

### ADR: Same-expiration strike-only rolls are allowed

- **Decision:** Replace the unconditional US-12 rule `newExpiration > currentExpiration` with a two-part rule: reject only when `newStrike === currentStrike AND newExpiration === currentExpiration` (code `no_change`) and reject when `newExpiration < currentExpiration` (code `must_not_be_earlier`). Same-expiration strike changes are valid.
- **Why:** US-13 introduces "Roll Down" and "Roll Up" labels that explicitly require same expiration with a different strike (per the 5-way table).
- **Alternatives considered:** Keep US-12's strict `>` and label same-expiration rolls as "Roll Down & Out" anyway — rejected as the label would be misleading.
- **Source:** `plans/us-13/research.md` ("Lifecycle Validation Change"), `plans/us-13/data-model.md` ("Validation Rules"), `plans/us-13/contracts/positions-roll-csp.md`

### ADR: 5-way roll-type label as a shared pure function

- **Decision:** Replace the 3-arg US-12 `getRollTypeLabel(currentStrike, newStrike)` with a 4-arg shared helper `getRollTypeLabel(currentStrike, newStrike, currentExpiration, newExpiration)` in a new file `src/renderer/src/lib/rollType.ts`. Five outcomes: `Roll Out`, `Roll Down & Out`, `Roll Up & Out`, `Roll Down`, `Roll Up`.
- **Why:** The 5 types are defined in the AC and the mockup already uses them. A shared module avoids duplicating the logic between `RollCspSheet.tsx` and the success state.
- **Alternatives considered:** Keep the 3-way and label same-expiration rolls as "Roll Down & Out" — rejected as misleading.
- **Source:** `plans/us-13/research.md` ("Roll Type Label Logic"), `plans/us-13/plan.md` §4, `plans/us-13/data-model.md` ("Roll Type Derivation")

### ADR: Roll count by counting ROLL_TO legs, exposed on `positions:get`

- **Decision:** Compute roll count as `COUNT(*) FROM legs WHERE position_id = ? AND leg_role = 'ROLL_TO'`. Add `rollCount: number` to `GetPositionResult` (i.e. extend the existing `positions:get` response). No new IPC channel.
- **Why:** Each roll creates exactly one `ROLL_TO` leg, so this count is the simplest source. Extending `positions:get` avoids round-trips since the detail page already fetches the position before opening the roll sheet.
- **Alternatives considered:** (1) Counting distinct `roll_chain_id` values — equivalent but more complex SQL for no benefit. (2) A dedicated `positions:roll-count` channel — unnecessary complexity.
- **Source:** `plans/us-13/research.md` ("Roll Count"), `plans/us-13/contracts/positions-roll-csp.md` ("Roll Count")

### ADR: Roll-count warning is soft / informational only

- **Decision:** Show a "Roll #N" badge always. At `rollCount >= 3` colour the badge red (`#f85149`) and add an amber `AlertBox` warning: "This position has been rolled multiple times — consider whether the capital is better deployed elsewhere." Does not block submission.
- **Why:** The story explicitly classifies this as informational, not a business rule.
- **Alternatives considered:** Blocking the roll at 3+ — rejected by the story's "Out of Scope" list ("Blocking rolls based on net debit or roll count (soft warnings only)").
- **Source:** `plans/us-13/plan.md` §5, `docs/epics/03-stories/US-13-roll-csp-down-and-out.md` ("Out of Scope")

### ADR: Active-leg queries must include `ROLL_TO`

- **Decision:** Update `src/main/services/list-positions.ts` to filter `leg_role IN ('CSP_OPEN', 'CC_OPEN', 'ROLL_TO')`, and update `src/main/services/get-position.ts` so the CSP_OPEN branch filters `leg_role IN ('CSP_OPEN', 'ROLL_TO')`.
- **Why:** Without including `ROLL_TO`, the position card and detail page would render the original CSP strike after a roll. The AC "the position card displays $175.00 as the active strike" requires picking the latest `ROLL_TO` leg.
- **Note on overlap with US-12:** US-12's refactor results already updated `get-position.ts` to include `ROLL_TO` for the active-leg query (`docs/spec/.extracts/us-12.md` — "Active-leg query must include ROLL_TO (post-review fix)"). The US-13 plan flags this and accepts that "if US-12 fixes this before merge, this area becomes a no-op for US-13"; `list-positions.ts` is still the residual gap. See Open Questions below.
- **Alternatives considered:** Updating the leg_role on rolled legs in place — rejected (would violate the linked-pair / append-only invariant).
- **Source:** `plans/us-13/research.md` ("Active Leg Query Gap (VERIFIED)"), `plans/us-13/plan.md` §3

### ADR: Client-side validation mirrors lifecycle engine

- **Decision:** The renderer `validate()` function in `RollCspSheet.tsx` enforces the same three rules as the engine: (1) `newExpiration < props.expiration` → expiration error, (2) both unchanged → root-level error ("Roll must change the expiration, strike, or both"), (3) same-expiration allowed when `newStrike !== props.strike`. Root error displayed in an `AlertBox` above the submit button.
- **Why:** The form should not let the trader submit a payload the engine will reject; the engine remains the authority and re-checks on the main side.
- **Alternatives considered:** Server-only validation — rejected on UX grounds (slower feedback, requires a round-trip to discover an obvious local error).
- **Source:** `plans/us-13/plan.md` §7

### ADR: Net-debit copy updated to call out cost-basis impact

- **Decision:** Change `NetCreditDebitPreview` debit warning text from US-12's "This roll costs more to close than the new premium provides" to "This roll produces a net debit, which increases your cost basis".
- **Why:** New wording is more informative — it tells the trader the consequence (cost basis goes up), not just the fact. Required verbatim by AC "Net debit preview with warning for expensive roll down".
- **Alternatives considered:** None documented.
- **Source:** `plans/us-13/research.md` ("Net Debit Warning Text"), `plans/us-13/plan.md` §5

### ADR: IPC payload schema unchanged

- **Decision:** `RollCspPayloadSchema` (`src/main/schemas.ts`) is not modified. `newStrike` was already declared as `z.number().positive().optional()` in US-12 and the service already defaults it to the current strike when omitted.
- **Why:** Strike was anticipated in US-12; only validation behaviour and renderer wiring need to change for US-13.
- **Alternatives considered:** None.
- **Source:** `plans/us-13/data-model.md` ("RollCspPayloadSchema (no change)"), `plans/us-13/contracts/positions-roll-csp.md` ("Request Payload")

## Contracts

### positions:roll-csp (IPC handler — validation behaviour widened)

- **Type:** IPC handler
- **Shape:** Request payload and success response are unchanged from US-12 (`docs/spec/.extracts/us-12.md`). Only the validation behaviour and error catalogue widen.

```typescript
// Request payload — unchanged from US-12
{
  positionId: string                  // UUID
  costToClosePerContract: number      // > 0
  newPremiumPerContract: number       // > 0
  newExpiration: string               // YYYY-MM-DD, must be >= currentExpiration (not strictly >)
  newStrike?: number                  // > 0, defaults to current strike
  fillDate?: string                   // YYYY-MM-DD, defaults to today
}

// Success response — unchanged from US-12
{
  ok: true,
  position:           { id, ticker, phase: 'CSP_OPEN', status: 'ACTIVE' },
  rollFromLeg:        LegRecord,      // action: BUY,  strike: currentStrike
  rollToLeg:          LegRecord,      // action: SELL, strike: newStrike
  rollChainId:        string,         // shared UUID
  costBasisSnapshot:  CostBasisSnapshotRecord
}
```

New error cases added by US-13:

| field           | code                  | message                                             | when                                                                |
| --------------- | --------------------- | --------------------------------------------------- | ------------------------------------------------------------------- |
| `__root__`      | `no_change`           | Roll must change the expiration, strike, or both    | `newStrike == currentStrike AND newExpiration == currentExpiration` |
| `newExpiration` | `must_not_be_earlier` | New expiration must be after the current expiration | `newExpiration < currentExpiration`                                 |

US-12 error cases (unchanged):

| field                    | code               | message                                 |
| ------------------------ | ------------------ | --------------------------------------- |
| `__phase__`              | `invalid_phase`    | Position is not in CSP_OPEN phase       |
| `costToClosePerContract` | `must_be_positive` | Cost to close must be greater than zero |
| `newPremiumPerContract`  | `must_be_positive` | New premium must be greater than zero   |
| `__root__`               | `not_found`        | Position not found                      |
| `__root__`               | `no_active_leg`    | Position has no active leg              |

Note: the US-12 error `must_be_after_current` on `newExpiration` is superseded by the US-13 split into `no_change` (root) and `must_not_be_earlier` (newExpiration).

- **Source:** `plans/us-13/contracts/positions-roll-csp.md`
- **Implementation:** `src/main/ipc/positions.ts` (registration unchanged; behaviour change is via `rollCsp` lifecycle and `rollCspPosition` service)

### rollCsp lifecycle function (signature & validation widened)

- **Type:** other (pure lifecycle engine function)
- **Shape:**

```typescript
interface RollCspInput {
  currentPhase: WheelPhase
  currentStrike: string // NEW (US-13)
  newStrike: string // NEW (US-13)
  currentExpiration: string
  newExpiration: string
  costToClosePerContract: string
  newPremiumPerContract: string
}

interface RollCspResult {
  phase: 'CSP_OPEN'
}

function rollCsp(input: RollCspInput): RollCspResult
```

Validations (throws `ValidationError`):

1. `currentPhase === 'CSP_OPEN'` else `__phase__` / `invalid_phase` (unchanged)
2. `requirePositiveDecimal(input.newStrike, 'newStrike', 'New strike')` (new)
3. If `newStrike === currentStrike AND newExpiration === currentExpiration` → `__root__` / `no_change` / "Roll must change the expiration, strike, or both" (new)
4. If `newExpiration < currentExpiration` → `newExpiration` / `must_not_be_earlier` / "New expiration must be after the current expiration" (changed: US-12 used `<=`)
5. `costToClosePerContract > 0` else `costToClosePerContract` / `must_be_positive` (unchanged)
6. `newPremiumPerContract > 0` else `newPremiumPerContract` / `must_be_positive` (unchanged)

## Domain Concepts

### Roll types (5-way classification)

A roll's label is derived from two independent dimensions — strike movement and expiration movement — yielding five valid combinations and two illegal ones (see decision table under `getRollTypeLabel`). Each label maps to one of three trader intents:

- **Roll Out** (same strike, later expiration) — defensive on time, offensive on premium (carrying the position forward, US-12 behaviour).
- **Roll Down / Roll Down & Out** (lower strike) — defensive on assignment risk, often produces a net **debit** since the lower-strike put has less premium.
- **Roll Up / Roll Up & Out** (higher strike) — uncommon but valid; collects more premium at the cost of accepting more assignment risk.

(Source: `docs/epics/03-stories/US-13-roll-csp-down-and-out.md` Context + Scenario Outline; `plans/us-13/data-model.md`)

### Roll count

Defined as the number of `ROLL_TO` legs attached to a position. Always `>= 0`; increments by exactly one per successful roll regardless of roll type. Used **only** for UI display: a badge ("Roll #N") and a 3+ informational warning. Does not affect lifecycle, cost basis, or order execution. (Source: `plans/us-13/research.md` "Roll Count")

### Active leg after a roll

After a roll, the latest `ROLL_TO` leg replaces the prior `CSP_OPEN` (or earlier `ROLL_TO`) leg as the "active leg" used by the position card and detail page. The leg is selected by the active-leg subquery (`ORDER BY fill_date DESC, created_at DESC LIMIT 1`) over `leg_role IN ('CSP_OPEN', 'CC_OPEN', 'ROLL_TO')`. The position row itself is **not** mutated; the new active strike is purely a function of leg history. (Source: `plans/us-13/research.md` "Active Leg Query Gap"; `plans/us-13/plan.md` §3)

### Net debit on roll-down

"Net debit" = `costToClose > newPremium` for one contract. Roll-downs frequently produce a net debit because the lower-strike put has less premium, especially when the underlying has dropped significantly. A net debit **increases** cost basis (per `calculateRollBasis` formula `basisPerShare = prevBasisPerShare − net`, where `net < 0` on a debit). The renderer flags this with amber/yellow styling and a warning that explicitly mentions cost-basis impact. (Source: `docs/epics/03-stories/US-13-roll-csp-down-and-out.md` Context; `plans/us-13/research.md` "Net Debit Warning Text")

## Decisions & Tradeoffs

- **Strike field is fully editable at the data layer.** US-12 already shipped `newStrike` as optional in the schema and rendered the field as editable (per the mockup). US-13 enables strike changes at the validation layer; no schema or UI structural change is needed for the field itself. (Source: `docs/spec/.extracts/us-12.md` "ADR: `newStrike` optional in payload schema"; `plans/us-13/research.md` "US-12 Baseline → Renderer")
- **`>=` not `>` on expiration.** The IPC contract document states "newExpiration must be `>=` currentExpiration (not strictly `>`)" — this is the precise behavioural change vs US-12. The split into `no_change` and `must_not_be_earlier` removes the implicit conflation that US-12 had. (Source: `plans/us-13/contracts/positions-roll-csp.md` "Request Payload")
- **Cost basis at the new strike.** When assignment later occurs after a roll-down, the assignment uses the _current_ (rolled-to) strike, not the original. Worked example in the story:
  ```
  Original CSP: strike $180, premium $3.50
  Roll to close: cost $2.80 (buy back original)
  Roll to open:  strike $175, premium $3.20, net credit $0.40
  Total premium collected: $3.50 + $0.40 = $3.90
  If later assigned at $175 (new strike): basis = $175.00 − $3.90 = $171.10/share
  ```
  (Source: `docs/epics/03-stories/US-13-roll-csp-down-and-out.md` "Cost basis impact")
- **Soft warnings only.** Both the net-debit preview and the 3+ roll-count warning are advisory — neither blocks submission. Explicitly listed in the story's "Out of Scope". (Source: story "Out of Scope")
- **Mockup state coverage.** The mockup `mockups/us-12-13-roll-csp-form.mdx` provides six states: credit, debit-warning, validation-error, down-and-out, roll-count-warning, success — each mapped to a specific plan area in `plan.md` §5. (Source: `plans/us-13/plan.md` Summary + §5)
- **Roll-type badge colour palette.** Roll type indicator uses blue `#58a6ff`; roll-count badge uses gray `#8899aa` (< 3) or red `#f85149` (≥ 3); debit preview uses amber/gold; success "Active strike" row uses gold. (Source: `plans/us-13/plan.md` §5 Mockup references)
- **E2E coverage is per-AC.** Plan §8 lists nine E2E tests, one per AC, in a new file `e2e/roll-csp-down-and-out.spec.ts` that re-uses the existing `_electron` setup pattern. (Source: `plans/us-13/plan.md` §8)
- **Active-leg-query ownership ambiguity vs US-12.** US-12's refactor results (`docs/spec/.extracts/us-12.md` — "Active-leg query must include ROLL_TO (post-review fix)") record that `get-position.ts` already includes `ROLL_TO` in its active-leg filter. The US-13 research notes this overlap and accepts that the area may be a no-op for `get-position.ts` if US-12 lands first; `list-positions.ts` still needs the same widening. (Source: `plans/us-13/research.md` "Active Leg Query Gap (VERIFIED)")
- **No new migrations.** Quickstart confirms "No new migrations required — US-13 uses existing schema." (Source: `plans/us-13/quickstart.md`)
