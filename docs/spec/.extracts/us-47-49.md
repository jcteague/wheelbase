# Extract: us-47-49

## Summary

Three related stories batched into one branch. **US-47** hardens `AlpacaBrokerProvider` to satisfy remaining US-40 contract details: money normalization to 4dp, consistent auth-error shape with `deeplink`, and paper+live-key mismatch detection. **US-49** adds parked-job self-resume to `PollingScheduler` so `marketClosedMs: null` interval jobs automatically wake when the market reopens. **US-48** was already code-complete and required only e2e + manual smoke verification (see `us-48` plan). No new database tables, IPC channels (beyond the `deeplink` field on the error envelope), or UI components were added.

## Architecture Decisions

### ADR: deeplink as top-level IPC envelope field

- **Decision:** Add `deeplink?: string` as a top-level field on `{ ok: false }` IPC error responses, populated only when the underlying `BrokerError` carries a deeplink.
- **Why:** The renderer needs the deeplink to navigate the user to the right settings screen. Top-level placement keeps it symmetric with `code`, which is already top-level; embedding it inside `errors[0]` would require callers to dig into the array, which doesn't match the existing renderer consumption pattern.
- **Alternatives considered:** Adding `deeplink` to `IpcFieldError` (per-field) — rejected because deeplinks are a call-level concern, not a per-field-validation concern. A separate `router` field — unnecessary indirection.
- **Source:** `plans/us-47-49/research.md`

### ADR: park-wake timer reuses scheduleTick

- **Decision:** Park-wake timers for `marketClosedMs: null` jobs use the same `scheduleTick(state, delayMs)` path as regular cadence ticks.
- **Why:** `scheduleTick` stores the timer id in `state.timerId`, so `stop()` already cancels it via the existing `clearTimeout` loop. No new state or cleanup paths are needed.
- **Alternatives considered:** A separate `state.parkTimerId` — rejected because it doubles the cleanup surface and violates the principle that one slot tracks one pending callback per job.
- **Source:** `plans/us-47-49/research.md`

### ADR: stale-nextOpen fallback uses marketOpenMs

- **Decision:** When `nextOpen` is missing, unparseable, or in the past, fall back to `scheduleTick(state, cadence.marketOpenMs)` rather than no timer.
- **Why:** Prevents the job from staying permanently parked due to clock skew or a malformed broker response. `marketOpenMs` is always present on interval policies; the next tick re-evaluates session and re-parks if still closed.
- **Alternatives considered:** Re-fetching market status immediately (zero delay) — rejected because it could busy-loop under persistent clock skew or bad broker data.
- **Source:** `plans/us-47-49/research.md`

## Acceptance Criteria

### US-47

- AC-1: `getAccountInfo` normalizes `buyingPower`, `portfolioValue`, and `cash` to 4dp strings; `environment` and `accountNumberMasked` are unchanged.
- AC-2: Every broker method rejects missing credentials with `BrokerError('auth_failed', 'Alpaca credentials not configured', 'settings/credentials/alpaca')`.
- AC-3: Broker IPC error payload includes `code`, `message`, and `deeplink` for auth failures; forwarded via `handleIpcCall`.
- AC-4: Paper environment with a live key (starts with `AK`) returns `BrokerError('environment_mismatch', 'Environment mismatch — these are LIVE keys, not paper keys')` on HTTP 401.
- AC-5: Paper environment with a paper key (starts with `PK`) on HTTP 401 returns `auth_failed`, not `environment_mismatch`.
- AC-6: Live environment routes to live Alpaca host (`paper: false`); returned `environment` field is `'live'`.

### US-49

- AC-1: A `marketClosedMs: null` interval job schedules a single wake timer at `status.nextOpen` when market is closed; logs INFO `job {name} parked until next market open at {nextOpen}`.
- AC-2: When the wake timer fires and market is open, the job resumes `marketOpenMs` cadence.
- AC-3: When the wake timer fires during pre/post-market, the job resumes `extendedHoursMs` cadence.
- AC-4: Launching after hours parks the job after the initial tick with exactly one pending timer.
- AC-5: `stop()` cancels the park-wake timer; `vi.getTimerCount() === 0` after stop resolves.
- AC-6: Stale/past `nextOpen` falls back to `marketOpenMs` re-check and logs WARN `nextOpen was unusable for {name}; scheduling fallback re-check`.
- AC-7: Park-wake does not fire a burst (structural: only one timer is queued per `scheduleTick`).

## Decisions & Tradeoffs

- **`requireCredentials()` moved into `getActivities()` and `getMarketStatus()`** — previously only `getAccountInfo()` guarded against missing credentials. The fix is a first-line `this.requireCredentials()` call in all three methods to ensure consistent auth-failed shape regardless of entry point.
- **`wrapError()` paper+AK mismatch added** — mirrors the existing live+PK guard in the opposite direction. Both are now symmetric: live env + PK key → mismatch; paper env + AK key → mismatch.
- **`toMoney` helper extracted** — `new Decimal(s).toFixed(4)` appears three times in `getAccountInfo`; extracted to a module-level `toMoney(value: string): string` during refactor.
- **Mismatch error messages made consistent** — during refactor, the live+PK message was updated from the context-prefixed `${context}: paper key used with live environment` to the plain `'Environment mismatch — these are PAPER keys, not live keys'`, matching the new paper+AK message style.
- **Park-wake reuses scheduleTick** — no new `state.parkTimerId` field; `stop()` unchanged because `clearTimeout(state.timerId)` already covers it.
