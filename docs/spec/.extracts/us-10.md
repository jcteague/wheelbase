# Extract: us-10

## Summary

US-10 implements the "shares called away" action that terminates the wheel cycle. When a covered call is exercised at expiration, the action records a `CC_CLOSE` leg with `action: 'EXERCISE'`, transitions the position `CC_OPEN → WHEEL_COMPLETE` with `status: CLOSED`, and computes the final cycle P&L as `(ccStrike − basisPerShare) × sharesHeld` plus an annualized return from `position.openedDate → fill_date`. A new pure lifecycle function `recordCallAway()` enforces the `CC_OPEN`-phase guard, multi-contract guard (`contracts <= 1`), and fill-date-on-or-after-CC-open guard; a new pure cost-basis function `calculateCallAway()` produces `finalPnl`, `sharesHeld`, `capitalDeployed`, `cycleDays`, and `annualizedReturn` (returning `'0.0000'` when `cycleDays <= 0`). A new `positions:record-call-away` IPC channel backed by `recordCallAwayPosition()` inserts the CC_CLOSE leg (fill_price = CC strike, fill_date = CC expiration, `premium_per_contract = '0.0000'`), updates the position row, and writes a final `cost_basis_snapshots` row carrying the previous `basisPerShare` / `totalPremiumCollected` plus the new `final_pnl`. The renderer ships `CallAwaySheet` (portal orchestrator) → `CallAwayForm` (P&L waterfall confirmation) → `CallAwaySuccess` ("WHEEL COMPLETE" hero + cycle summary + "Start New Wheel on {ticker} →" CTA navigating to `/#/new?ticker={ticker}`). The fill date and fill price are never user-entered — both are derived from the active `CC_OPEN` leg. No DB migration is required. (Source: `plans/us-10/plan.md`, `plans/us-10/research.md`)

## Architecture Decisions

### ADR: Extend `LegAction` enum with `'EXERCISE'`
- **Decision:** Extend `LegAction` from `z.enum(['SELL', 'BUY', 'EXPIRE', 'ASSIGN'])` to `z.enum(['SELL', 'BUY', 'EXPIRE', 'ASSIGN', 'EXERCISE'])`. The new value is used exclusively for the CC_CLOSE leg created by call-away.
- **Why:** The story explicitly distinguishes "shares delivered by option exercise" from a market `BUY` (used for buy-to-close in US-8). Tagging the leg as `EXERCISE` preserves leg history semantics for downstream analytics and reporting.
- **Alternatives considered:** Reusing `BUY` — rejected because the story specifies a distinct action for exercise; the trader did not buy back the contract, the contract was exercised against them.
- **Source:** `plans/us-10/research.md`, `plans/us-10/data-model.md`

### ADR: Dedicated `recordCallAway()` lifecycle function
- **Decision:** Add `recordCallAway()` to `src/main/core/lifecycle.ts` as a pure function returning `{ phase: 'WHEEL_COMPLETE' }`. It validates `currentPhase === 'CC_OPEN'`, `contracts <= 1`, and `fillDate >= ccOpenFillDate`.
- **Why:** The lifecycle engine is a pure state machine; each transition gets its own named function, consistent with `closeCsp()`, `recordAssignment()`, `openCoveredCall()`, `closeCoveredCall()`.
- **Alternatives considered:** None — established pattern across all Epic 02 lifecycle additions.
- **Source:** `plans/us-10/plan.md` §2, `plans/us-10/research.md`

### ADR: Dedicated `calculateCallAway()` cost-basis function
- **Decision:** Add `calculateCallAway()` to `src/main/core/costbasis.ts` returning `{ finalPnl, sharesHeld, capitalDeployed, cycleDays, annualizedReturn }`. Formula: `finalPnl = (ccStrike − basisPerShare) × sharesHeld`; `annualizedReturn = (finalPnl / capitalDeployed) × (365 / cycleDays) × 100`, with a guard returning `'0.0000'` when `cycleDays <= 0`.
- **Why:** `basisPerShare` is the **effective** cost basis already reduced by all premiums collected — the story Technical Notes explicitly forbid re-adding `totalPremiumCollected`. Wrapping the math in a named function keeps the engine open/closed and the service thin.
- **Alternatives considered:** Inline computation in the service — rejected; violates pure-engine boundary. Re-adding premium waterfall separately — rejected by the story.
- **Source:** `plans/us-10/plan.md` §3, `plans/us-10/research.md`, `docs/epics/02-stories/US-10-record-shares-called-away.md` Technical Notes

### ADR: Fill date and fill price derived, not user-entered
- **Decision:** Payload contains only `positionId`. The service derives `fillDate = ccOpenLeg.expiration` and `fillPrice = ccOpenLeg.strike`. The renderer shows the fill date as a read-only field with hint "Derived from your CC — the day shares are delivered to the buyer".
- **Why:** Story Technical Notes: "The fill price is **always the CC strike** — the trader does not enter it manually; it is derived from the CC_OPEN leg." For Phase 1 simplicity, the same principle applies to fill date (using the CC expiration date, not T+1 settlement). Eliminates an entire class of user-entry validation errors.
- **Alternatives considered:** Exposing `fillDate` as an editable field — deferred behind the story's "early exercise" out-of-scope note.
- **Source:** `plans/us-10/research.md`, `plans/us-10/contracts/positions-record-call-away.md`

### ADR: Multi-contract guard at the lifecycle layer
- **Decision:** The lifecycle engine throws `ValidationError('contracts', 'multi_contract_unsupported', 'Multi-contract call-away is not yet supported')` when `contracts > 1`. The service surfaces this before any DB writes.
- **Why:** Story Out of Scope: "Multi-contract positions (> 1 contract): call-away is not supported in this release". Service-layer guards are the authoritative validation layer in this codebase; UI guards alone would be insufficient.
- **Alternatives considered:** UI-only guard — rejected. Silent failure — rejected; the trader needs a clear message.
- **Source:** `plans/us-10/research.md`, `plans/us-10/data-model.md`

### ADR: Final cost-basis snapshot, not in-place update
- **Decision:** Insert a new `cost_basis_snapshots` row carrying the prior snapshot's `basis_per_share` and `total_premium_collected`, plus the newly computed `final_pnl`. Do not mutate the existing CC_OPEN snapshot.
- **Why:** Codebase convention — snapshots are append-only and represent the cost-basis history of the wheel. Matches the pattern used in `expireCspPosition` and `closeCspPosition`. Story Technical Notes require `final_pnl` stored in `cost_basis_snapshot`.
- **Alternatives considered:** Updating the existing snapshot — rejected; mutates history.
- **Source:** `plans/us-10/research.md`, `plans/us-10/data-model.md`

### ADR: CC_OPEN leg `closed_date` linkage by convention
- **Decision:** Do **not** add a `closed_date` column to `legs`. The new CC_CLOSE leg shares `strike` and `expiration` with the originating CC_OPEN leg, which is sufficient for leg-history display.
- **Why:** The `legs` table has no `closed_date` column in the current schema; introducing one would require a migration solely for display affordance already achieved by shared strike/expiration. Mirrors `closeCoveredCallPosition` linkage style.
- **Alternatives considered:** Adding `closed_date` column to `legs` — deferred; no consumer requires it for US-10.
- **Source:** `plans/us-10/research.md`

### ADR: Terminal `WHEEL_COMPLETE` phase + `closed_date = fill_date`
- **Decision:** Set `position.phase = 'WHEEL_COMPLETE'`, `position.status = 'CLOSED'`, `position.closed_date = fillDate` (the CC expiration date). `WHEEL_COMPLETE` is a terminal state with no further valid transitions.
- **Why:** Story Technical Notes: "Store final_pnl in cost_basis_snapshot; set closed_date and status = CLOSED on the position." The phase name carries the domain meaning that the wheel cycle is finished — distinct from `CLOSED_FOR_LOSS` or any other terminal label.
- **Alternatives considered:** None — explicit story requirement.
- **Source:** `plans/us-10/research.md`, `plans/us-10/data-model.md`, `docs/epics/02-stories/US-10-record-shares-called-away.md`

### ADR: Sheet component pattern — mirror `CloseCcEarlySheet`
- **Decision:** Build `CallAwaySheet` (portal orchestrator with `successState: RecordCallAwayResponse | null` state machine) → `CallAwayForm` (confirmation with P&L waterfall) → `CallAwaySuccess` ("WHEEL COMPLETE" hero card). Scrim + 400px right-side panel; sheet returns `null` when `!open`.
- **Why:** The whole Epic 02 surface uses `createPortal` for right-panel modals; mirroring `CloseCcEarlySheet` keeps blur/scrim/focus behavior consistent and reuses styling primitives.
- **Alternatives considered:** shadcn Sheet primitive — rejected as inconsistent with the established custom portal pattern.
- **Source:** `plans/us-10/plan.md` §9, `plans/us-10/research.md`

### ADR: "Start New Wheel" CTA via hash navigation
- **Decision:** The success CTA `onClick` sets `window.location.hash = '#/new?ticker=' + ticker` and then calls `onClose`, navigating to the new-position form with the ticker prefilled.
- **Why:** Story Technical Notes: "uses internal router navigation to `/new?ticker=AAPL` (hash-based routing via wouter)". The Electron app requires hash-based routing for `file://` URLs.
- **Alternatives considered:** `<Link>` component — acceptable but `onClick` mirrors the success-CTA pattern already used in `CloseCcEarlySuccess`.
- **Source:** `plans/us-10/research.md`, `docs/epics/02-stories/US-10-record-shares-called-away.md` Technical Notes

### ADR: No schema migration
- **Decision:** No new tables, no new columns, no migration. Reuse `legs`, `positions`, and `cost_basis_snapshots`.
- **Why:** The only enum extension (`LegAction` adding `'EXERCISE'`) is in TypeScript/Zod, not the SQL schema — the `legs.action` column is `TEXT` and accepts any string. `WHEEL_COMPLETE` already exists as a `WheelPhase` value.
- **Alternatives considered:** None needed.
- **Source:** `plans/us-10/data-model.md`, `plans/us-10/research.md`, `plans/us-10/quickstart.md`

### `positions:record-call-away`
- **Type:** IPC handler (renderer → main, invoke / request-response)
- **Shape:**
  ```typescript
  // Request payload (validated by RecordCallAwayPayloadSchema)
  {
    positionId: string  // UUID — the only field; fillDate and fillPrice are derived from CC_OPEN leg
  }

  // Success response
  {
    ok: true,
    position: {
      id: string
      ticker: string
      phase: 'WHEEL_COMPLETE'
      status: 'CLOSED'
      closedDate: string         // ISO date: CC expiration (= fillDate)
    },
    leg: {                       // the new CC_CLOSE leg
      id: string
      positionId: string
      legRole: 'CC_CLOSE'
      action: 'EXERCISE'
      instrumentType: 'CALL'
      strike: string             // copied from CC_OPEN leg
      expiration: string         // copied from CC_OPEN leg
      contracts: number          // copied from CC_OPEN leg (must be 1)
      premiumPerContract: '0.0000'  // exercise: no premium collected
      fillPrice: string          // CC strike (4 dp)
      fillDate: string           // CC expiration date
      createdAt: string
      updatedAt: string
    },
    costBasisSnapshot: {         // new final snapshot row, carries finalPnl
      id: string
      positionId: string
      basisPerShare: string
      totalPremiumCollected: string
      finalPnl: string           // e.g. "780.0000" or "-250.0000"
      snapshotAt: string
      createdAt: string
    },
    finalPnl: string             // e.g. "780.0000"
    cycleDays: number            // calendar days, position.openedDate → fillDate
    annualizedReturn: string     // e.g. "16.7500", or "0.0000" if cycleDays <= 0
    basisPerShare: string        // effective cost basis used in the calculation
  }

  // Error response
  { ok: false, errors: [{ field: string, code: string, message: string }] }
  ```

## Acceptance Criteria

Background:
- The trader has a `CC_OPEN` position on AAPL
- The effective cost basis is $174.20 per share (after CSP and CC premiums)
- The CC strike is $182.00 with fill date "2026-02-21", 1 contract
- Total premium collected across all legs is $580.00

- Scenario: Successfully record shares called away
  - Given the position is in `CC_OPEN` phase
  - When the trader submits the call-away form with fill date `"2026-02-21"`
  - Then the position phase changes to `WHEEL_COMPLETE`
  - And the position status changes to `CLOSED`
  - And a `CC_CLOSE` leg is recorded with `fill_price $182.00` and `fill_date "2026-02-21"`
  - And the final P&L shows `+$780.00` (share appreciation `($182.00 − $174.20) × 100`)
- Scenario: Called-away below cost basis shows a loss
  - Given the effective cost basis is $176.50 per share
  - And the CC strike is $174.00 (below cost basis)
  - When the trader records shares called away at $174.00
  - Then the final P&L shows `−$250.00` (`($174.00 − $176.50) × 100`)
  - And the P&L is displayed in red
- Scenario: P&L breakdown shown on the form before submission
  - When the trader views the call-away confirmation sheet
  - Then a P&L waterfall shows: CC strike `$182.00`, − Effective cost basis `$174.20`, = Appreciation per share `$7.80`, × 100 shares `$780.00`, = Final cycle P&L `$780.00`
- Scenario: Reject call-away when not in CC_OPEN phase
  - Given the position is in `HOLDING_SHARES` phase
  - When the trader attempts to record shares called away
  - Then the action is rejected with message `"No open covered call on this position"`
- Scenario: Reject fill date before CC open date
  - Given the CC was opened on `"2026-01-20"`
  - When the trader enters fill date `"2026-01-19"`
  - Then a validation error appears: `"Fill date cannot be before the CC open date"`
  - And no leg is created
- Scenario: Success state shows complete wheel summary
  - Given the shares-called-away has been confirmed
  - Then the success screen shows `"WHEEL COMPLETE"`
  - And the total cycle P&L is displayed prominently
  - And the cycle duration in calendar days is shown (position open date to fill date)
  - And the annualized return percentage is displayed
  - And a `"Start New Wheel on AAPL →"` CTA is visible

(Source: `docs/epics/02-stories/US-10-record-shares-called-away.md`)

## Decisions & Tradeoffs

- The active `CC_OPEN` leg is the source of truth for strike, expiration, contracts, and CC open fill date — the service reads these from leg history rather than from any cached position field. (Source: `plans/us-10/plan.md` §5, `plans/us-10/data-model.md`)
- `basisPerShare` is the effective cost basis from the latest `cost_basis_snapshot`; the formula never re-adds `totalPremiumCollected` because premium reductions are already baked into `basisPerShare`. (Source: `docs/epics/02-stories/US-10-record-shares-called-away.md` Technical Notes, `plans/us-10/research.md`)
- `cycleDays` is calendar days from `position.openedDate` to `fillDate` (inclusive endpoint subtraction); `annualizedReturn` returns `'0.0000'` when `cycleDays <= 0` to avoid divide-by-zero. (Source: `plans/us-10/data-model.md`, `plans/us-10/plan.md` §3)
- The success-state hero card uses `pnlColor(finalPnl)` (green when positive, red when negative) so the confirmation and success views render the sign consistently. (Source: `plans/us-10/refactor-phase-results.md` §10)
