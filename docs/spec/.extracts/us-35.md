# Extract: us-35

## Summary

This plan delivered two bundled stories: **US-46 (PollingScheduler)** — a shared, market-aware, setTimeout-chain-based job scheduler — and **US-35 (Assignment Detection & Auto-Transition)** — a poll job that reads Alpaca `OPASN` activities, matches them to open CSP legs, persists a `pending_assignments` row per match, surfaces a notification banner on the positions list, and on trader confirmation calls `assignCspPosition` to transition the position into `HOLDING_SHARES`. Done when assignments detected via real Alpaca paper polling appear as banners in the renderer, can be confirmed to auto-transition positions, and survive app restarts.

## Architecture Decisions

### ADR: Scheduler primitive — setTimeout chain (US-46)

- **Decision:** Each registered job manages its own `setTimeout` chain. After `handler` settles, schedule the next tick with `setTimeout(..., cadenceMs)`.
- **Why:** `setInterval` does not respect async handlers and can stack runs if a tick takes longer than the interval. setTimeout chains naturally serialise. Plus, chain pattern composes cleanly with market-session reads (decide cadence per tick).
- **Alternatives considered:** `node-cron` — overkill, adds a dependency, weak fit for interval-with-market-awareness; rxjs `interval()` — fine but project already has rxjs; chose plain primitives to keep cognitive load low.
- **Source:** `plans/us-35/research.md`

### ADR: Scheduler does not persist state (US-46)

- **Decision:** No `last_run_at` column or settings row. Scheduler is purely in-memory.
- **Why:** Any handler that cares about "what did I see last time" owns its own watermark (US-35 stores `lastPollTimestamp` in app settings). Keeps the scheduler dumb and easy to test.
- **Source:** `plans/us-35/research.md`

### ADR: Activity watermark storage (US-35)

- **Decision:** Store `assignments_last_poll_at` in a small `app_settings` key-value table (create if not present).
- **Why:** The detection service needs to ask Alpaca for activities `since X` to avoid re-processing the entire history every poll. The watermark is per-environment (paper vs live separate keys).
- **Alternatives considered:** Compute the watermark from `MAX(transaction_time)` over the `pending_assignments` table — rejected because dismissed-and-cleared assignments lose this signal.
- **Source:** `plans/us-35/research.md`

### ADR: Watermark captured at poll start, not poll end

- **Decision:** Capture `pollStartedAt = new Date().toISOString()` **before** `await brokerProvider.getActivities(...)`; persist that timestamp (not `now()`) when the batch completes.
- **Why:** Protects against a read-then-update race where activities that arrive during the broker call would be skipped on the next poll. Stamping the start (not the finish) means anything that arrived during the gap is replayed on the next poll, and dedupe handles it.
- **Alternatives considered:** Persist `MAX(transaction_time)` from the returned batch — captured implicitly via stamp-at-start; `pollStartedAt` alone is sufficient and safer.
- **Source:** `plans/us-35/code-review-fixes.md` (Area A1)

### ADR: Deduplication via compound UNIQUE(activity_id, position_id)

- **Decision:** Originally `pending_assignments.activity_id` was UNIQUE alone. After the merge with main (which introduced its own migration 006 for `credential_settings` and `app_settings`), the pending_assignments migration was renumbered to `008_create_pending_assignments.sql` and uses `CREATE UNIQUE INDEX uq_pending_assignments_activity_position ON pending_assignments(activity_id, position_id)` from the start. `INSERT OR IGNORE` on conflict.
- **Why:** A single OPASN activity can match multiple open CSP positions on the same OCC symbol (e.g. two CSP positions on AAPL $180 2026-01-19 PUT). The original single-column UNIQUE would silently lose the second-position pending row. Compound UNIQUE allows one pending row per `(activity_id, position_id)` pair while still preventing duplicate processing.
- **Alternatives considered:** Multi-account modeling on positions — deferred to follow-on story.
- **Source:** `plans/us-35/research.md`, `plans/us-35/code-review-fixes.md` (Area A2)

### ADR: OCC symbol matching (US-35)

- **Decision:** Match OPASN activity symbol against `legs.option_symbol` where the parent position is `CSP_OPEN` and the leg is open. Returns a list of matches (multiple positions may match a single symbol).
- **Why:** OPASN symbol is the put that got assigned. Matching on `option_symbol` avoids ticker/strike/expiration parsing in the match query. Parsing still happens for the notification banner display.
- **Source:** `plans/us-35/research.md`, `plans/us-35/code-review-fixes.md` (Area A2)

### ADR: Notification persistence via the table itself (US-35)

- **Decision:** A "pending" row in `pending_assignments` IS the notification. Renderer queries the table.
- **Why:** Survives app restart automatically. Confirm/dismiss are state transitions on the same row.
- **Source:** `plans/us-35/research.md`

### ADR: Polling cadence for assignment detection (US-35)

- **Decision:** 60s during regular market hours, 5 minutes during extended hours, parked overnight (runs once on next market open). Cadence policy: `{ kind: 'interval', marketOpenMs: 60_000, extendedHoursMs: 300_000, marketClosedMs: null }`.
- **Why:** OPASN events post overnight after expiration; the next morning's first poll catches them. Frequent during-hours polling is for same-day assignments (early-exercise corner case).
- **Open item:** Could be tightened to "once 30 minutes after market open" — deferred until user feedback.
- **Source:** `plans/us-35/research.md`

### ADR: Banner UX — one banner per pending assignment, stacked

- **Decision:** One banner per pending assignment, stacked. Each has its own Confirm / Dismiss.
- **Why:** Bulk confirm/dismiss is out of scope per the story. Stacking keeps each decision discrete.
- **Source:** `plans/us-35/research.md`

### ADR: Scheduler instance — module-level singleton with safe-broker fallback

- **Decision:** `src/main/services/scheduler-instance.ts` exports a module-level `const scheduler` created via `createPollingScheduler(getSafeBroker())`. `getSafeBroker()` wraps `brokerFactory.create()` in try/catch, returning a stub `BrokerProvider` that reports `session: 'closed'` when credentials are missing.
- **Why:** Node module caching guarantees singleton semantics; multiple stories (US-44 IVR collector and beyond) register on the same instance. Safe-broker fallback prevents the module from throwing at import time when credentials aren't configured — parked jobs (no ticks) is the safe degraded state.
- **Alternatives considered:** Lazy `getScheduler()` factory (deferred to a follow-on per code-review-fixes Area H1) for improved testability.
- **Source:** `plans/us-35/green-phase-area6-results.md`, `plans/us-35/code-review-fixes.md` (Area H1)

### ADR: Consolidated `before-quit` handler

- **Decision:** Single `app.on('before-quit', ...)` handler awaits `Promise.all([scheduler.stop(), marketDataProvider.disconnect()])` then calls `app.exit(0)`.
- **Why:** The pre-existing `marketDataProvider.disconnect()` was fire-and-forget; consolidating ensures both subsystems shut down cleanly and concurrently before exit. The scheduler's `stop()` drains in-flight handlers with a 5-second timeout.
- **Source:** `plans/us-35/refactor-phase-area6-results.md`

### ADR: Dev-only test-scheduler IPC

- **Decision:** Dev-only IPC channels `_test:scheduler-registry`, `_test:scheduler-run-now`, `_test:scheduler-register`, `_test:scheduler-simulate-wake` exposed via `src/main/ipc/test-scheduler.ts`. Guarded by `NODE_ENV === 'test'`. Test jobs can be seeded from `WHEELBASE_TEST_JOBS` env var via `seedTestJobsFromEnv`.
- **Why:** E2E specs need to introspect the scheduler registry and trigger out-of-band runs without polluting the production IPC surface.
- **Source:** `plans/us-35/refactor-phase-area8-results.md`

### PollingScheduler interface (US-46)

- **Type:** Service interface
- **Shape:**

  ```typescript
  export type CadencePolicy =
    | {
        kind: 'interval'
        marketOpenMs: number
        extendedHoursMs?: number
        marketClosedMs?: number | null
      }
    | { kind: 'afterClose'; offsetMinutes: number }

  export type JobHandler = () => Promise<void>

  export type JobConfig = {
    name: string
    cadence: CadencePolicy
    handler: JobHandler
  }

  export interface PollingScheduler {
    register(config: JobConfig): void
    start(): void
    stop(): Promise<void>
    runNow(jobName: string): Promise<void>
  }

  export class SchedulerError extends Error {
    readonly code: 'already_registered' | 'job_not_found' | 'not_started'
  }

  // Pure helpers
  export function decideNextCadenceMs(policy: CadencePolicy, status: MarketStatus): number | null
  export function decideAfterCloseFireAt(
    nextClose: string,
    offsetMinutes: number,
    nowMs: number
  ): number | null

  export function createPollingScheduler(
    brokerProvider: BrokerProvider,
    clock?: Clock
  ): PollingScheduler
  ```

  Cadence semantics:

  | Policy       | Tick selection                                                                                                                                                     |
  | ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
  | `interval`   | `marketOpenMs` during regular hours; `extendedHoursMs` (if set) during pre/post; `marketClosedMs` (if set) during closed (`null` parks). Initial run on `start()`. |
  | `afterClose` | One run per trading day at `(today's market close) + offsetMinutes`. Skip weekends/holidays. Missed runs not backfilled.                                           |

  Market session decided per tick via `BrokerProvider.getMarketStatus()`, cached for the duration of the tick to avoid double-calls.

- **Source:** `plans/us-35/data-model.md`, `plans/us-35/green-phase-results.md`
- **Implementation:** `src/main/services/polling-scheduler.ts`

## Schema Changes

### Migration 008 — pending_assignments

- **Change:** new table + indexes
- **Migration file:** `migrations/008_create_pending_assignments.sql` (renumbered from 006 during merge with main, which took 006 for `credential_settings`)
- **Columns / fields:**

  ```sql
  CREATE TABLE IF NOT EXISTS pending_assignments (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    position_id     TEXT NOT NULL REFERENCES positions(id) ON DELETE CASCADE,
    leg_id          TEXT NOT NULL REFERENCES legs(id) ON DELETE CASCADE,
    activity_id     TEXT NOT NULL,
    broker_symbol   TEXT NOT NULL,
    qty             INTEGER NOT NULL,
    transaction_time TEXT NOT NULL,

    detected_at     TEXT NOT NULL DEFAULT (datetime('now')),

    dismissed_at    TEXT

  CREATE INDEX IF NOT EXISTS idx_pending_assignments_status ON pending_assignments(status);
  CREATE INDEX IF NOT EXISTS idx_pending_assignments_position ON pending_assignments(position_id);
  ```

  Notes:

## Acceptance Criteria

US-46 (PollingScheduler):

- Register an interval job
- Start invokes every registered job once and then on cadence
- Market-hours-aware interval respects `marketClosedMs` of null
- Market-hours-aware interval with extended hours uses different cadence
- After-market-close cron-style job (one run per trading day at marketClose + offsetMinutes; skip weekends/holidays; missed runs not backfilled)
- Handler exception does not stop the scheduler (WARN log + reschedule, no pile-up)
- `runNow` triggers an out-of-band invocation
- `stop` cancels all pending invocations and drains in-flight handler promises with a 5-second timeout
- System wake from sleep does not fire missed ticks
- Concurrent registration of same job name is rejected (`SchedulerError('already_registered')`)

US-35 (Assignment Detection & Auto-Transition):

- Detect assignment from OPASN activity and create pending record
- Ignore assignment activity for unknown positions (DEBUG log, skip)
- Do not process the same activity twice (`INSERT OR IGNORE`)
- Handle multiple assignments in a single poll
- API error during polling does not crash the app (WARN log, scheduler continues)
- Assignment notification banner appears on the position list
- Confirming the assignment transitions the position (phase → HOLDING_SHARES, success toast)
- Dismissing the assignment removes the notification (no re-appearance on next poll)
- Assignment notification persists across app restarts (DB persistence)
- Pulsing amber row indicator on rows with a pending assignment (per code-review Area D1 — added during remediation to satisfy original AC)

## Decisions & Tradeoffs

- **Stamp watermark at poll start, not end** — slightly more re-processing on the next poll (handled by `INSERT OR IGNORE`) in exchange for never missing an activity that arrives during the broker call.
- **Compound UNIQUE on (activity_id, position_id)** instead of single-column on activity_id — supports the rare-but-real case of multiple CSP positions on the same OCC symbol; migration edited in place (no shipped data to preserve; devs with local sqlite need to delete the file).
- **TEXT primary keys (UUIDs) over INTEGER** — corrected during green phase to match existing positions/legs schema; the plan's INTEGER spec would have broken FK referential integrity.
- **Banner success-state retention** — on confirm `ok:true`, the banner transitions to a success view (rather than unmounting immediately) so the "Open covered call →" link is reachable. This required keeping confirmed assignments in local component state after the pending list invalidates.
- **`dismissedIds` local Set in banner** — banners disappear immediately on `ok:true` without waiting for a query refetch, since the mocked `useQueryClient.invalidateQueries` in tests doesn't trigger re-renders.
- **Module-level singleton scheduler with safe-broker fallback** — picks degraded "no ticks" mode over import-time crash when broker credentials are missing; later improvable to a lazy `getScheduler()` factory (deferred to Area H1 follow-on).
- **`handleIpcCall` cannot express top-level `code` alongside `errors`** — confirm/dismiss handlers still need bespoke error envelope mapping via `pendingAssignmentErrorResponse`. Tracked as future work if more error types need a `code` field.
- **`runDetectionNow` originally returned `{ ok: true }` only** — code-review Area E2 calls for it to return real `{ detected, skipped, durationMs }` (option (b) is the honest fix; option (a) is to shrink the d.ts to match).
- **Pulsing amber indicator initially missed** — re-added per code-review Area D1 using a small dot span with `bg-wb-gold animate-wb-pulse` and `data-testid="pending-assignment-indicator"` on rows in PositionsListPage / PositionCard whose `position.id` is in the pending set.
- **Inline pixel spacing replaced with Tailwind scale** — `px-[24px] py-[12px]` → `px-6 py-3` to align with the project's design-token discipline.
- **`PendingAssignmentNotification.positionId` typed as `string`** — was originally typed `number` in `src/preload/index.d.ts` but the service returned a UUID string; corrected per code-review Area E1.
- **`scheduler.stop()` drain-timeout cleanup** — captures the 5s setTimeout id and clears it after `Promise.race` resolves (Area F1) to avoid an uncleared timer when drain wins.
