# Extract: us-16

## Summary

This story fixes two bugs in the cost basis engine and one bug in the assignment service: (1) `calculateRollBasis` ignores the strike-delta formula for CSP rolls that change the strike, producing a materially wrong basis; (2) `calculateAssignmentBasis` includes gross ROLL_TO premium without deducting the ROLL_FROM cost to close, understating the assignment basis. Both fixes are pure engine/service changes — no IPC, schema, or frontend changes are required. Done state: all 9 acceptance-criteria scenarios pass as unit tests, service integration tests, and E2E tests.

## Architecture Decisions

### ADR: Extend existing `calculateRollBasis` rather than create a new function

- **Decision:** Extend the existing `calculateRollBasis` function rather than creating a new one.
- **Why:** The function already exists in `src/main/core/costbasis.ts` and is called by both `rollCspPosition` and `rollCcPosition`. It correctly handles the net credit/debit math but applies only the simple formula (`prevBasis - netCredit`) regardless of leg type or strike change. Adding `legType`, `prevStrike`, and `newStrike` to its input is a backward-compatible extension.
- **Alternatives considered:** Creating a separate `calculateCspRollBasis` and `calculateCcRollBasis`; rejected because it duplicates shared net-credit logic.
- **Source:** `plans/us-16/research.md`

### ADR: CSP different-strike roll formula includes strike delta

- **Decision:** `newBasis = prevBasis + (newStrike − prevStrike) − netCredit` for CSP rolls where `newStrike ≠ prevStrike`.
- **Why:** When rolling down (e.g., $50 → $47), the assignment obligation drops by $3/share; this must be reflected in basis immediately, not just at assignment. Ignoring the strike delta gives a materially wrong basis ($47.70 vs the correct $44.70 in the US-16 roll-down scenario).
- **Alternatives considered:** Deferring the strike adjustment to assignment time; rejected because intermediate snapshots would be inaccurate.
- **Source:** `plans/us-16/research.md`

### ADR: CC roll formula ignores strike direction

- **Decision:** CC rolls always use `newBasis = prevBasis - netCredit` regardless of strike direction.
- **Why:** CC strike changes do not affect share cost basis — the shares are already held and the cost was set at assignment. Only the net option premium from the CC roll changes basis.
- **Alternatives considered:** None — this is stated directly in the tech notes and confirmed by the AC.
- **Source:** `plans/us-16/research.md`

### ADR: Compute net credit per roll chain in service layer (not engine)

- **Decision:** Fix `assignCspPosition` to compute a **net credit per roll chain** (ROLL_TO.premium − ROLL_FROM.premium) and pass those netted values to `calculateAssignmentBasis` as `legRole: 'ROLL_NET'` entries with explicit labels.
- **Why:** `calculateAssignmentBasis` currently sums CSP_OPEN + all ROLL_TO premiums. This is wrong because it treats the gross ROLL_TO premium as a credit without deducting the ROLL_FROM cost to close. For example: CSP opened at $50, premium $2.00; rolled (cost-to-close $0.80, new premium $1.50, net credit $0.70) → correct basis = $47.30. Current code gives $50 − $2.00 − $1.50 = $46.50, which is wrong.
- **Alternatives considered:**
  - Passing ROLL_FROM legs directly to the engine as debits — rejected because the engine would need roll_chain_id grouping logic (not appropriate for a pure function).
  - Using the previous cost basis snapshot at assignment time — rejected because `calculateAssignmentBasis` recalculates from scratch and also needs to produce a waterfall; the snapshot does not carry waterfall data.
  - Mutating the engine to infer debits from ROLL_FROM legRole — rejected because it requires the engine to know how to group roll pairs, which belongs in the service layer.
- **Source:** `plans/us-16/research.md`

### ADR: Premium waterfall format — single net line per roll

- **Decision:** The premium waterfall shows one line per roll: `"Roll #N credit: $X"` or `"Roll #N debit: $X"` where X is the net value. This is produced by the service layer grouping legs by roll_chain_id (ordered by fill_date), computing net per roll, and passing an explicit `label` field in `AssignmentBasisLeg`.
- **Why:** The AC specifies `"Roll #1 credit: $0.70"` — a single net line, not two separate ROLL_FROM/ROLL_TO lines.
- **Alternatives considered:** Showing gross ROLL_TO and ROLL_FROM as two separate waterfall lines — rejected because the AC and mockup both show a single net line.
- **Source:** `plans/us-16/research.md`

### ADR: Optional `label` field on `AssignmentBasisLeg`

- **Decision:** Add an optional `label?: string` field to `AssignmentBasisLeg` so the service layer can supply display text for roll-net entries. Engine uses `leg.label ?? LEG_ROLE_LABEL[leg.legRole] ?? leg.legRole` in waterfall generation.
- **Why:** The engine stays pure (no string formatting logic beyond applying the label), while the service controls how each roll is labeled.
- **Alternatives considered:** Adding a separate labeling map in the engine keyed by roll index — rejected because the engine has no roll index concept.
- **Source:** `plans/us-16/research.md`

### ADR: No new IPC, migrations, or frontend work

- **Decision:** This story makes no changes to IPC handlers, Zod schemas, SQL migrations, or the renderer.
- **Why:** The story explicitly states "The display is handled by US-15" and "this is primarily a core engine and service-layer story." All data flows through existing IPC channels; correctness is validated at the engine and service layer.
- **Alternatives considered:** Not documented.
- **Source:** `plans/us-16/research.md`

## Contracts

### RollBasisInput (extended)

- **Type:** TypeScript interface (pure engine input)
- **Shape:**

```typescript
export interface RollBasisInput {
  prevBasisPerShare: string
  prevTotalPremiumCollected: string
  costToClosePerContract: string
  newPremiumPerContract: string
  contracts: number
  legType: 'CSP' | 'CC'
  prevStrike?: string // required when legType === 'CSP'
  newStrike?: string // required when legType === 'CSP'
}
```

Validation rules:
- `legType` is always required.
- `prevStrike` and `newStrike` are required when `legType === 'CSP'`; ignored for `legType === 'CC'`.
- When `prevStrike === newStrike`, use the simple formula (`prevBasis - netCredit`); when they differ, use the strike-delta formula.

- **Source:** `plans/us-16/data-model.md`
- **Implementation:** `src/main/core/costbasis.ts`

### AssignmentBasisLeg (extended)

- **Type:** TypeScript interface (pure engine input)
- **Shape:**

```typescript
export interface AssignmentBasisLeg {
  legRole: string
  premiumPerContract: string
  contracts: number
  label?: string // optional display override for waterfall line
}
```

Engine uses `leg.label ?? LEG_ROLE_LABEL[leg.legRole] ?? leg.legRole` for waterfall display.

- **Source:** `plans/us-16/data-model.md`
- **Implementation:** `src/main/core/costbasis.ts`

### ROLL_NET synthetic premium leg

- **Type:** service-produced synthetic entry passed to `calculateAssignmentBasis` (not stored in DB)
- **Shape:**

```typescript
{
  legRole: 'ROLL_NET',
  premiumPerContract: '0.70',   // ROLL_TO.premium − ROLL_FROM.premium (can be negative for debit)
  contracts: 1,
  label: 'Roll #1 credit'       // or 'Roll #1 debit' if negative
}
```

- **Source:** `plans/us-16/data-model.md`
- **Implementation:** `src/main/services/assign-csp-position.ts`

## Acceptance Criteria

- AC1: Cost basis after single CSP roll with net credit — basis shows $47.30, total premium $270
- AC2: Cost basis after single CSP roll with net debit — basis shows $48.50, total premium $150
- AC3: Cost basis after three sequential CSP rolls — final basis $46.70, total premium $330
- AC4: Cost basis after CSP rolls followed by assignment — assignment basis $47.30 and waterfall shows "CSP Open: $2.00, Roll #1 credit: $0.70"
- AC5: Cost basis after CC roll with net credit — basis shows $45.00
- AC6: Cost basis snapshot chain is complete and auditable — 6 snapshots, each with `basis_per_share` and `total_premium_collected`, in chronological order
- AC7: Multi-contract roll applies net credit/debit per contract correctly — same per-share basis regardless of contract count
- AC8: Cost basis after CSP roll down to lower strike — basis is $44.70, NOT $47.70
- AC9: Cost basis after CC roll up to higher strike — strike change does not affect basis

## Decisions & Tradeoffs

- Engine stays pure: roll-chain grouping logic lives in the service layer (`groupRollsByChain` in `assign-csp-position.ts`) rather than the engine, so the engine remains free of roll/chain knowledge.
- Backward-compatible extension: `RollBasisInput` adds `legType` as required, which forces compilation breakage in service callers — intentionally so callers must opt into the new behavior. Layer 2 areas were sequenced immediately after Layer 1 Green to restore compilation.
- Snapshot 3 basis is $44.00 (NOT $44.70) in the full chain because the roll-down starts from $47.30 (after a prior same-strike roll), not $48.00. The quickstart Key Numbers table lists independent scenarios; chained scenarios diverge.
- Snapshot 4 (assignment) basis matches Snapshot 3 ($44.00) because `calculateAssignmentBasis` recomputes from scratch: strike $47 − CSP $2.00 − Roll #1 net $0.70 − Roll #2 net $0.30 = $44.00.
- `groupRollsByChain` is co-located as a private helper in `assign-csp-position.ts` unless future services need it (avoid premature abstraction).
