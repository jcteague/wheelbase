# Extract: us-101

## Summary

"Turn `Open Wheel` into a shared **New position** sheet over the positions list with a
`Standard / PMCC` toggle: Standard is the shipped wheel form unchanged, PMCC records a long LEAPS
call and a short call together — chain-picked or typed, with actual fills, per-leg fees and a live
opening cash-flow review — through a new `positions:create-pmcc` handler that writes the position,
both legs and the opening cost-basis snapshot in one transaction." A `PMCC_OPEN` position shows "a
minimal, truthful row and detail page; every wheel-only job (alerts, assignment detection, option
polling, the calendar) skips it by construction." "This is journal entry, not order placement: the
service imports no broker module and the e2e suite asserts no `broker:` IPC channel is invoked on
the success path." Migration 017 adds `legs.fees`; `NewWheelPage.tsx` is deleted (`#/` and `#/new`
both render `PositionsListPage`). Linear story: OPT-7 / US-101; estimated 8 points. It names the
PMCC phase and leg roles the later Epic 09 lifecycle stories consume and writes the opening
snapshot in US-103's ledger convention. (Source: `plans/us-101/plan.md` Summary;
`docs/us-101-implementation.md` "What shipped".)

## Architecture Decisions

### ADR: `#/new` becomes "positions list with the New position sheet open"

- **Decision:** Keep `/new` as a route, but render it with `PositionsListPage`. `App.tsx` routes
  `/` and `/new` to the same component through a single RegExp route (`path={/^\/(new)?$/}`), and
  the page derives `sheetOpen = location === '/new'`. Closing the sheet (Cancel, ×, Escape, scrim,
  or a PMCC success) calls `navigate('/', { replace: true })`. `NewWheelPage.tsx` is deleted; its
  consume-on-mount of the promote query string moves into the sheet. The sidebar `Open Wheel`
  item, the `+ New Wheel` header link, the empty-state link, `CallAwaySuccess` and the US-68
  promote keep their `#/new…` targets. Per results: the page does not remount across `/` ↔ `/new`
  ("which is what keeps the recorded banner alive and the list's scroll position intact");
  "Closing the sheet refetches the page's stale queries, which the old page remount used to do
  implicitly"; the sheet restores focus "to whichever element opened it (sidebar item, header link,
  empty-state link) and falls back to the header trigger" (plan said the `+ New Wheel` trigger).
- **Why:** The sheet must open _over_ the list and leave its scroll intact, which a page navigation
  cannot do. Fourteen e2e specs and five renderer entry points already speak `#/new`; US-122's
  promote needs a URL to land on. One RegExp route removes the question of whether two `<Route>`
  elements reconcile into the same instance.
- **Alternatives considered:** (a) a pure local-state sheet with no route (breaks every `#/new`
  entry point and the promote handoff); (b) `#/?new=1` (same breakage); (c) two `<Route>` elements
  to the same component; (d) keep `NewWheelPage` for promote only ("two homes for one form").
- **Source:** `plans/us-101/research.md`, `docs/us-101-implementation.md`,
  `plans/us-101/refactor-phase-results.md` (§12)

### ADR: Standard mode is the shipped `NewWheelForm`, success behaviour included

- **Decision:** Standard renders `NewWheelForm` unchanged: same field ids, validation, promote
  chrome, in-form `✓ WHEEL OPENED` status card and 2 s redirect. Only PMCC mode closes the sheet on
  success and shows the list-level `PMCC recorded — XYZ · LEAPS + short call open` banner with
  `View position →`. Per results: `NewWheelForm` gained an optional `onCancel` — "when present it
  renders its fields in a `SheetBody` and `Cancel` + `Open Wheel` in a `SheetFooter`, exactly as
  `PmccEntryForm` does. Without the prop it renders as before" — plus the optional `sharedRef`
  handle (below) and `onPendingChange`.
- **Why:** The story says Standard "retains the existing opening-put workflow";
  `csp-flow.spec.ts` and `promote-to-trade.spec.ts` assert on that `[role="status"]` card. The
  `onCancel` footer follows the UI note "Keep Cancel and the active strategy's primary action in
  the fixed footer" and the rule that the active form owns the footer.
- **Alternatives considered:** Closing the sheet on wheel success with a list banner (the mockup
  does this for both modes) — would rewrite six assertions for behaviour the AC does not require;
  noted as a follow-up.
- **Watch-out:** with the list underneath, `LoadingState` and `AssignmentNotificationBanner` also
  use `role="status"`; if a spec flakes, scope to `[role="dialog"] [role="status"]` in that spec.
- **Source:** `plans/us-101/research.md`, `plans/us-101/refactor-phase-results.md` (§10)

### ADR: PMCC phase and leg-role names (owned here, consumed by US-115/119/120/111)

- **Decision:** Phases carry a `PMCC_` prefix on the shared `WheelPhase` enum: `PMCC_OPEN` (LEAPS +
  short call open — the only value this story adds). Reserved by name, **not added**:
  `PMCC_LEAPS_ONLY` (US-119 / US-115) and `PMCC_CLOSED` (US-111 / US-120). Leg roles:
  `LEAPS_OPEN` (`BUY`, `CALL`) and `SHORT_CALL_OPEN` (`SELL`, `CALL`); reserved
  `SHORT_CALL_CLOSE`, `SHORT_CALL_EXPIRED`, `LEAPS_CLOSE`, `SHORT_CALL_ASSIGNED`.
  `PHASE_LABEL.PMCC_OPEN` = `PHASE_LABEL_SHORT.PMCC_OPEN` = `'LEAPS + short call open'`;
  `LEG_ROLE_LABEL.LEAPS_OPEN = 'Buy LEAPS call'`, `.SHORT_CALL_OPEN = 'Sell short call'`;
  `PHASE_COLOR.PMCC_OPEN` distinct from every wheel phase. `TriggerEvent` gains `PMCC_OPEN`.
- **Why:** The story forbids overloading `CC_OPEN`; a prefix keeps SQL `phase IN (…)` filters in
  wheel-only jobs correct by construction; only the produced phase enters the enum so
  `Record<WheelPhase, …>` maps stay honest.
- **Alternatives considered:** a separate `PmccPhase` enum and a `phase` union type; overloading
  `CC_OPEN` + `strategy_type` (rejected by the story).
- **Source:** `plans/us-101/research.md`, `plans/us-101/data-model.md` §2

### ADR: Per-leg fees live on the leg (`legs.fees`), not on the snapshot

- **Decision:** Migration `017_add_leg_fees.sql`: `ALTER TABLE legs ADD COLUMN fees TEXT NOT NULL
  DEFAULT '0.0000'`. `LegRecord.fees: string` (4 dp). Wheel legs keep the default and every
  existing `LegRecord` literal gets `fees: '0.0000'` (the wheel never writes fees).
- **Why:** US-103 needs "each fee … once, attached to its own leg"; US-119 records fees on the
  buyback. A fees field on the snapshot would lose per-leg attribution.
- **Alternatives considered:** folding fees into `premium_per_contract` ("hides the fee in the
  fill price and breaks 'actual fill' as recorded"); a `leg_fees` table ("overkill for one number").
- **Source:** `plans/us-101/research.md`, `plans/us-101/data-model.md` §1

### ADR: The opening snapshot is written in US-103's ledger convention

- **Decision:** One `cost_basis_snapshots` row with `trigger_event = 'PMCC_OPEN'`,
  `basis_per_share = initialNetDebit / (contracts × 100)` (fees included, 4 dp; `23.0200` for the
  fee example), `total_premium_collected = shortCredit − shortFees` (dollars; `199.0000` fee
  example, `200.0000` base), `snapshot_at = makeSnapshotAt(long.fillDate)`, `final_pnl NULL`.
- **Why:** US-103's running formula "must reproduce $2,302.00 for that example rather than adding
  [fees] a second time" and defines `total_premium_collected` as short credits after fees; US-103
  then extends a chain rather than migrating one.
- **Alternatives considered:** storing the total debit in `basis_per_share` (wrong unit); no
  snapshot (US-103's first history row would not exist).
- **Source:** `plans/us-101/research.md`, `plans/us-101/data-model.md` §3

### ADR: One pure `calculatePmccOpeningDebit`, shared by service, renderer preview, list and detail

- **Decision:** `calculatePmccOpeningDebit({ contracts, long: { strike, fillPrice, fees }, short })`
  in `src/main/core/costbasis.ts` → `{ leapsCost, shortCredit, fees, initialNetDebit,
  netDebitBeforeFees, basisPerShare, strikeWidthPerShare, debitToWidthPercent }` (4-dp strings;
  `debitToWidthPercent = (longFill − shortFill) / (short.strike − long.strike) × 100`, fees
  excluded, `null` when width ≤ 0). The renderer's `PmccCashFlows` preview imports it from
  `main/core/costbasis` exactly as `PositionCard.tsx` imports `computeUnrealizedPnl`.
  **Per results (authoritative):** "list and detail recompute the initial net debit from the legs'
  fills and fees through `calculatePmccOpeningDebit` instead of the rounded `basis_per_share`" —
  the plan's `initialNetDebit = basis_per_share × 100 × contracts` was replaced (cold-review
  finding). A `money4(value: Decimal): string` helper now owns the "4-dp TEXT money" convention
  across the module (13 call sites).
- **Why:** "The AC pins five numbers; two implementations would drift." Recomputing from the legs
  avoids the rounding loss of a per-share basis.
- **Alternatives considered:** a `src/shared/` copy; an ad-hoc `parseFloat` preview in the form.
- **Source:** `plans/us-101/research.md`, `plans/us-101/refactor-phase-results.md` (§1, §11),
  `docs/us-101-implementation.md`

### ADR: PMCC entry validation is a pure `openPmcc` in `core/lifecycle.ts`, mirrored by the form schema

- **Decision:** `openPmcc(input)` throws `ValidationError(field, code, message)` with the exact AC
  messages and dotted field paths (`long.fillPrice`, `short.expiration`, `short.strike`,
  `__pair__`); field paths are typed by `PmccField = 'ticker' | '__pair__' |
  \`${'long' | 'short'}.${keyof OpenPmccLegInput}\``. The renderer schema
  (`schemas/pmcc-entry.ts`) enforces field-shape rules with the same messages and the cross-leg
  rules via `superRefine`, its paths pinned with `as const satisfies readonly PmccField[]`.
  `handleIpcCall` joins Zod paths with `.`. **Per results:** rule order runs "unexpired contract"
  (rule 13) **before** "expiration after fill date" (rule 12) "in both the engine and the form
  schema", "so an already-expired contract entered with today's fill date gets the AC's message";
  `__pair__` "is a typed optional key of the entry schema (two casts removed)", and "the server's
  pair-level errors now share the client's typed `__pair__` slot". The helper
  `requireNonNegativeDecimal` was renamed `requireNonNegativeFees`.
- **Why:** Engines are pure and own the rules; the story says "Use the same validation at the
  main-process boundary." Dotted paths map 1:1 to RHF's nested `setError('long.fillPrice')`.
- **Boundary-only rules:** underlying mismatch, not a call, quantity mismatch, non-standard
  deliverable have no form field — the form always sends `ticker` / `'CALL'` / shared `contracts`
  / `100`; covered by engine tests and e2e IPC calls.
- **Alternatives considered:** a flat payload (`longStrike`, `shortStrike`, …) — loses the named
  legs and makes US-104/105 inconsistent; Zod-only validation — custom codes cannot be expressed.
- **Source:** `plans/us-101/research.md`, `plans/us-101/data-model.md` §4/§7,
  `plans/us-101/refactor-phase-results.md` (§11, §12), `docs/us-101-implementation.md`

### ADR: Call-chain picker — chain IPC + client-side delta band + one notice slot per leg

- **Decision:** `useCallChain({ ticker, preset, underlyingPrice })` wraps a TanStack query on
  `market-data:option-chain` with `type: 'call'`, the preset's expiration window and strike
  bounds, `staleTime` 30 s, `refetchInterval` 60 s, `enabled` on `tickerSchema`, `select:
  filterCallChain` (absolute delta inside the band; greek-less contracts kept at the end, `Δ —`).
  Notices from pure `deriveChainNotice` in priority order `'loading'` → `'unavailable'` →
  `'empty'` → `'stale'` (selected quote older than `STALE_QUOTE_MS` = 5 min), copy via
  `chainNoticeMessage` (the `derivePromoteBanner` / `promoteBannerMessage` split). A selection
  writes only `strike`, `expiration`, `contractId`; fill, fees and fill date are never written by a
  selection or refetch; `Enter manually` clears and unlocks. **Per results (authoritative):**
  - The underlying price comes from `useUnderlyingPrice(ticker)` — "a one-shot snapshot on its own
    query key", a plain `useQuery` over `getStockQuotes` "that never touches the subscription" —
    **not** `useStockQuotes([ticker])`, which "owns the main process's single stock-quote stream
    subscription (`setStockQuoteTickers` on mount, `[]` on unmount), so mounting it inside the
    sheet replaced the positions list's live feed and cleared it on close"; also "a live price in
    the chain's query key would drop the selected contract on every tick." (Plan's "the query is
    shared" assumption did not hold.)
  - The chain request carries **no `limit`**, so the adapter follows every page ("a 180+ DTE call
    window on a liquid name runs well past one 250-contract page") — research's `limit: 250`
    single-page plan and truncation risk are superseded.
  - The chain "keeps its previous page for the same ticker" during a refetch; "a disabled chain
    query reports `idle` (no 'Loading…' before a ticker is typed)"; `filterCallChain` "keeps the
    selected contract in the list even when a refetch moves it out of the delta band, and drops any
    quote whose OCC root is not the ticker (adjusted contracts never reach the picker)"; the leg
    section "holds the last-seen selected quote so the select, quote strip and stale notice survive
    a refetch that omits it."
- **Why:** The provider abstraction is already behind this IPC; Alpaca's chain filter has no delta
  parameter. The 5-minute threshold matches the detail page's `SNAPSHOT_STALE_THRESHOLD_MS`.
- **Alternatives considered:** reusing `services/candidate-chains.ts` (watchlist-shaped, put-only);
  a single-contract re-quote via `usePromotedQuote` (right for US-122).
- **Source:** `plans/us-101/research.md`, `plans/us-101/data-model.md` §8,
  `plans/us-101/refactor-phase-results.md` (§9, §11, §12), `docs/us-101-implementation.md`

### ADR: Draft retention across the toggle — both forms stay mounted, one imperative shared-field handle

- **Decision:** `NewPositionSheet` renders both `NewWheelForm` and `PmccEntryForm` from the first
  open and hides the inactive one with `hidden`. Each form exposes `{ getShared(): { ticker,
  contracts }, setShared(v) }` via `useImperativeHandle` (`NewWheelForm`'s optional `sharedRef`);
  on toggle the sheet copies ticker/contracts across. Each form is its own `<form>`, so a hidden
  form is never submitted. The toggle is disabled while either mutation is pending. Cancel / × /
  Escape / scrim close via the route and drop both drafts; reopening starts fresh in Standard. A
  failed PMCC save keeps sheet, mode and draft. Per results: "Escape inside a portalled popover no
  longer closes the sheet"; the sheet never closes while a save is pending.
- **Why:** Retained drafts + shared ticker/quantity "with the least machinery."
- **Alternatives considered:** lifting ticker/contracts into the sheet as controlled inputs;
  unmount-and-remount with a saved snapshot.
- **Source:** `plans/us-101/research.md`, `plans/us-101/refactor-phase-results.md` (§11)

### ADR: Test-only chain delay in the fake provider

- **Decision:** `FakeMarketDataProvider.getOptionChainSnapshot` honours
  `FAKE_OPTION_CHAIN_DELAY_MS` (default 0) after `maybeThrow()`; read through the file's
  `parseEnv<number>` seam (refactor), not a bare `process.env`. Does not apply to
  `getOptionSnapshot` or `getStockQuotes`.
- **Why:** The `Loading call contracts…` AC is otherwise a race in e2e.
- **Alternatives considered:** asserting loading only in a component test; a 2-second delay on
  every fixture.
- **Source:** `plans/us-101/research.md`, `plans/us-101/refactor-phase-results.md` (§2)

### ADR: Storage-failure e2e uses a SQLite `BEFORE INSERT … RAISE(ABORT)` trigger (supersedes the read-only-file plan)

- **Decision (as built):** "The storage-failure e2e uses a `BEFORE INSERT … RAISE(ABORT)` trigger
  on `cost_basis_snapshots` rather than `chmod`."
- **Why:** "a read-only file does not fail writes on an already-open connection, and the trigger
  fails the transaction's _last_ write, which is the only way a pass proves the rollback."
- **Alternatives considered:** research's planned `chmod 0o444` of the DB (+ `-wal`/`-shm`) —
  superseded; a `_test:fail-next-write` handler ("leaks test control into the service"); dropping
  the `legs` table via a test IPC.
- **Source:** `docs/us-101-implementation.md` (Decisions), `plans/us-101/research.md` (original)

### ADR: List and detail surfaces get a PMCC branch; wheel code paths untouched

- **Decision:** `PositionListItem` becomes `WheelListItem | PmccListItem` discriminated on
  `strategyType` (the `IpcIvRankPair` exactly-one-arm pattern); only the PMCC arm carries `pmcc:
  PmccListSummary`, and it types `strike`, `expiration`, `dte`, `instrumentType`, `contracts`,
  `entryPremiumPerContract` as `null` so the calendar, `useOptionSnapshots` and `deriveRowDisplay`
  skip it without a branch. The summary is filled by one extra legs query (`readPmccSummaries`).
  `PositionCard` delegates to `PmccPositionRow`; `PositionCockpit` renders `PmccLegReference` when
  `strategyType === 'PMCC'`; `PositionDetailContent` hides `PositionAlertOverridesForm`;
  `PositionDetailActions` shows only the badge for `PMCC_OPEN`. Branches by `strategyType`, never
  by phase string. No change to `evaluate-alerts.ts` / `detect-assignments.ts` — tests prove their
  phase filters (`phase IN ('CSP_OPEN','CC_OPEN')`, `phase = 'CSP_OPEN'`) and the phase-aware
  `activeLegSubquery()` already exclude PMCC.
- **Why:** "Only show the new PMCC on surfaces that can handle its strategy." US-108 / US-118
  replace these minimal views; "they must be truthful now and cheap to delete later."
- **Alternatives considered:** populating `expiration` with the short call's date so the calendar
  shows it — would render a PMCC through wheel copy ("CC expiring"); deferred.
- **Source:** `plans/us-101/research.md`, `plans/us-101/data-model.md` §6/§9,
  `docs/us-101-implementation.md`

## Contracts

### `positions:create-pmcc`

- **Type:** IPC handler
- **Shape:**
  ```typescript
  const PmccLegPayloadSchema = z.object({
    underlying: z.string(),
    instrumentType: z.enum(['PUT', 'CALL']),
    deliverableShares: z.number(), // no .int(): rule 4 is the engine's
    strike: z.number(),
    expiration: IsoDateSchema,
    contracts: z.number(),
    fillPrice: z.number({ error: '<per-leg required message>' }),
    fillDate: IsoDateSchema,
    fees: z.number()
  })
  export const CreatePmccPositionPayloadSchema = z.object({
    strategy: z.literal('PMCC'), // kept for a later z.discriminatedUnion('strategy', …)
    ticker: z.string(),
    long: PmccLegPayloadSchema,
    short: PmccLegPayloadSchema,
    accountId: z.string().optional(),
    thesis: z.string().optional(),
    notes: z.string().optional()
  })
  // success
  {
    ok: true,
    position: PositionRecord & { strategyType: 'PMCC'; phase: 'PMCC_OPEN'; status: 'ACTIVE'; closedDate: null },
    longLeg: LegRecord & { legRole: 'LEAPS_OPEN'; action: 'BUY'; instrumentType: 'CALL'; fillPrice: string },
    shortLeg: LegRecord & { legRole: 'SHORT_CALL_OPEN'; action: 'SELL'; instrumentType: 'CALL'; fillPrice: string },
    costBasisSnapshot: CostBasisSnapshotRecord & { triggerEvent: 'PMCC_OPEN'; finalPnl: null },
    openingDebit: PmccOpeningDebitResult // fixture: 2500 / 200 / 0 / 2300 / 2300 / 23 / 30 / '76.6667'
  }
  ```
  Numeric bounds are deliberately not in Zod ("the engine owns those messages"). `IsoDateSchema`
  is the shared constant extracted in refactor (five uses). Error table (field → code → message):
  `ticker` `invalid_format` `Ticker must be 1–5 uppercase letters`; `*.underlying`
  `underlying_mismatch` `Both calls must have the same underlying.`; `*.instrumentType`
  `not_a_call` `PMCC entry requires two call options.`; `*.deliverableShares`
  `nonstandard_deliverable` `This entry supports standard 100-share contracts only.`;
  `*.contracts` `must_be_positive_integer` `Contracts must be a positive whole number.`;
  `short.contracts` `quantity_mismatch` `Opening quantities must match for this PMCC entry.`;
  `*.strike` `must_be_positive` `Strike must be positive`; `long.fillPrice` (Zod, missing)
  `Enter the actual LEAPS fill price.`; `short.fillPrice` (Zod, missing) `Enter the actual
  short-call fill price.`; `*.fillPrice` `must_be_positive` `Actual fill price must be greater
  than zero.`; `*.fees` `must_be_non_negative` `Fees cannot be negative.`; `*.fillDate`
  `cannot_be_future` `Fill date cannot be in the future.`; `short.fillDate` `long_after_short`
  `LEAPS must be acquired no later than the short-call fill.`; `*.expiration`
  `expiration_not_after_fill` `Expiration must be after the fill date.`; `*.expiration`
  `expired_contract` `Use an unexpired contract for opening a current position.`;
  `short.expiration` `short_not_before_long` `Short call must expire before the LEAPS call.`;
  `short.strike` `strike_not_above_long` `Short-call strike must be above the LEAPS strike.`;
  `__pair__` `not_net_debit` `This PMCC entry requires a net debit before fees.`; `__root__`
  `internal_error` `An unexpected error occurred` (renderer shows `Could not record PMCC. Your
  entries are preserved. Try again.`). Logging: INFO `pmcc_position_created { positionId, ticker,
  phase, initialNetDebit }`, INFO `pmcc_entry_rejected { ticker, field, code }`; DEBUG
  `create_pmcc_position_inputs`, `pmcc_opening_debit_calculated`, `create_pmcc_position_tx_start`
  / `_committed`. Handler: `handleIpcCall('positions_create_pmcc_unhandled_error', () =>
  createPmccPosition(db, CreatePmccPositionPayloadSchema.parse(payload), ivrOnDemand))`;
  `void ivrOnDemand?.collect(ticker)` after commit.
- **Source:** `plans/us-101/contracts/positions-create-pmcc.md`, `plans/us-101/data-model.md` §5
- **Implementation:** `src/main/ipc/positions.ts` → `src/main/services/create-pmcc-position.ts`
  (re-exported from `src/main/services/positions.ts`); engines `src/main/core/lifecycle.ts`
  (`openPmcc`), `src/main/core/costbasis.ts` (`calculatePmccOpeningDebit`); preload
  `src/preload/index.ts` (`createPmccPosition`), `src/preload/index.d.ts`
  (`IpcCreatePmccPositionPayload`, `IpcCreatePmccPositionResult` with the same literal narrowing);

### `market-data:option-chain` renderer access (new consumer)

- **Type:** IPC handler (existing) + renderer adapter/hook
- **Shape:** `getOptionChain(filter)` → `OptionChainQuote[]` (throws `ApiError` 502 on `{ ok:
  false }`); `optionChain(filter)` query key; `useCallChain({ ticker, preset, underlyingPrice })`

## Acceptance Criteria

Scenario names from Linear OPT-7 (one `it()` per `Then`, one `it.each` row per outline example in
`e2e/open-pmcc-position.spec.ts` — 40 cases across 9 scenarios; fixture XYZ at $100, LEAPS $80
call 368 DTE fill $25.00, short $110 call 32 DTE fill $2.00):

- **Open the shared new-position panel**
  - opens a right-hand "New position" panel over the positions list with "Standard" selected
  - the panel shows the existing standard wheel fields and "Open Wheel" submit action
  - a "Standard / PMCC" toggle is visible above the form
- **Switch the entry form in the same panel** (Scenario Outline)
  - Standard → PMCC: the same panel shows Buy LEAPS call and Sell short call sections and the Record PMCC action
  - PMCC → Standard: the same panel shows the existing opening cash-secured put fields and the Open Wheel action
  - (same panel, retained drafts, shared ticker/quantity, hidden form never submits)
- **Select the two contracts independently**
  - selecting the XYZ $80 call expiring in 368 days for the long leg shows its strike, expiration, 368 DTE, quote timestamp, and bid, ask, mid and delta
  - the short-call selection remains independent and is limited to XYZ calls
  - the actual fill price remains a separate required input
- **Review the initial cash flows**
  - shows LEAPS purchase cost $2,500.00 and Short-call credit $200.00
  - shows Fees $0.00 and Initial net debit $2,300.00
  - shows Strike width / share $30.00 and Debit / strike width, before fees 76.67%
  - does not present short-call credit as earned profit or show a guaranteed maximum profit or breakeven
  - (UI-Changes example) adding $1.00 of fees to each leg changes the debit to $2,302.00 while the ratio stays 76.67%
- **Record the position and view both legs**
  - selecting Record PMCC closes the panel and one PMCC position appears with status "LEAPS + short call open" and initial net debit $2,300.00
  - its detail page shows both legs with their quantities, actual fills, fill dates, strikes, and expirations
  - its row in the positions list identifies PMCC and labels each leg's expiration separately
  - no broker order is submitted
- **Reject an unsupported or incomplete entry** (Scenario Outline, 17 rows: `rejects when <invalid_case> with "<message>"`; each asserts the entered values are preserved and `listPositions()` is empty)
  - UI-driven (13): short expiration = LEAPS expiration / after LEAPS → `Short call must expire before the LEAPS call.`; short strike 75.00 / 80.00 → `Short-call strike must be above the LEAPS strike.`; long fill empty → `Enter the actual LEAPS fill price.`; contracts 0 / 1.5 → `Contracts must be a positive whole number.`; fill price 0 / −1 → `Actual fill price must be greater than zero.`; fees −1 → `Fees cannot be negative.`; long fill date tomorrow → `Fill date cannot be in the future.`; long fill date after short fill date → `LEAPS must be acquired no later than the short-call fill.`; expiration on/before fill date → `Expiration must be after the fill date.`; expiration before today → `Use an unexpired contract for opening a current position.`; short credit exceeding long cost → `This PMCC entry requires a net debit before fees.`
  - Boundary-only (4, via `window.api.createPmccPosition(payload)`): short underlying `ABC` → `Both calls must have the same underlying.`; short leg is a put → `PMCC entry requires two call options.`; long 1 / short 2 contracts → `Opening quantities must match for this PMCC entry.`; adjusted deliverable (`deliverableShares: 50`) → `This entry supports standard 100-share contracts only.`
- **Continue when market data cannot supply a selection** (Scenario Outline, 4 rows; fill preserved, manual entry works)
  - the call chain request is still loading → "Loading call contracts…"
  - the selected filters return no contracts → "No matching calls. Adjust filters or enter manually."
  - the market-data request failed → "Quotes unavailable. Enter your filled trade manually."
  - the options quote is stale → "Quote is stale. Verify against your actual fill."
- **Recover from a failed save without a partial position**
  - a storage failure shows "Could not record PMCC. Your entries are preserved. Try again." and neither an incomplete PMCC nor a standalone opening leg appears, and Record PMCC becomes available again
- **Cancel without recording**
  - selecting Cancel closes the panel with no new position and the underlying list retains its scroll position

## Decisions & Tradeoffs

- **`Record PMCC` is always enabled** (results; plan said "disabled while the form is invalid"):
  "submitting an invalid form surfaces the field (and pair) errors and focuses the first"; reads
  `Recording…` while pending, with "a re-entry guard against double clicks" (cold-review B-findings).
- **Ratio label** is `Debit / strike width, before fees` (results; plan/tests had `Debit / width
  before fees`).
- **Error routing:** `__pair__` errors render above the cash-flows block; `long.contracts` /
  `short.contracts` land on the shared `Contracts per leg`; `__root__` / `internal_error` → the
  `AlertBox variant="error"` recovery banner at the top of the body; save-error routing extracted
  to `showSaveErrors(error, setError)`.
- **Form UX copy:** eyebrow `OPEN WHEEL`, title `New position`, subtitle `Record a completed
  trade`; helper `Start the wheel with a cash-secured put.` / `Long LEAPS call + a shorter-dated
  short call.`; leg sections `Buy LEAPS call` (`BUY TO OPEN`, `180+ DTE · Δ 0.70–0.85`) / `Sell
  short call` (`SELL TO OPEN`, `20–45 DTE · Δ 0.25–0.35`); fill labels `Actual purchase / share` /
  `Actual sale / share`; `Opening credit is not yet realized profit.`; small print `Uses your
  actual fills. No order is placed.`; sheet width 460; native `<select>` picker (no `Select`
  primitive) with first option `Choose contract / enter manually`. Changing Ticker clears both
  legs' `contractId`, strike, expiration and fill price but not fees / fill dates.
- **Minimal row:** `PMCC` badge, `LEAPS + short call open`, Strike `$80.00 / $110.00`, Expiration
  `LEAPS · <date>` / `Short · <date>`, DTE `368d` / `32d`, Premium `$200.00`, Cost Basis
  `$2,300.00 net debit`, Opt Mid and P&L `—`, no `TargetBadge` / `ExpiringSoonFlag`. Shared
  `rowStyle(index, phase)` in `positionRowStyles.ts` (refactor).
- **Minimal detail:** `PmccLegReference` — two `SectionCard`s with Strike, Expiration, DTE,
  Contracts, Actual fill, Fill date, Fees; `Initial net debit $2,300.00`; `Live P&L unavailable
  until PMCC valuation ships`; no `VerdictBlock`, no `Cost basis & history` drawer (US-103).
- **Field ids for e2e:** `#pmcc-ticker`, `#pmcc-contracts`, `#long-strike`, `#long-expiration`,
  `#long-fill`, `#long-fees`, `#long-fill-date`, `#long-contract` + `short-` twins;
  `data-testid="record-pmcc"`.
- **Refactor extractions:** `money4` (costbasis), `IsoDateSchema` (main schemas), `insertPosition`
  (`position-rows.ts`, returns `OpenedPositionRecord<S, P>`), `insertPmccLeg`, `ISO_DATE_REGEX`
  (renderer common), `toListItemBase`, `rowStyle`, `LegDatePicker`, pure `legCashFlow`,
  `eachLeg` as nested function. The PMCC money refinements were _not_ folded into
  `positiveMoneySchema` ("the PMCC rules need the AC's exact messages and `parseInputDecimal`").
- **Declined:** `registerParsedHandler` for `positions:create-pmcc` (would be its only caller);
  folding `mapActiveLeg` into `mapLegRow`; switching `openWheel` / `openCoveredCall` to the
  parameterised per-leg helpers ("their messages differ").
- **Tests:** property tests for `calculatePmccOpeningDebit` (Decimal identities, contract
  scale-invariance, `null` iff width ≤ 0, fee-independence of the ratio, 4-dp format) and `openPmcc`
  (generated valid input accepted; strike/expiration/net-debit/put guards; every thrown `field` ∈
  `PmccField`). "No broker order" asserted by spying on `broker:` channels on the success path.
  Existing specs and `e2e/helpers.ts` unchanged; `pmcc-helpers.ts` imports from `helpers.ts`.
- **DTE basis:** kept the codebase's local-calendar-day basis (`computeDteFromInput`, engine
  `computeDte`) rather than the story's America/New_York valuation date — "a cross-cutting change
  outside this story"; fixture yields 368 / 32 on any US-zone machine.
- **Follow-ups (not this story):** US-103 (running PMCC basis + history drawer), US-108 / US-118
  (full row and cockpit), US-113 / US-122 (IV block and promote-into-PMCC in this sheet), US-115 /
  US-119 / US-120 / US-111 (reserved `PMCC_LEAPS_ONLY` / `PMCC_CLOSED` phases and roles); closing
  the sheet on wheel success with a list banner.
