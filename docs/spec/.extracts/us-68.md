# Extract: us-68

## Summary

US-68 is the bridge from "this is the best candidate" to actually opening the wheel, and —
like US-66 — a **pure renderer story**: no IPC surface, no service, no engine, no migration.
It adds a **Promote to trade** action to every ranked screener row, which navigates to the
existing US-1 new-wheel form with ticker, strike, expiration, premium and `contracts: 1`
pre-filled from the candidate, plus a `quotedAt` provenance stamp and an optional `thesis`
seeded from the ticker's watchlist note (US-63).

The pre-filled premium is an **editable default, never a lock**. On open, the promoted form
re-fetches a fresh quote for that exact contract over the existing option-snapshots IPC and
reconciles it into exactly one non-blocking banner (`offline > stale > moved > edited >
match`). The re-fetch never writes into form state — the trader records their actual fill,
not the screener's snapshot — and nothing is persisted until the trader submits the
unchanged `positions:create` mutation.

Promote also grows the form a **derived row** (capital required, yield-if-flat) that
recomputes live as the trader edits, and field hints from the mockup. All of the new chrome
is scoped to promoted mode; the plain US-1 form renders and behaves exactly as before.

## Architecture Decisions

### ADR: The promoted payload travels on the hash query string — and is consumed once

- **Decision:** "Promote to trade" navigates to
  `#/new?promoted=1&ticker=…&strike=…&expiration=…&premium=…&quotedAt=…[&thesis=…]`.
  `NewWheelPage` parses the search string into a `PromotedCandidate` (or `null`) **once**,
  into a `useState` initializer, then clears the query with `history.replaceState` in an
  effect. The clear is keyed off the raw `promoted` param, not the parsed result, so a
  malformed promote is consumed too.
- **Why:** The [wouter-hash-routing-query-prefill ADR](../architecture/02-adrs/wouter-hash-routing-query-prefill.md)
  already established query strings as the mechanism for one-shot navigation context, and
  the payload is five scalars plus an optional ≤500-char thesis.
  The consume step is **load-bearing, not tidiness**: wouter's hash `navigate` writes the
  query into the real `location.search` (`url.search = search`, never cleared) while
  `useHashLocation` exposes no `searchHook`, so `useSearch()` reads that same
  `location.search`. Left in place, the params outlive the promote — the sidebar's plain
  "Open Wheel" anchor would re-open the form fully pre-filled from a candidate nobody
  promoted, provenance strip and market-data re-fetch included. A *malformed* promote is
  cleared for the same reason: its surviving `ticker=` would still pre-fill the next visit.
  `replaceState` fires no `hashchange`, so the current mount keeps the payload it parsed.
- **Alternatives considered:** Zustand/Context/global state (rejected by the existing ADR
  for exactly this shape of problem); a module-level "pending promote" variable (breaks on
  reload, untestable); passing only `contractId` and re-deriving from the screener cache
  (fails when the query cache is cold on the form page).
- **Source:** `plans/us-68/research.md`, `plans/us-68/contracts/promote-navigation.md`, code review

### ADR: Thesis is seeded at the source page from the watchlist cache

- **Decision:** `ScreenerPage` calls `useWatchlist()`; the promote click looks up the
  candidate ticker's `notes` and, when non-empty, URL-encodes it into `thesis`. An
  unresolved (or note-less) watchlist simply omits the param — promote is never blocked on
  the query.
- **Why:** Seeding at the destination would force `NewWheelPage` to gate form mount on an
  async fetch, since RHF `defaultValues` are read once. The source page already has the
  cached watchlist, and the query-string carry keeps the form synchronous.
- **Alternatives considered:** destination-side `useWatchlist` + `reset()` when data lands
  (racy against user typing); destination-side render gating (spinner complexity for an
  optional nicety).
- **Source:** `plans/us-68/research.md`

### ADR: Fresh-quote reconciliation is renderer-only over the existing option-snapshots IPC

- **Decision:** `usePromotedQuote(promoted)` builds the single OCC put symbol with
  `buildOccSymbol` and runs a **one-shot** TanStack query over the existing
  `getOptionSnapshots` adapter: `enabled` only with a promoted payload,
  `refetchInterval: false`, `refetchOnWindowFocus: false`, `retry: false`,
  `staleTime: Infinity`, **`gcTime: 0`**, under a new promote-scoped key in
  `marketDataQueryKeys`. Every failure mode — rejected query, `unavailable: true`, symbol
  missing from the map, or a candidate whose OCC symbol will not build — collapses to
  `'failed'`.
- **Why:** The story's re-fetch is a point-in-time confirmation on form open, not a live
  ticker; `useOptionSnapshots`'s 60s polling would keep flipping the banner while the
  trader types. `gcTime: 0` is what makes it genuinely one-shot: with `staleTime: Infinity`
  alone the cache entry survives unmount, so promoting the same contract twice inside the
  default 5-minute window would resolve instantly from cache and present the *previous*
  visit's mark and timestamp as the fresh quote — precisely the staleness the story exists
  to catch. Degrading rather than throwing mirrors the boundary-I/O rule of the
  [alert-evaluation-failure-isolation ADR](../architecture/02-adrs/alert-evaluation-failure-isolation.md).
- **Alternatives considered:** reusing `useOptionSnapshots` (polling semantics wrong; the
  shared query key would cross-contaminate cockpit caches); a new dedicated IPC handler
  (duplicate surface for data the existing handler already returns).
- **Source:** `plans/us-68/research.md`, code review

### ADR: Price-moved test is a pure helper — deviation must exceed max($0.05, 5%)

- **Decision:** `markMovedMaterially(promotedMark, freshMark)` in
  `src/renderer/src/lib/promote.ts`:
  `|fresh − promoted| > max(0.05, 0.05 × promoted)`, strict `gt`, all via `decimal.js`. A
  deviation exactly at the threshold does **not** warn.
- **Why:** The story pins the formula — both the tick-noise floor and the relative test must
  be exceeded, which is equivalent to exceeding the max of the two. The $0.05 floor exists
  to keep sub-$1.00 premiums from triggering on routine bid-ask bounce, not as an
  independent trigger. A pure helper is unit-testable independent of the form, matching the
  `openCcGuardrail.ts` precedent in the soft-client-side-warnings ADR. AC check: promoted
  2.70 → threshold 0.135; fresh 2.50 → deviation 0.20 → warns; fresh 2.68 → 0.02 → silent.
  Sub-$1 floor: 0.60 → threshold 0.05; 0.64 silent, 0.66 warns.
- **Note:** This is an **AND** of the two tests. The story was revised on this branch from
  an earlier "> 5% **or** > $0.05" wording; under the current rule a $2.70 → $2.62 move is
  silent where the old wording would have warned.
- **Alternatives considered:** computing inline in the component (untestable); comparing
  main-process-side (a new IPC surface for a display-only concern).
- **Source:** `plans/us-68/research.md`

### ADR: One banner slot with a fixed precedence — offline > stale > moved > edited > match

- **Decision:** `derivePromoteBanner(...)` returns exactly one state:
  1. `offline` (gold) — re-fetch failed or symbol unavailable
  2. `stale` (gold) — market display is `CLOSED` **or** `EXT`; the state carries
     `session: 'CLOSED' | 'EXT'` so the copy can differ
  3. `moved` (gold) — `markMovedMaterially` true
  4. `edited` (green) — the trader's premium ≠ the promoted premium
  5. `match` (green) — fetch succeeded, no material move
  6. `none` — fetch still pending on an open market
  No state ever disables submit.
- **Why:** The mockup shows exactly one banner per state and the states genuinely overlap.
  `offline` outranks `stale` because it explains why no fresh time is shown; `stale`
  outranks the price comparisons because a closed-market fetch "succeeds" with the 16:00
  close, so `match`/`moved` against it would mislead. The `session` discriminator exists
  because one shared "Market closed — …" string would be **false during an EXT session**,
  with the pill beside it reading `EXT`; equity options simply do not trade extended hours,
  which is the accurate reason an EXT mark is stale.
- **Alternatives considered:** stacking multiple banners (the mockup shows one; two gold
  "verify before recording" warnings is noise); keying stale off a timestamp-age heuristic
  (rejected for the same reason US-66 rejected it — the pill's session derivation is the
  single source).
- **Source:** `plans/us-68/research.md`, code review

### ADR: The re-fetch never writes into form state

- **Decision:** The fresh quote flows only into the provenance strip and the banner. The
  premium field is set once, from the promoted mark, in `useForm({ defaultValues })` — no
  `reset()`, no `setValue()` on resolution.
- **Why:** The story is explicit, and two ACs assert the field still shows `2.70` after a
  fresh `2.68` / `2.50` arrives. The trader records their actual fill, not the mark. Keeping
  fetch results out of RHF state also sidesteps every race between resolution and typing.
- **Alternatives considered:** none viable — overwriting is AC-forbidden.
- **Source:** `plans/us-68/research.md`

### ADR: Provenance and banner deliberately report different instants

- **Decision:** `usePromoteBanner` returns two timestamps. `PromoteProvenance` shows the
  **freshest mark held** — the re-fetch's timestamp once it lands, the screener's until
  then. The `offline` and `stale` banners carry **`promoted.quotedAt`** instead.
- **Why:** They describe different things. The strip answers "how current is the newest
  quote I have?" (the AC: "the snapshot time updates to the fresh quote's time"). The
  banners describe **the pre-filled mark**, which is always the screener's — so
  "the pre-filled mark is a stale after-hours snapshot (quoted 10:42:15)" must name the
  screener's instant. Unifying the two (an intermediate state during review) made the
  banner assert a false provenance for the value sitting in the premium field whenever the
  two differed. Each element names what it is describing.
- **Source:** code review

### ADR: "Edited" is a property of the form, not of the banner

- **Decision:** `isPremiumOverridden(currentPremium, promotedPremium)` is exported from
  `lib/promote.ts`. The derived row's "recomputed from your price" caption reads it
  directly, independently of which banner won the precedence chain.
- **Why:** Deriving the caption from `banner.kind === 'edited'` silently dropped it whenever
  a higher-precedence banner (offline / stale / moved) held the single slot — i.e. for most
  of the trading day — even though `deriveYield` genuinely had recomputed from the trader's
  price. Whether the trader overrode the mark is a fact about the form; the banner is only
  one of several places that fact surfaces.
- **Source:** code review

### ADR: Promoted chrome is a component, so the plain form mounts no market-data hooks

- **Decision:** `PromotedFormChrome` owns `usePromoteBanner` (and through it
  `usePromotedQuote` + `useMarketStatusDisplay`) and renders the provenance strip and banner.
  `NewWheelForm` renders it only when `promoted` is set.
- **Why:** `useMarketStatusDisplay` mounts `useMarketStatus`, which carries
  `refetchInterval: 60_000`. Calling it unconditionally from the form added a permanent 60s
  `market:status` IPC poll to `#/new` — a page that previously made no market calls at all.
  Scoping it to a conditionally-rendered child keeps the cost on the promoted path.
  The derived row stays in the form because it also needs strike/contracts/expiration; it
  takes `edited` as a prop computed from `isPremiumOverridden`, which is what made the
  extraction possible at all.
- **Source:** code review

### ADR: Derived capital/yield row and promote chrome render only in promoted mode

- **Decision:** `NewWheelForm` gains an optional `promoted?: PromotedCandidate` prop. When
  present it renders the provenance strip, the banner slot, a derived row (capital required
  = strike × 100 × contracts, grouped 0dp; yield-if-flat = premium/strike, annualized
  × 365/DTE, recomputed live via `useWatch`), field hints from the mockup, and a `{dte} DTE`
  hint under expiration; contracts defaults to `'1'` and the Advanced section opens so the
  seeded thesis is visible. When absent the form renders exactly as before.
- **Why:** Every AC mentioning capital/yield/provenance is framed inside the promote flow.
  Scoping the new chrome keeps the US-1 surface stable (Simplicity First), and `useWatch`
  for reactive derived values follows the CLAUDE.md form rules.
- **Alternatives considered:** always rendering the derived row (scope creep into US-1's
  accepted UI); a separate `PromotedWheelForm` (would duplicate the entire field grid and
  success flow for one prop's worth of difference).
- **Source:** `plans/us-68/research.md`

### ADR: DTE for live form input is counted in local calendar days

- **Decision:** `computeDteFromInput(expiration)` in `lib/format.ts` guards a possibly
  mid-edit date and counts with `differenceInCalendarDays(parseISO(expiration), new Date())`
  — deliberately matching the engine's `src/main/core/dte.ts`, **not** the UTC arithmetic in
  the older renderer `computeDte`.
- **Why:** `computeDte` builds "today" from UTC date parts, so for any trader west of UTC
  after the UTC date rolls over (≈17:00 ET — exactly when candidates get reviewed) it counts
  one day short. The promoted form would read `36 DTE` for the screener row that just said
  `37`, and annualize the yield off that wrong number, so the form's `%/yr` would not match
  the screener's `annualizedYield`. CLAUDE.md's Date Handling rule names this pattern
  directly.
- **Source:** code review

### ADR: E2E simulates quote drift and outage by mutating main-process env at runtime

- **Decision:** The spec reuses the US-66 screener fixtures/helpers and, between "screener
  results rendered" and "Promote clicked", mutates the fake provider's fixtures from the
  test via `app.evaluate(...)` — a re-served chain at a drifted mark and later timestamp, or
  `FAKE_MARKET_DATA_ERROR` for the outage. CLOSED/EXT use the existing `marketStatus` launch
  fixture.
- **Why:** `FakeMarketDataProvider` re-reads `process.env` on **every** call
  (`buildMockMap` / `maybeThrow`), so runtime mutation needs no new test seam — the screener
  run sees the original quote and the form's re-fetch sees the drifted/failed one, which is
  exactly the story's temporal split. `ElectronApplication.evaluate` runs in the main process.
- **Alternatives considered:** a new env seam for "second fetch differs" (unnecessary);
  stubbing the IPC from the renderer (violates the US-65/66 nothing-between-IPC-and-DOM
  testing decision).
- **Source:** `plans/us-68/research.md`

## Contracts

No IPC surface added. US-68 **consumes** `market-data:optionSnapshots` (US-33/39) and
`positions:create` (US-1) unchanged. Its one interface boundary is a cross-page navigation
contract, documented in IPC-contract format because it is the story's only boundary.

### promote-navigation (hash query string)

- **Type:** cross-page navigation contract
- **Producer:** `ScreenerPage` / `ScreenerResultsTable` → `navigate('/new?' + buildPromoteSearch(...))`
- **Codec:** `src/renderer/src/lib/promote.ts`
- **Consumer:** `NewWheelPage` → `NewWheelForm`'s `promoted` prop
- **Shape:**

```typescript
// #/new?promoted=1&ticker=AAPL&strike=180&expiration=2026-08-21
//       &premium=2.70&quotedAt=2026-08-07T20%3A00%3A02Z[&thesis=<encodeURIComponent>]

type PromoteSearchParams = {
  promoted: '1' // discriminator — absent on the plain ?ticker= flows
  ticker: string // uppercase ticker
  strike: string // Decimal-normalized ('180.0000' → '180')
  expiration: string // YYYY-MM-DD
  premium: string // the promoted mark, 2dp, verbatim ('2.70')
  quotedAt: string // ISO instant of the screener quote
  thesis?: string // watchlist note, URL-encoded; omitted when absent
}

function buildPromoteSearch(candidate: PromoteSource, note?: string | null): string
function parsePromotedParams(search: string): PromotedCandidate | null
```

- **Errors:** none. Malformed or incomplete `promoted` params are not an error state —
  `parsePromotedParams` returns `null`, the page renders the plain form (honouring a bare
  `?ticker=` if present), and the params are cleared from the URL either way.
- **Validation:** an internal Zod schema reusing `tickerSchema`, `positiveMoneySchema` and
  `isoDateSchema` from `schemas/common.ts`, plus a parseable-instant refinement for
  `quotedAt` and a ≤500-char `thesis`.
- **Source:** `plans/us-68/contracts/promote-navigation.md`

### Test-id contract (the e2e / component boundary)

- **Type:** DOM contract
- **Shape:** `screener-promote-<ticker>` (the per-row action), `promote-provenance`,
  `promote-banner` (carrying `data-kind` and `data-tone`), `derived-capital`, `derived-yield`.
- **Implementation:** `ScreenerResultsTable.tsx`, `PromoteProvenance.tsx`,

## Schema Changes

None. US-68 persists nothing new — no table, no migration, no service change. The recorded
trade goes through the existing `positions:create` path with whatever the trader confirms;
SQLite stays the source of truth and the screener snapshot is never written anywhere.

## Acceptance Criteria

_Background: the screener shows an AAPL candidate — $180 put, expiring 2026-08-21, mark
$2.70, delta 0.28, quoted at 10:42:15._

- **Promote pre-fills the new-wheel form** — clicking "Promote to trade" on the AAPL row
  opens the new-wheel form with ticker `AAPL`, strike `180`, expiration `2026-08-21`,
  premium per contract `2.70`, contracts `1`, and capital required `$18,000` (180 × 100 × 1).
- **Pre-filled premium is editable, not locked** — changing premium per contract to `2.65`
  is accepted.
- **Submitting records the edited premium** — the recorded trade shows premium per contract
  $2.65, not the screener snapshot.
- **A fresh quote is shown when the form opens** — with a current mark of $2.68, the snapshot
  time updates to the fresh quote's time and the premium field still shows `2.70`.
- **Warn when the price has moved materially** — a re-fetched mark of $2.50 shows the
  non-blocking banner "Price moved: quoted $2.70 → now $2.50 — review before submitting";
  the premium field still shows `2.70` and the trader can still submit.
- **Warn when the market is not open** — with the market status pill reading `CLOSED` or
  `EXT`, the form flags the pre-filled mark as a stale after-hours snapshot.
- **Form still works when the fresh quote can't be fetched** — with the provider
  unavailable, the form opens with the promoted values pre-filled, shows "Couldn't refresh
  quote — showing screener snapshot from 10:42:15", and the trader can still submit.
- **Promote never auto-submits** — no position is created until the trader submits the form.

## Decisions & Tradeoffs

- **Structural fields are pre-filled but stay editable.** Promote never locks a field; only
  market-derived values (premium) are treated as volatile snapshots.
- **The banner is always non-blocking.** No banner state disables submit — the trader is
  being told something, not stopped.
- **Banner copy lives in one place** (`promoteBannerMessage` in `lib/promote.ts`) so the
  component, its unit tests, and the e2e spec assert the same literals.
- **A cleared or half-typed premium is not an override.** `parseInputDecimal` (new, in
  `lib/decimal-input.ts`) rejects `''` and `'2.'` — `new Decimal` throws on the first and
  silently reads the second as `2`, so neither is safe to point at a value the trader is
  still typing. The same guard backs the derived row's `—` placeholders.
- **Yield formatting reuses `fmtYieldPercent`** for both the period and annualized figures,
  so the promoted form and the screener row round identically. (The mockup mixed
  `toFixed(2)` and `toFixed(1)`; one rounding rule was preferred over mockup fidelity.)
- **The screener table gained a trailing, unlabelled action column.** The 12 metric columns
  US-66 pinned keep their positions; `TableHeader`'s `children` became optional.
- **`AlertBox` gained pass-through for three `data-*` attributes only** — deliberately not
  `ComponentProps<'div'>`, since the component owns its `className`/`style` and advertising
  them while dropping them would be a lie.
- **All 10 e2e assertions were falsified** (expected values flipped) against the running app
  before being trusted — the US-65/66 technique, applied because the production code already
  existed when the e2e layer was written.
- **`vitest.e2e.config.ts` sets `bail: 1`**, which masks how many specs really pass; use
  `--bail=0` when diagnosing.

## Open Questions

- **The renderer now has two DTE bases.** `computeDteFromInput` counts local calendar days
  (matching `core/dte.ts`), while the older `computeDte` still backs ~9 call sites with UTC
  arithmetic — including `lib/verdict.ts`, which makes *management decisions* on it. US-68
  documented the divergence rather than closing it; converging on the local implementation
  is a small, well-tested follow-up.
- **Yield and capital math is duplicated across the process boundary.**
  `NewWheelDerivedRow` re-implements, constant for constant, formulas the US-65 engine
  already ran on the same contract (`SHARES_PER_CONTRACT`, `DAYS_PER_YEAR`, period yield,
  annualization, capital). A pure module under `src/shared/` would let both consume one copy.
- **An outage suppresses the after-hours flag.** With the market CLOSED *and* the provider
  down, `offline` outranks `stale`, so the stale-snapshot warning is not shown. The offline
  copy still says "Verify before recording", so the trader is under-informed rather than
  misled.
- **A materially-moved price is never surfaced outside market hours**, since `stale`
  unconditionally outranks `moved`. Deliberate, but it means the price-moved warning is
  unreachable in the session where most wheel planning happens.
- **The promoted form shows no market-status pill.** It consumes market status (the banner
  says "Market closed" / "Extended hours") but `NewWheelPage`'s header carries only a
  breadcrumb, so there is no pill to corroborate it — unlike the screener and cockpit headers.
- **`derivePromoteBanner` handles 2 of the 4 `MarketStatusDisplay` members.** It tests
  `CLOSED || EXT` explicitly (matching the AC's two examples); `DELAYED` falls through to the
  price comparison and would show a reassuring `match` banner over data the app has flagged as
  delayed. Unreachable today only because `usePromoteBanner` calls `useMarketStatusDisplay()`
  with the default `stale = false` — one future caller passing `true` flips it silently.
- **The strip and the banner both label their instant "Quoted"** and, when the market is
  CLOSED/EXT and the re-fetch succeeded, print different times. Each value is individually
  correct (the strip must update per AC 4; the banner must name the pre-filled mark), but the
  shared label attributes the fresh quote's time to the promote. Relabelling one of them
  (e.g. `Promoted 10:42:15 · Quote 16:00:02`) would resolve it — a copy decision, not a code one.
- **The moved-threshold semantics were narrowed on this branch** from "> 5% **or** > $0.05"
  to `max($0.05, 5%)`. The code follows the current story wording; the change reduces how
  often traders are warned and is worth an explicit product confirmation.
