# Extract: us-104

## Summary

"Add the PMCC short-call roll: a pure `rollPmccShortCall` lifecycle rule set (phase, open short,
positive money, US-102's coverage comparator, on-or-after-current, no-change), a service that writes
the linked `ROLL_FROM` BUY / `ROLL_TO` SELL pair and calls US-103's `appendPmccSnapshot` with
`'PMCC_SHORT_ROLL'` in one transaction, the `positions:roll-pmcc-short` channel, and the `Roll Short
Call` sheet from the consolidated detail mockup — coverage ruler, live `Net Debit / Net Credit`
preview with the roll label and replacement DTE, post-roll basis and effective share cost, and the
advisory below-effective-cost warning. Done when every Linear scenario passes end to end from the
US-103 Background (XYZ, $108 short, basis $21.20), the roll lands as one chain and one snapshot
reading $21.80, and the wheel's covered-call roll is unchanged." Linear story: OPT-12 / US-104;
estimated 5 points. Layout of record: `mockups/epic-09-pmcc-position-detail.mdx` (`RollShortSheet`,
presets `rs-entry` … `rs-recorded`; `mockups/us-104-roll-pmcc-short-call.mdx` is design history).
**No migration.** Builds on US-103 (`appendPmccSnapshot`, `groupRollChains`, `readLegs`,
`PmccTriggerEvent`) and carries the short-side half of US-102's comparator extraction. During
implementation and review the engine grew from eight to **ten** rules (a roll fill-date rule and an
expiration-after-fill rule), the date/no-change rules moved into a shared pure
`pmccShortRollIssues` in `src/main/core/pmcc-rules.ts` consumed by both engine and renderer schema,
the engine result became `{ phase, openShort, newStrike }`, `insertLegRow` was extracted into
`leg-rows.ts`, and `RollResultBase` became generic over the phase. All 12 e2e cases (one per AC
scenario / outline row) pass (`green-phase-results.md` Area 10). (Source: `plans/us-104/plan.md`
Summary; `research.md`; `data-model.md` § 4; `*-phase-results.md`.)

## Architecture Decisions

### ADR: US-104 builds on US-103 and carries the short-side half of US-102's comparator extraction

- **Decision:** Assumes US-103 has landed (every main-process area imports its writer, chain helper,
  legs reader and trigger vocabulary). Because US-102 had not started, this story extracts the
  **short-side** comparator from `pmccCrossLegIssues` into two exports in
  `src/main/core/pmcc-rules.ts` — `shortExpiresBeforeLeaps(shortExpiration, longExpiration): boolean`
  (`shortExpiration < longExpiration`, ISO strings compare as dates) and
  `SHORT_NOT_BEFORE_LONG = { code: 'short_not_before_long', message: 'Short call must expire before the LEAPS call.' }`
  (`as const satisfies PmccRule`) — and makes `pmccCrossLegIssues` call them, "so the message exists
  once. US-102 keeps ownership of the message text and of the inverse (`LEAPS call must expire after
  the short call.`), the US-105 / US-115 boundaries, and its own AC."
- **Why:** "Linear marks US-104 blocked by US-102 and US-103 … US-102's only deliverable this story
  needs is the shared predicate + message, and US-102 itself says the entry check is to be extracted
  rather than copied."
- **Alternatives considered:** Wait for US-102 (blocks a 5-point story on another for one
  function); copy the comparison inline in `rollPmccShortCall` ("the exact drift US-102 exists to
  prevent"); pass `pmccCrossLegIssues` the whole pair (it also runs fill-date, strike-above-long and
  net-debit rules that do not apply to a roll).
- **Refactor outcome:** `issueIf` now takes a `{ code, message }` rule object for all rules
  (`(broken, field, rule: PmccRule)`); `PmccIssue` became generic `PmccIssue<F extends string =
  PmccCrossLegField>`. A second shared constant `EXPIRATION_NOT_AFTER_FILL = { code:
  'expiration_not_after_fill', message: 'Expiration must be after the fill date.' }` is used by
  `openPmcc`'s per-leg rule, the roll engine and the roll form.
- **Source:** `plans/us-104/research.md`; `plans/us-104/refactor-phase-results.md` Area 1;
  `plans/us-104/data-model.md` § 4

### ADR: `rollPmccShortCall` is a new pure lifecycle function with a fixed rule order (ten rules)

- **Decision:** In `src/main/core/lifecycle.ts`:

  ```ts
  interface PmccShortCallTerms { strike: string; expiration: string; fillDate: string }
  interface RollPmccShortCallInput<S extends PmccShortCallTerms = PmccShortCallTerms> {
    currentPhase: WheelPhase
    openShort: S | null
    leapsExpiration: string
    fillDate: string        // the roll's fill date
    newStrike?: string      // omitted = roll out at the current strike
    newExpiration: string
    costToClosePerContract: string
    newPremiumPerContract: string
  }
  interface RollPmccShortCallResult<S extends PmccShortCallTerms = PmccShortCallTerms> {
    phase: 'PMCC_OPEN'
    openShort: S            // the caller's own short, now known to exist
    newStrike: string       // the current strike when the input omitted it
  }
  ```

  Rules, in order, first failure throws `ValidationError(field, code, message)`:

  | #   | Rule                                                                       | field                    | code                          | message                                                                            |
  | --- | -------------------------------------------------------------------------- | ------------------------ | ----------------------------- | ---------------------------------------------------------------------------------- |
  | 1   | `currentPhase !== 'PMCC_OPEN'`                                             | `__phase__`              | `invalid_phase`               | `Position is not in PMCC_OPEN phase`                                               |
  | 2   | `openShort === null`                                                       | `__root__`               | `no_open_short_call`          | `This PMCC has no open short call to roll.`                                        |
  | 3   | `fillDate < openShort.fillDate`                                            | `fillDate`               | `close_date_before_open`      | `Fill date cannot be before the short call open date`                              |
  | 4   | `costToClosePerContract ≤ 0`                                               | `costToClosePerContract` | `must_be_positive`            | `Cost to close must be greater than zero`                                          |
  | 5   | `newPremiumPerContract ≤ 0`                                                | `newPremiumPerContract`  | `must_be_positive`            | `Replacement premium must be greater than zero`                                    |
  | 6   | `newStrike ≤ 0`                                                            | `newStrike`              | `must_be_positive`            | `Strike must be positive`                                                          |
  | 7   | `!shortExpiresBeforeLeaps(newExpiration, leapsExpiration)`                 | `newExpiration`          | `short_not_before_long`       | `Short call must expire before the LEAPS call.` (US-102's constant)                |
  | 8   | `newExpiration < openShort.expiration`                                     | `newExpiration`          | `must_be_on_or_after_current` | `Replacement expiration must be on or after the current expiration (Nov 20, 2026)` |
  | 9   | `newExpiration <= fillDate`                                                | `newExpiration`          | `expiration_not_after_fill`   | `Expiration must be after the fill date.` (`EXPIRATION_NOT_AFTER_FILL`)            |
  | 10  | `newStrike === openShort.strike && newExpiration === openShort.expiration` | `__roll__`               | `no_change`                   | `Roll must change the strike, the expiration, or both`                             |

  "Rules 3 and 7–10 are reported by the pure `pmccShortRollIssues` in `pmcc-rules.ts` (review fix),
  which the renderer form schema also consumes, so codes and messages have one home; the engine
  throws its first issue, a rule-3 issue before the money rules." Rule 8's date is
  `format(parseISO(d), 'MMM d, yyyy')`; strike equality is `Decimal.eq` (so `108` vs `108.0000` is
  `no_change`). No logging, no I/O.
- **Why:** The story's technical note names the function and its two jobs ("validates that the PMCC
  has an open short call and that the replacement is a legal successor"). Structural guards first,
  then field-level money guards ("so a $0.00 cost to close is reported beside its field even when
  the dates are also wrong"), then the coverage invariant ("safety-critical, before the softer date
  and no-change rules"). `__roll__` and `must_be_on_or_after_current` reuse `rollCc`'s vocabulary.
  - **Rule 3 (review B1):** without it "a too-early roll would sort before the open short in
    `currentShortCallLeg`'s fill-date replay. The closed short would then read as still open, a
    second roll would close it twice, and the snapshot would get an out-of-order `eventDate`." Keeps
    the `close_date_before_open` code/wording of `requireFillDateOnOrAfterOpen`. No "not after the
    current expiration" / "not in the future" fill rules were added (no roll precedent).
  - **Rule 9 (review fix):** "Without it the engine recorded an expired SELL `ROLL_TO` that
    `currentShortCallLeg` then treats as the open short forever." Runs after coverage and
    on/after-current so those AC messages still win, and before no-change.
  - **Result shape (revised after review):** the plan's draft had `newStrike: string` required and
    a result of `{ phase: 'PMCC_OPEN' }`. Returning the validated short (generic `S`, the caller's
    own `LegRecord` narrowed to non-null) and the resolved strike removed a dead `short === null`
    re-check and a never-read `?? 0` fallback from the service.
- **Alternatives considered:** Extend `rollCc` with a `strategy` flag (different phase, nullable leg,
  coverage rule; US-14 chose replicate-not-generalize). Put the comparator in the service. A shared
  `requireRollChanges` with `rollCc` was rejected in refactor: it would parameterise both messages
  and change `rollCc`'s strike comparison from string equality to `Decimal.eq` — "a behaviour change,
  not a refactor".
- **Source:** `plans/us-104/research.md` § ADR `rollPmccShortCall`; `data-model.md` § 4;
  `refactor-phase-results.md` Area 2; code `src/main/core/lifecycle.ts`, `src/main/core/pmcc-rules.ts`

### ADR: The roll's date and no-change rules live once in `pmccShortRollIssues`

- **Decision:** `pmccShortRollIssues(input: PmccShortRollInput): PmccIssue<PmccShortRollField>[]` in
  `src/main/core/pmcc-rules.ts`, following US-101's `pmccCrossLegIssues` pattern.
  `PmccShortRollContext = { openShort: PmccShortCallTerms; leapsExpiration: string }`;
  `PmccShortRollInput = PmccShortRollContext & { fillDate, newStrike, newExpiration: string | undefined }`
  (`undefined` = undecided, the rule is skipped); `PmccShortRollField =
  Extract<keyof RollPmccShortCallInput, 'fillDate' | 'newExpiration'> | '__roll__'`. The engine throws
  the first issue; the renderer schema's `superRefine` reports the first issue per path.
- **Why:** "The form schema used to re-spell rules 3, 8 and 10 and restate the open short as
  `current*` fields." Deriving the field names from the engine input means "the form paths and the
  engine's `ValidationError.field` cannot diverge".
- **Source:** `plans/us-104/data-model.md` § 4 ("Shared roll rules (review)")

### ADR: The open legs of a PMCC are derived by replaying its legs, and `getPosition` returns them

- **Decision:** `src/main/services/pmcc-ledger.ts` exports `currentLeapsLeg(legs)` (US-103's private
  `newestLongBuy`, renamed and exported) and `currentShortCallLeg(legs)` — a replay in `readLegs`
  order: `SHORT_CALL_OPEN` or a short-side chain's `ROLL_TO` (`rollFrom.action === 'BUY'`) opens;
  `SHORT_CALL_EXPIRED` / `SHORT_CALL_CLOSE` / `SHORT_CALL_ASSIGNED` closes. `pmccOpenLegs(legs):
  PmccOpenLegs | null` (`null` when there is no LEAPS leg). `GetPositionResult.pmccOpenLegs:
  PmccOpenLegs | null` (null for a wheel), computed next to `pmccLedger`.
- **Why:** "US-103 changes no phase and US-115 / US-119 (which will introduce `PMCC_LEAPS_ONLY`) have
  not shipped, so 'has an open short call' cannot be read from `phase` yet." The renderer needs the
  same answer for the header action, the sheet context and the leg reference; ADR
  `server-side-dte-and-derived-fields` puts derived facts in the main process. "`activeLegSubquery`
  must **not** learn PMCC phases: US-101 keeps the alert, polling and calendar jobs off PMCC rows
  precisely because it returns no leg for them."
- **Alternatives considered:** Teach `activeLegSubquery` PMCC phases; derive in the renderer from
  `detail.legs`; wait for `PMCC_LEAPS_ONLY`.
- **Refactor outcome:** a private `orderedLedgerEvents(legs, chains): LedgerEvent[]` (`LedgerEvent =
  { leg; chain?: never } | { chain; leg?: never }`) now feeds `contributionsFrom`, `currentLeapsLeg`
  (`reduce(applyLeapsEvent)`) and `currentShortCallLeg` (`reduce(applyShortCallEvent)`), removing
  the triplicated merge/sort.
- **Source:** `plans/us-104/research.md`; `refactor-phase-results.md` Area 3

### ADR: `rollPmccShortCallPosition` writes the pair and calls US-103's writer in one transaction

- **Decision:** `rollPmccShortCallPosition(db, positionId, payload): RollPmccShortCallResult` in
  `src/main/services/roll-pmcc-short-call-position.ts`. Flow: `getPosition` (→ `not_found`) →
  `detail.pmccOpenLegs` (null → `__phase__`/`invalid_phase` for a non-PMCC_OPEN row such as a wheel,
  else `no_active_leg` for a PMCC with no LEAPS) → money to 4 dp → `rollPmccShortCall` (receives
  `openShort` possibly `null`, so "no open short" is the engine's `no_open_short_call`) → one
  `db.transaction`: `insertLegRow(ROLL_FROM BUY CALL, open short's strike/expiration/contracts,
  premium = fill = costToClose, fees '0.0000')`, `insertLegRow(ROLL_TO SELL CALL, replacement
  strike/expiration, premium = fill = newPremium)`, shared new `roll_chain_id`, then
  `appendPmccSnapshot(db, positionId, { triggerEvent: 'PMCC_SHORT_ROLL', eventDate: fillDate, now })`.
  Position row untouched (phase stays `PMCC_OPEN`, `updated_at` not bumped). `shortCallRollNumber =
  groupRollChains(detail.legs).filter(c => c.rollFrom.action === 'BUY').length + 1`. `fillDate`
  defaults to `localToday()`.
- **Why:** "This is US-14's shape with US-103's writer in place of `calculateRollBasis`; the story
  says … 'This story must not compute a basis of its own.'" Returning the ledger lets the success
  state show post-roll figures without a refetch; the roll number names the ledger line US-109 will
  render. A failed snapshot write rolls the two legs back (US-103's "failed leg event" guarantee).
- **Alternatives considered:** Record fees on the roll legs — no fees input in the AC or mockup;
  wheel rolls also write `'0.0000'`.
- **Source:** `plans/us-104/research.md`; `green-phase-results.md` Area 5 (deviations);
  `refactor-phase-results.md` Area 5

### ADR: `insertLegRow` is the one full-column leg insert

- **Decision:** `insertLegRow(db, leg: LegRecord): void` in `src/main/services/leg-rows.ts` — one
  INSERT built from `LEG_COLUMNS`, "the inverse of `readLegs`' mapping". Used by the roll service,
  `create-pmcc-position.ts#insertPmccLeg` (now builds the record, inserts, returns it),
  `test-fixtures/pmcc-legs.ts#insertLegs`, and the US-103 seam `ipc/test-pmcc-ledger.ts`
  (`toLegRecord(positionId, leg, now)` + shared insert). Each one's private `INSERT_LEG_SQL` is gone.
- **Why:** The roll's insert was "the fifth copy" of the leg INSERT SQL.
- **Not changed:** the wheel roll/open services ("Their SQL hard-codes literals and they do not build
  a `LegRecord` first").
- **Source:** `plans/us-104/refactor-phase-results.md` Area 5

### ADR: Payload reuses the roll payload base; money crosses the IPC as numbers

- **Decision:** As built, `RollPmccShortCallPayloadSchema = RollPayloadBaseSchema.extend({ fillDate:
  IsoDateSchema.optional() })` (`positionId`, `costToClosePerContract`, `newPremiumPerContract`,
  `newExpiration`, `newStrike?`, `fillDate?`). "Only `fillDate` is tightened to ISO, here and not on
  the base, so the wheel rolls' validation is unchanged" — the PMCC fill date drives open-short
  replay order. The service formats to 4-dp strings before the engine and the inserts. (The plan
  had `= RollPayloadBaseSchema` unchanged.)
- **Why:** "every shipped roll channel — and US-101's `positions:create-pmcc` — takes `z.number()` and
  formats in the service. One wire convention per channel family beats a one-off."
- **Alternatives considered:** A string-money schema for this channel only.
- **Source:** `plans/us-104/research.md`; `data-model.md` § 4; code `src/main/schemas.ts`

### ADR: `RollResultBase<Phase>` owns the `position` block for every roll result

- **Decision:** `export interface RollResultBase<Phase extends WheelPhase>` now includes

  `rollChainId`, `costBasisSnapshot`. `RollCspResult = RollResultBase<'CSP_OPEN'>`,

- **Why:** "written out by hand three times"; exported names unchanged for consumers.
- **Source:** `plans/us-104/refactor-phase-results.md` Area 4

### ADR: The sheet is the mockup's `RollShortSheet`; the effective-share-cost warning is renderer-side and advisory

- **Decision:** `RollPmccShortCallSheet` (portal, `SheetPanel width={440}`, `role="dialog"
  aria-label="Roll Short Call"`, Escape / scrim / Cancel close without recording) owns an RHF
  instance via `useRollPmccShortCallForm(ctx, today)` (`mode: 'onChange'`,
  `zodResolver(rollPmccShortCallSchema(ctx))`) and renders `RollPmccShortCallForm`: **Coverage**
  (`PmccCoverageRuler`), **Current short call** (Contract, Expiration with DTE, Sold at, `LEAPS ·
  read-only`, `Effective share cost` highlighted, the "not a guaranteed breakeven" note),
  **Replacement short call** (`RollPmccShortCallFields`: cost to close, premium, strike, expiration
  with `N DTE` hint, fill date defaulting to today, read-only contracts), the **Net** card or its
  dashed placeholder (`PmccRollNetPreview`), the advisory warning, the no-change error, and a footer
  with the blocked note, Cancel / `Confirm roll`, and `Your draft is kept until the roll is valid.
  No order is placed.` Live figures come from pure helpers in `src/renderer/src/lib/pmcc-roll.ts`.
  The warning is `AlertBox variant="warning"` and never disables confirm.
- **Why:** The consolidated mockup is the layout of record; the story's note "Advisory only — never
  blocks confirm" and ADR `soft-client-side-warnings`. `mode: 'onChange'` "is what makes 'the
  confirm action is disabled' true while the trader is still typing".
- **As built (deviations):** Confirm `disabled` is `!schema.safeParse(watchedValues).success`, not
  RHF `!isValid` — "RHF's `setError` forces `isValid: false`, so a `root.save` failure would disable
  the very retry its message invites". The no-change rule re-runs on strike/expiration changes via
  RHF `deps: '__roll__'`, and the fill-date input declares `deps: 'newExpiration'` so rule 9
  re-validates. Warning and roll label render only once the roll is valid; dates render ISO as in
  the mockup; button label `Confirm roll`; the warning keeps the mockup's trailing `You can still
  record it.`; sheet mount also requires `pmccLedger.effectiveShareCost`.
- **Alternatives considered:** Reuse `RollCcForm` with props (different warning, label, no coverage
  context); keep confirm enabled and validate on submit like US-101 (contradicts the AC).
- **Source:** `plans/us-104/research.md`; `green-phase-results.md` Area 9; `refactor-phase-results.md` Area 9

## Contracts

### `positions:roll-pmcc-short`

- **Type:** IPC handler
- **Shape:**

  ```typescript
  // Request — RollPmccShortCallPayloadSchema = RollPayloadBaseSchema.extend({ fillDate: IsoDateSchema.optional() })
  {
    positionId: string                 // a PMCC in PMCC_OPEN with an open short call
    costToClosePerContract: number     // positive — buy-to-close price per share
    newPremiumPerContract: number      // positive — sell-to-open price per share
  ```

## Acceptance Criteria

Linear OPT-12, one named e2e `it` each in `e2e/pmcc-short-call-roll.spec.ts` (12 total, all pass).
Background: XYZ PMCC, LEAPS $80 call (+368d), open $108 short sold at $1.80 (+67d), basis $21.20,
effective share cost $101.20 (US-103 `OPEN` + `EXPIRE_1` + `SHORT_2`).

1. **The roll form shows the decision context for the open short call** — sheet shows `$108.00`,
   current expiration with DTE, `$1.80 / share`, `LEAPS · read-only` `$80.00 · <LEAPS exp>`,
   `Effective share cost` `$101.20`; five inputs visible; no net card, placeholder shown.
2. **Net debit preview for a roll up and out** — 3.00 / 112 / +95d / 2.40 → `Net Debit: $0.60 per
   share ($60.00 total)`; label `Roll Up & Out: $108 to $112 strike, <Mon> to <Mon> expiration` …
   `N DTE`; confirm enabled.
3. **Net credit preview for a roll out at the same strike** — 1.10 / 108 / +95d / 2.30 → `Net Credit:
   $1.20 per share ($120.00 total)`; label `Roll Out: same $108 strike, …`.
4. **Recording the roll creates a linked leg pair and one net cost-basis line** — `ROLL_FROM` BUY
   $108 @ 3.0000 and `ROLL_TO` SELL $112 @ 2.4000 sharing one non-null chain id; basis `21.8000`;
   four snapshots, last `PMCC_SHORT_ROLL` `21.8000`; `pmccOpenLegs.long` $80, `.short` $112; banner
   `Short-call roll #1 debit` · `$0.60 per share`; drawer `$21.80`; `Sell short call` card `$112.00`.
5. **Warning when the replacement strike sits below the effective share cost** — 3.00 / 98 / +95d /
   2.50 → `Short strike $98.00 is below your effective share cost of $101.70 after this roll. If
   assigned, covering from the LEAPS realizes roughly $3.70 per share of loss.`; confirm enabled.
6. **Reject a replacement expiration that would outlast the LEAPS** — expiration = LEAPS → field
   error `Short call must expire before the LEAPS call.`; confirm disabled; IPC bypass →
   `newExpiration` / `short_not_before_long`; no legs written; short still $108.
7. **Reject a roll that changes neither strike nor expiration** — `Roll must change the strike, the
   expiration, or both`; confirm disabled.
8. **Reject a replacement expiration earlier than the current short call** — `Replacement expiration
   must be on or after the current expiration (<MMM d, yyyy>)`; confirm disabled.
9. **Outline: Reject a non-positive cost to close** — `Cost to close must be greater than zero`;
   confirm disabled.
10. **Outline: Reject a non-positive replacement premium** — `Replacement premium must be greater than
    zero`; confirm disabled.
11. **Reject a roll when the PMCC has no open short call** — LEAPS-only state: no `Roll Short Call →`;
    bypass → `This PMCC has no open short call to roll.`; legs and snapshots unchanged.
12. **Leave a classic wheel covered-call roll unaffected** — CC_OPEN wheel: no `roll-pmcc-short-btn`;
    `Roll CC →` sheet reads `Roll Covered Call` and contains no `Effective share cost`, `LEAPS`, or
    `Roll Short Call`.

Additional review-driven rules (not Linear AC; unit/integration-covered): roll fill date before the
open short's fill → `fillDate` / `close_date_before_open`; replacement expiring on/before the roll
fill → `newExpiration` / `expiration_not_after_fill` (both in the form schema and the engine).

(Source: `plans/us-104/plan.md` § AC Audit and Area 10; `data-model.md` § 2; `red-phase-results.md` Area 10.)

## Decisions & Tradeoffs

- **Worked figures** (1 contract, $0 fees): up & out net −0.60 debit / $60 / basis 21.80 / eff
  101.80; out credit +1.20 / $120 / 20.00 / 100.00; below-eff 98 strike −0.50 / 21.70 / 101.70 /
  shortfall $3.70. `effective after = leapsStrike + (basis − net)`. After the up-and-out roll the
  chain reads `PMCC_OPEN, PMCC_SHORT_EXPIRED, PMCC_SHORT_OPEN, PMCC_SHORT_ROLL` /
  `23.0000, 23.0000, 21.2000, 21.8000` (`research.md`).
- **"No open short" is the engine's rule, not `no_active_leg`:** the service passes `openShort: null`
  through; `no_active_leg` is only for a PMCC row with no LEAPS. A wheel id reports `__phase__` /
  `invalid_phase` before `no_active_leg` (`green-phase-results.md` Area 5).
- **Money on the wire is numbers**, formatted to 4 dp in the service (deliberate deviation from the
  story note's "money as strings at 4 dp").
- **No fees input on the roll**; legs write `fees = '0.0000'` (additive later).
- **e2e fill date:** the recording test sets `ROLL_FILL_DATE = localDate(63)` because the Background's
  events are future-dated and `allSnapshots` orders by `snapshot_at`; a today-filled roll sorted
  before them (`red-phase-results.md` Area 10). (Rule 3 later made that ordering a hard rule.)
- **Renderer date check** uses `isBefore(parseISO(...))`/`isSameMonth` rather than string slicing in
  the helpers (CLAUDE.md Date Handling); core rules compare ISO strings.
- **`moneySchema` / `inputToNumber`** moved to `src/renderer/src/schemas/common.ts`, shared by
  `pmcc-entry.ts` and the roll schema; `required` stays private in `pmcc-entry.ts`.
- **Not refactored (deliberately):** three roll booleans in `usePositionDetailSheets` not folded into
  one union (would touch wheel state); no shared `useRollSheetForm` across roll sheets; `money4`
  duplicated in two services; `pmcc-roll-helpers.ts` not folded into `pmcc-ledger-helpers.ts`;
  13 `api/positions.ts` adapters still share an unextracted unwrap body; other forms still hand-roll
  400-`detail` extraction and could adopt `applyIpcFieldErrors`.
- **Property tests:** `pmcc-rules.property.test.ts` (comparator ≡ calendar-day `<`; cross-leg issue
  iff `!shortExpiresBeforeLeaps`); `lifecycle.property.test.ts` adds `rollPmccShortCall` to the phase
  guards, a coverage guard and a valid-input invariant; new `strictlyOrderedDays(count)` arbitrary
  keeps `replacement < leaps` in the generator. Stressed at `numRuns: 500` over five seeds.
- **Test helpers moved** to `src/main/services/test-fixtures/pmcc-legs.ts`: `pmccOpenPayload(day)`,
  `recordPmccLegEvent(db, positionId, legs, triggerEvent)`.
