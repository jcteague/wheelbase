# Extract: us-43

## Summary

US-43 delivers `fetchIVR(ticker)` — a pure TypeScript module in `src/main/integrations/barchart-ivr-scraper.ts` that fetches IV Rank and IV Percentile from Barchart's internal JSON API (`/proxies/core-api/v1/options/get`). Returns a typed discriminated union (`IVRResult`) and never throws. No DB writes, no IPC channels, no UI — it is the foundational fetch primitive for downstream stories US-44 (scheduled collection) and US-45 (UI display). The story pivoted from the original Market Chameleon + cheerio specification after investigation revealed MC's IVR data is JavaScript-rendered and protected by a custom XOR cipher on all discovered API endpoints. Barchart provides the same data (IVR + IVP + HV20) as clean JSON via an unauthenticated session-cookie API. Implementation spans a full Red→Green→Refactor cycle across 7 areas (schema/types, ticker validation, session acquisition, JSON parser, HTTP fetch helper, main orchestrator, AC-level tests) and delivers 46 passing tests. (Sources: `plans/us-43/plan.md`, `plans/us-43/research.md`, `plans/us-43/data-model.md`, `plans/us-43/refactor-phase-results.md`)

## Architecture Decisions

### ADR: Use Barchart internal JSON API instead of Market Chameleon HTML scraping

- **Decision:** Call `https://www.barchart.com/proxies/core-api/v1/options/get` directly instead of scraping Market Chameleon's HTML.
- **Why:** Market Chameleon's IVR data is JavaScript-rendered and the backend endpoints use a custom XOR cipher requiring a session cookie as the decryption key — too brittle for a simple scraper. Barchart returns the same data (IVR + IVP) as clean JSON via an unauthenticated GET, tested live against SPY, AAPL, TSLA, and a fictional ticker.
- **Alternatives considered:** Market Chameleon + cheerio (story original — blocked by JS rendering and XOR cipher); Playwright headless (blocked by Cloudflare ERR_HTTP2_PROTOCOL_ERROR); paid Barchart OnDemand API (requires API key + paid plan — overkill).
- **Source:** `plans/us-43/research.md`

### ADR: Two-step session acquisition with module-level cache

- **Decision:** On first call, GET a Barchart page to harvest `Set-Cookie` headers → extract and URL-decode `XSRF-TOKEN` → cache `{ cookies, xsrf, expiresAt }` for 30 minutes → reuse on all subsequent calls within the TTL.
- **Why:** The API requires a valid session cookie and XSRF token but not login credentials. A 30-minute cache avoids paying the session-acquisition overhead on every ticker lookup; US-44 will call `fetchIVR` once per ticker per scheduled batch.
- **Alternatives considered:** Per-call session acquisition (correct but wasteful); hardcoded cookies (brittle — expire on server restart); constructor injection of cookies (overkill for a single-user desktop app).
- **Source:** `plans/us-43/research.md`

### ADR: Typed discriminated union result — never throws

- **Decision:** `fetchIVR` returns `IVRResult = IVROk | IVRNotAvailable | IVRParseError | IVRNetworkError | IVRRateLimited | IVRInvalidInput`. Every internal error path maps to a variant; the module never throws.
- **Why:** Consistent with the story acceptance criteria and the established integration layer pattern. Callers can exhaustively narrow the union without `try/catch`.
- **Alternatives considered:** Throwing typed errors — rejected because it breaks the "never-throw" contract and requires callers to catch.
- **Source:** `plans/us-43/research.md`, `plans/us-43/data-model.md`

### ADR: File and function naming after the actual data source

- **Decision:** File `barchart-ivr-scraper.ts`, exported function `fetchIVR(ticker)`, result field `source: "barchart"`.
- **Why:** The story originally named the integration after Market Chameleon. After the pivot, the file was named after the actual data source to avoid misleading maintainers.
- **Alternatives considered:** Keeping the MC filename (misleading); generic `ivr-scraper.ts` (obscures data source).
- **Source:** `plans/us-43/research.md`

### ADR: `createRateLimiter()` closure factory over class

- **Decision:** `createRateLimiter()` closes over `lastAt` and returns `{ throttle(minMs) }`. `RateLimiter` is a plain TypeScript type, not a class. A module-level singleton gates API calls only — not the infrequent session acquisition.
- **Why:** Matches the project's functional-programming standard ("avoid classes in TypeScript; use plain functions and types"). The Green phase used a class; refactor converted it.
- **Source:** `plans/us-43/refactor-phase-results.md`

### ADR: Typed `SessionResult` and `ApiFetchResult` discriminated unions

- **Decision:** `getSession()` returns `{ ok: true; session } | { ok: false; error: IVRRateLimited | IVRNetworkError }`. `fetchApi()` returns `{ ok: true; response: Response } | { ok: false; error }`. Neither throws; `fetchIVR` reads as a straight-line happy path with typed early returns.
- **Why:** The initial Green implementation threw on HTTP errors and used substring matching on thrown messages to reconstruct typed results. The refactor eliminated the string-matching anti-pattern and made error paths typed end-to-end.
- **Source:** `plans/us-43/refactor-phase-results.md`

### ADR: `vi.stubGlobal('fetch', mockFetch)` for test isolation

- **Decision:** Tests stub the global `fetch` with `vi.stubGlobal('fetch', mockFetch)`. Each test mocks two sequential responses: (1) session acquisition page → mock `Set-Cookie` headers; (2) API call → mock JSON body.
- **Why:** Consistent with `massive-market-data.test.ts`. Avoids constructor injection of `fetchFn`, which is inconsistent with the existing integration layer style.
- **Source:** `plans/us-43/research.md`

## Acceptance Criteria

- **AC-1 (Covered ticker):** `fetchIVR("SPY")` returns `{ status: "ok", data: { ticker: "SPY", ivr: number 0..100, ivp?: number 0..100, observedAt: ISO-8601, source: "barchart" } }`; `ivr` is rounded to one decimal place.
- **AC-2 (Ticker not covered):** `count === 0` in Barchart response → `{ status: "not_available", error: { code: "TICKER_NOT_COVERED", message includes ticker } }`.
- **AC-3 (Parse error):** `count > 0` but `raw.impliedVolatilityRank1y` absent or non-numeric → `{ status: "parse_error", error: { code: "PARSE_FAILED", message includes field name, rawSnippet ≤ 500 chars } }`; WARN log emitted.
- **AC-4 (Network failure):** HTTP 5xx or thrown `TypeError` → `{ status: "network_error", error: { code: "NETWORK_FAILURE" } }` after up to 2 retries with exponential backoff.
- **AC-5 (Rate limit):** HTTP 429 → `{ status: "rate_limited", error: { code: "RATE_LIMITED", message includes Retry-After if present } }`; no retry.
- **AC-6 (Polite user agent):** Session-acquisition and API fetches both send `User-Agent` starting with `"Wheelbase/{version}"`. Module-level `RateLimiter` enforces ≥ 1000 ms between API calls.
- **AC-7 (Invalid input):** Empty, non-alphanumeric, or >5-char ticker → `{ status: "invalid_input", error: { code: "INVALID_TICKER" } }` without issuing any network request.

## Decisions & Tradeoffs

- **Barchart pivot over Market Chameleon.** MC's IVR data requires JS rendering and a custom XOR cipher on all discovered API endpoints — unsuitable for a simple scraper. Barchart's unauthenticated JSON API is faster, more reliable, and equally data-rich.
- **Module-level session cache.** Avoids the session-acquisition overhead per ticker call; critical for the US-44 batch scenario.
- **`cheerio` added but unused.** Added to `package.json` during the research phase for the original MC plan; not imported by this module and may be used by future scraper stories.
- **Pure integration module.** No IPC, no DB, no UI. Downstream wiring deferred to US-44 and US-45.
- **46 tests (unit + AC coverage).** All areas Red→Green→Refactor; AC tests map 1:1 to the Gherkin scenarios from the user story (adapted to the Barchart mechanics).
